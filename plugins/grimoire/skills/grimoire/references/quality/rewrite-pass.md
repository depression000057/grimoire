# 話し言葉への書き直し

このファイルの役割: 日本語の破綻点検を終えた原稿を、書き手とは別の「書き直し担当」として、生身の人が話す自然な言葉に書き直す手順と指示文。

いつ読むか: 日本語の破綻点検（`references/quality/breakdown-checklist.md`）を終えた直後。この後は、意味のすり替わり点検（`references/quality/meaning-check.md`）に進む。

目次:

- §1 この工程の役目と、書き手と役を分ける理由
- §2 準備（渡すもの・渡さないもの）
- §3 前提メモを用意する
- §4 書き直し担当への指示文（そのまま渡す）
- §5 守ること（8つ）
- §6 診断の観点の説明（なぜその観点を見るのか）
- §7 書き直しを受け取った後の確認
- §8 うまくいかない時

## §1 この工程の役目と、書き手と役を分ける理由

書き直しの役目は、原稿の中身を変えずに、次の3つを一度に直すこと。

1. 文と文のつながり（前の文から次の文へ、なぜそうなるのかが続いているか）
2. 読者1人の目線（途中で「どういうこと？」「なんで？」が浮かばないか）
3. 言葉の手ざわり（AI っぽい言い回しが無く、声に出した時のリズムがあるか）

書き手と同じ役のまま直すと、自分の意図を知っているせいで、読者が止まる所を読み飛ばしてしまう。だから、原稿を初めて読む「書き直し担当」に役を切り替えて行う（なぜ: 書く担当と直す担当を分けると、片方だけでは拾えない引っかかりを拾える）。

この工程は、破綻点検の後にやる（なぜ: 書き直しは文のリズムを整えるのは得意でも、抜けた主語や指す先の分からない「それ」までは補わない。抜けを先に埋めておかないと、抜けたまま読みやすい文になって残る）。

書き直しの後には、元の原稿と1文ずつ比べる「意味のすり替わり点検」がある。そのあと、**書き直した方を土台にして、意味が変わった所だけ元の原稿の言葉に戻す**（なぜ: 元の原稿を土台にして書き直しの一部だけ拾うと、話し言葉の良さがほとんど消えて、同じ直しを何度も繰り返すことになる）。

手伝いの AI（サブエージェント）を呼べる環境（Claude Code など）では、この工程を別の AI に任せてよい（なぜ: 書いた AI とは別の AI が書き直すと、同じ AI では気づけない言い回しの癖まで直せる）。その場合も §3 の前提メモを一緒に渡し、§7 の確認はこちらでやる。

## §2 準備（渡すもの・渡さないもの）

1. **新しい会話を開く**。開けない環境では、同じ会話の中で「ここからは書き直し担当に切り替える。これまでの設計の話は使わない」と宣言する（なぜ: 書いた時のやりとりが見えていると、書き直し担当も書き手の意図で読んでしまう）
2. **渡すのは3つだけ**: §4 の指示文／原稿の全文（破綻点検で直した後のもの）／§3 の前提メモ
3. **渡さないもの**: 設計メモ・タイトル案の一覧・破綻点検の記録・これまでの会話（なぜ: 読者が知らない情報を渡すと、読者の目線で読めなくなる）
4. **長い原稿（note の本文など）は、区切りのよい所で2〜3回に分けて渡してよい**。その場合も、毎回、指示文と前提メモを一緒に渡す。分けた境目の前後1〜2文は、次の回にも含める（なぜ: 境目でつながりが切れるのを防ぐため）

## §3 前提メモを用意する

書き直し担当に渡す短いメモ。`00_わたしの設定.md` と原稿から、受講生の AI が作る。下の9項目を「項目名: 中身」の形で1行ずつ書き、先頭に「前提メモ」と1行置く。

| 項目 | 書くこと |
|---|---|
| 媒体 | Threads 投稿／note／セールスレター／台本 のどれか |
| 元の原稿の字数 | N字（空白と改行を除く） |
| 書き直し後の字数の範囲 | N×0.95 〜 N×1.05 字 |
| 読者1人 | 年代・今の状況・口にする言葉・毎日手で触る物 |
| 声 | 一人称・語尾の傾向・読者との距離・絵文字の有無・締め方 |
| 禁止したい言葉 | 設定の「禁止したい言葉」をそのまま |
| 変えない言葉 | 見出し・区切り行・商品名・価格・数字・固有名・指定された文言 |
| 強い言葉の一覧 | 原稿の中の、強い約束・強い言い切りを抜き出したもの |
| 例えの出どころ | 読者1人の生活の場面を3つ |

「強い言葉の一覧」は、書き手が原稿から抜き出して書く。例えば1行目の言い切り、有料ラインの前の約束、締めの言い切りなど（なぜ: 一覧にしておくと、書き直し担当が弱めずに残せ、書き直しの後に残ったかを照らし合わせられる）。

字数は、Python が動く環境なら次の1行で数える。動かない環境では、AI に数えさせた数字は目安として扱う（なぜ: AI は文字数を正確に数えるのが苦手）。

```
python3 -c "import sys;t=open(sys.argv[1],encoding='utf-8').read();print(len(''.join(t.split())))" 原稿.md
```

## §4 書き直し担当への指示文（そのまま渡す）

新しい会話に、次の指示文・前提メモ・原稿の順で貼る。指示文は変えずに使う。

> あなたは、この原稿の「書き直し担当」です。書いた人とは別の人として、原稿を初めて読む立場で作業してください。
>
> ◆ やること
> まず原稿を読んで、下の観点で自分で診断してください。何が問題かは、こちらからは指定しません。あなたが判断してください。
> 書き言葉ではなく、生身の人が話す、ごく自然な話し言葉（語り口）で書いてください。
> 日本語として違和感のある所、AI っぽさ、日常会話・台本・文章としての日本語のリズム・テンポ・語感を、文脈と前提を全部つかんだうえで、違和感のある所は全部直してください。
>
> ◆ 一回で全部やる
> 目立つ数か所だけ直して残りをそのまま写すこと、後から言われたら直すことは、しないでください。この1回の出力だけで、もう一度直しに出さなくて済む完成稿にしてください。そのために、下の3つの点検を、全部の行・全部の段落に同時に当てて、生身の人の生きた言葉へ、ゼロから磨き上げてください。
> 意図・内容・伝えたい事実は変えずに、大人の知性と品のよさを保ちながら、平易で、すっと腑に落ちる日本語にしてください。
>
> ◆ 意味を変えない
> 話し言葉にする勢いで、原稿の核心の主張・結論・前提の条件・数字・勧めている行動を、別の話にすり替えないでください。書き直しの後に、元の原稿と1文ずつ比べる点検があります。意味の変質・事実のでっち上げ・抜け落ちが1か所でも見つかれば、不合格になります。
>
> ◆ 読者1人の目線
> この文章にたどり着いた読者1人（前提メモの「読者1人」）になったつもりで読んだ時に、「これは自分のことだ」と思える表現になっているか、読んでいる途中で「これどういうこと？」「なんで？」という疑問が浮かぶ所が無いかを全部洗い出し、その疑問が解消されるように書き直してください。
>
> ◆ 書き手の独り言をなくす
> 文脈がつながっていない、つなぎの言葉が無い、急に言いたい話題へ飛んでいる「書き手の独り言」をなくし、前の文から次の文へ、必然性のある因果の橋を架けて、一本の滑らかな糸としてつなぎ直してください。
>
> ◆ 強い言葉を弱めない
> 読者の気持ちを強く引きつける、そのジャンルならではの強い言葉・強い約束（前提メモの「強い言葉の一覧」）を、無難な日常の言葉に弱めたり、格下げしたりしないでください。
>
> ◆ 矛盾は削らず、橋を架ける
> 強い約束と途中の説明（「都合のいい話ではない」など）が食い違って見える時は、冒頭の強い言葉を削って地味にしないでください。なぜその変化が起きるのかという現実的なしくみを、本文の中で論理的に通してください。あなたの役目は表現を丸めることではなく、強い表現のまま論理を通すことです。ただし、しくみの説明に使うのは原稿の中にある材料だけにしてください。
>
> ◆ 守ること
> - 字数は、前提メモの「書き直し後の字数の範囲」（元の字数の±5%）に収めてください。
> - 言い直しの文・新しい例・新しい体験・新しい数字・新しい主張を足さないでください。読者の生活への「肉付け」は、原稿にある具体を前に出す・言い方を変える範囲で行ってください。原稿に無い具体が要る所は、作らずに元の文の意味のまま残してください。
> - 効果の言い方を強めないでください（「軽くなる」を「消える」にしない、「減る」を「なくなる」にしない）。
> - 敬語を重ねないでください（「させていただきます」「お〜になられる」「〜していただけますでしょうか」などにしない）。
> - 言い切りが要る所（1行目・締め・強い約束）に、「ね」「よ」などの語尾や「〜んです」やクッションの言葉を足して、軟らかくしないでください。
> - 前提メモの「変えない言葉」（見出し・区切り行・商品名・価格・数字・固有名・指定された文言）は、一字も変えないでください。
> - 前提メモの「禁止したい言葉」は使わないでください。
> - 例えを直す時は、前提メモの「例えの出どころ」の場面から選んでください。
> - 改行は1息ごとにしてよいですが、空行（段落の区切り）・見出し（# で始まる行）・区切り行・HTML コメントの位置は変えないでください。
> - 下のチェックリストは内部用です。チェックリストの説明文は、出力に絶対に出さないでください。
>
> ■ 診断のチェックリスト（3つの点検を、全部の行に当てる）
>
> ◆ 点検1: 文と文のつながりを確かめる（骨組み）
> - 指す言葉: 「これ」「それ」「こんなこと」などが何を指すか、読者がその場で分かるか。分からない所は、指している物の名前をそのまま書いているか。
> - 理由の抜け: 「AだからB」の間にある「なぜそうなるのか」が抜けていないか。読者が「なんで？」と止まりそうな所に、理由の一文があるか。
> - 話のつながり: 前の文や段落に無かった言葉・問い・考えを、いきなり次の文の主語にしていないか。前の文の終わりの言葉を、次の文が受けて続けているか。強く言い切ったり行動を頼んだりした直後に、読者の「え、なんで？」を受け止めずに別の話へ移っていないか。
>
> ◆ 点検2: 読者1人の疑問を先回りして解消し、肉付けする（共感）
> - 説明不足と疑問の先回り: 読んだ瞬間に「何に？」「どういうこと？」「なんで？」が浮かぶ所が無いか。浮かぶ所は、その直前か直後に理由のクッションを挟んで解消しているか。専門用語や抽象的な言葉が、読者に分からないまま残っていないか（普段の言葉にかみ砕いているか）。数字が出てきたら、なぜその数字になるかの計算の橋が架かっているか。
> - 読者の生活への着地: 見出しや目次をなぞるだけの、中身の薄い要約スライドやマニュアルの調子になっていないか。一般論で止まらず、読者がやりがちな失敗の具体になっているか。抽象的な考えで止まらず、読者の毎日の中で起きる場面や五感になっているか。解説や解決策を言う前に、読者の心の声（反論・戸惑い・疑い・後ろめたい本音）をすぐに代わりに言っているか。失敗→正解の対比で見せているか。抽象的なラベルが、具体的なタイトル・投稿文・金額・行動になっているか。（どれも、原稿にある材料の範囲で行う）
>
> ◆ 点検3: AI っぽい構文をなくし、話し言葉のリズムにする（語感）
> - AI っぽい構文: 並べる形・二重の形（「〜だけでなく、…もまた」「〜を通じて」など）。他人事・高みの見物・解説者の形（「〜と言えるでしょう」「〜が重要になってきます」「〜というわけです」「〜ではないでしょうか」など）。中身の無い形容や動詞（「根本的な」「多角的な」「深掘りする」「言語化する」など）。お決まりの決まり文句（「安心してください」「いかがでしょうか」「実はこれ、」「〜という好循環」など）。小論文のような理屈の後に、急に体験談へ飛ぶ形（「なぜなら〜からです。これはね、〜」など）。
> - つなぎ・テンポ・会話のリズム: 1行が、声に出す1息になっているか。同じ語尾が3回続いていないか（「です」「ます」「でした」の連打をせず、「だ」「た」「る」「ない」「ね」「よ」「でしょ」を自然に回す）。「なんですね」「なんです」「なんですよ」を重ねすぎていないか。否定のつなぎ（「〜なくて、〜ではなく」）が重なっておらず、肯定と理由がすっきり分かれているか。続く形のまま句点で止めていないか（「あって。」「ので。」「けど。」）。文頭の「で、」が続いていないか（削るか、ほかのつなぎに散らす）。要約メモのような、ぶっきらぼうな言い切り（「〜なった。」「〜やった。」「〜見えてしまう。」）になっていないか。事実だけで止まっている文を、語りかけや共感の言葉で着地させているか（言い切りが要る所は除く）。
>
> ■ 媒体ごとの決まり（前提メモの媒体に当てはまる時だけ）
> - 台本・動画の音声: 1行を声に出す1息で区切り、耳で1回聞いて分かる言葉にする。見ている状況（夜・布団の中・スマホで見ている など）と、台本の中で頼む動作を食い違わせない。話し手の方言や口調の濃さは、声の設定どおりに保つ（濃くしすぎない）。合図やキーワードがある時は、省かず変えず、決めた回数・決めた位置で言う。
> - SNS 投稿（Threads・X・Instagram）: 1行目で一番強い主張・結論・ギャップを出して、スクロールの手を止める。スマホの画面で目が動く順を考え、1文を短く、空白の行を適切に置く。読者が「わかる」「保存したい」と思って反応したくなる着地にする。
> - セールスレター・販売ページ: 買う前の「怪しい」「本当に効果あるの？」という反論を、先回りして解消する（原稿にある答えの順番と言い方を整える範囲で）。大きな変化を約束するだけの抽象的な言葉で終えず、行動の直後に得られる具体的な生活の変化を描く。次の行動への心理的なハードル（価格・手間・危険）を下げる（価格や条件そのものは変えない）。
> - 記事・note・メルマガ: 見出しと本文の1行目を滑らかにつなぎ、見出しだけが浮かないようにする。読者が途中で離れそうな難しい説明の直前に、共感のクッションを置く。
>
> ◆ 出力
> 書き直した全文だけを出してください。診断の結果・変更の理由・前置き・後書きは出さないでください。直す所が無かった部分も省かずに、全文を出してください。1か所を直すと前後のつながりが崩れる時は、前後1〜2文も含めて整えてください。

## §5 守ること（8つ）

| # | 決まり | なぜ |
|---|---|---|
| 1 | 字数は元の±5%以内 | 書き直しは放っておくと言葉を足して長くなる。長くなった後で字数に合わせて削ると、せっかくの話し言葉が壊れ、日本語として成り立たない文に戻る |
| 2 | 言い直し・例・体験・数字・主張を足さない | 足した分は書き手が確かめていない中身になり、そのまま公開すると事実でない話が混ざる。長さも増えて、決まり1を守れなくなる |
| 3 | 効果の言い方を強めない | 「軽くなる」を「消える」にすると、書き手が約束していない効果を約束することになり、誇大な表現に近づく |
| 4 | 敬語を重ねない | 「させていただきます」の重なりは丁寧さでなく距離を生み、話し言葉のリズムを止める |
| 5 | 強い言葉（強い約束・強い言い切り）を弱めない | 書き直しは無難な方へ丸めたがる。強い言葉が消えると、読者の手を止めていた理由も消える |
| 6 | 矛盾は削らず、原稿の材料で橋を架けて回収する | 食い違いを削って消すと、強い約束が地味になるか、約束の根拠が抜ける。材料の範囲で橋を架ければ、強さと筋の両方が残る |
| 7 | 意味・事実・前提・数字・勧める行動をすり替えない | 読みやすくても意味が変わった文は、書き手の原稿ではなくなる。次の意味のすり替わり点検で戻す手間が増える |
| 8 | 出力は書き直した全文だけ | 診断や説明が混ざると、どこまでが本文か分からなくなり、比べる点検と貼り付けの両方で事故が起きる |

決まり3と5は対になっている。**強さは、元の原稿と同じにそろえる**（強めもしないし、弱めもしない）。

## §6 診断の観点の説明（なぜその観点を見るのか）

§4 の指示文に入っている観点を、受講生が確かめられるように説明する。

### 点検1: 骨組み（文と文のつながり）

| 観点 | 見ること | なぜ |
|---|---|---|
| 指す言葉 | 「これ」「それ」「こんなこと」が何を指すかが、その場で分かるか | 読者は前を読み返さない。何を指すか分からないまま理由を聞かされても、何の理由か分からない |
| 理由の抜け | 「AだからB」の間の「なぜそうなるのか」が書いてあるか | 理由が抜けると、読者は「なんで？」を抱えたまま次の文へ進み、納得しないまま終わる |
| 話のつながり | 前に無かった言葉をいきなり主語にしていないか／前の文の終わりを次の文が受けているか／強い言い切りの後に読者の反応を受け止めているか | 話がつながらないと、読者は書き手の頭の中を想像して間を埋めるしかなく、埋められなかった所で読むのをやめる |

### 点検2: 読者1人（疑問の先回り・肉付け）

| 観点 | 見ること | なぜ |
|---|---|---|
| 疑問の先回り | 「何に？」「どういうこと？」「なんで？」が浮かぶ所に、理由のクッションがあるか | 疑問を解消されないまま読み進める読者はいない。疑問が浮かんだ所が、離れる所になる |
| 専門用語・抽象語 | 読者の普段の言葉にかみ砕いているか | 分からない言葉が1つ出ただけで、その段落は読者にとって他人の話になる |
| 数字の計算の橋 | なぜその数字になるかがつながっているか | 根拠の見えない数字は、疑われるか読み飛ばされる |
| 要約スライド調・マニュアル調 | 見出しをなぞるだけの薄い文になっていないか | 骨組みだけの文は情報に見えても、人の話としては聞かれない |
| 一般論→やりがちな失敗の具体 | 読者が実際にやっている失敗の形になっているか | 一般論は正しくても、読者は自分の話だと思わない |
| 抽象→毎日の場面・五感 | 読者の生活の中の一場面になっているか | 場面が浮かんだ瞬間に、読者は「自分のことだ」と感じる |
| 心の声の代弁 | 解説の前に、読者の反論・戸惑い・疑い・後ろめたい本音を代わりに言っているか | 心の声を先に言われた読者は、自分を分かっている相手の説明として続きを聞く |
| 失敗→正解の対比 | 並べて見せているか | 対比があると、どこを変えればいいかが一目で分かる |
| 抽象ラベル→具体 | 具体的なタイトル・投稿文・金額・行動になっているか | ラベルのままでは、読者は明日何をすればいいか分からない |

肉付けは、原稿にある具体を前に出す・言い方を変える範囲で行う。原稿に具体が無い所は、書き直し担当が作らずに元の意味のまま残す（なぜ: 書き直しで作った具体は、書き手が確かめていない作り話になる）。足りない具体は、あとで書き手（受講生本人）が補う。

### 点検3: 語感（AI っぽい構文・話し言葉のリズム）

| 観点 | 見ること | なぜ |
|---|---|---|
| 並べる形・二重の形 | 「〜だけでなく、…もまた」「〜を通じて」 | 翻訳文のような硬さが出て、人が話している感じが消える |
| 解説者の形 | 「〜と言えるでしょう」「〜が重要になってきます」「〜というわけです」「〜ではないでしょうか」 | 外から眺めて評論する言い方は、読者と同じ場所に立っていない |
| 中身の無い形容・動詞 | 「根本的な」「多角的な」「深掘りする」「言語化する」 | 何がどうなるのかを言わずに、言った気にさせる言葉だから |
| 決まり文句 | 「安心してください」「いかがでしょうか」「実はこれ、」「〜という好循環」 | どの文章にも出てくる言葉は、読者に「どこかで読んだ文」と感じさせる |
| 理屈から体験談へ急に飛ぶ | 「なぜなら〜からです。これはね、〜」 | 読者の疑問を拾わずに理屈と体験談が続くと、話がかくかくと途切れる |
| 1行＝1息 | 声に出した時の息継ぎで区切れているか | 息の長さに合った行は、黙読でも読みやすい |
| 語尾の3連続 | 同じ語尾が3回続いていないか | 語尾が1種類にそろうと、中身と関係なく単調に聞こえる |
| 「なんです」の重ね | 「なんですね」「なんです」「なんですよ」が多すぎないか | 話し言葉の語尾も、多すぎると新しい口癖になって目立つ |
| 否定のつなぎの重なり | 「〜なくて、〜ではなく」 | 読者は否定をひっくり返しながら読むことになり、文がもたつく |
| 続く形の句点止め | 「あって。」「ので。」「けど。」 | 文が宙に浮いたまま終わり、読者の息が変な所で止まる |
| 文頭の「で、」の連続 | 続けて使っていないか | 1回なら話し言葉らしさ、続くとリズムの崩れになる |
| ぶっきらぼうな言い切り | 「〜なった。」「〜やった。」 | 要約メモのような言い切りは、読者に話しかけている温度が無い |
| 事実だけで止まる文 | 語りかけや共感で着地しているか | 事実を並べるだけの文章は、報告書に聞こえる |

### 媒体ごとの決まり

§4 の指示文の「媒体ごとの決まり」は、前提メモの媒体に当てはまる時だけ使う（なぜ: 台本の決まりを note に当てると、段落や見出しの形が崩れる）。note では、見出しと本文の1行目のつながりと、難しい説明の前の共感のクッションを必ず確かめる。

## §7 書き直しを受け取った後の確認

書き直し担当が出した全文を受け取ったら、書き手（受講生の AI）が次を確かめる。1つでも外れていたら、意味のすり替わり点検の前に直す。

1. **字数**: §3 の方法で数え、元の±5%に入っているか
   - 5%より長い時: 書き直し担当に「足した言い直し・例・説明の文を、文ごと外して」と頼み直す。自分で1文の中を削って縮めない（なぜ: 文の中を削ると、主語や目的語が抜けた文に戻る）
   - 5%より短い時: 何かが抜け落ちている疑いが強い。意味のすり替わり点検で、抜けた所を必ず探す
2. **変えない言葉**: 見出し・区切り行・商品名・価格・数字・固有名・指定の文言が、一字も変わっていないか
3. **強い言葉の一覧**: 前提メモに書いた強い言葉が、同じ強さで全部残っているか
4. **足された中身**: 原稿に無かった例・体験・数字・主張が増えていないか
5. **敬語の重なり**: 「させていただく」「お〜になられる」が増えていないか
6. **言い切りの位置**: 1行目・締め・強い約束が、語尾やクッションで軟らかくなっていないか
7. **出力の形**: 診断・説明・前置きが混ざっていないか（混ざっていたら取り除く）

確認が終わったら、`references/quality/meaning-check.md` で元の原稿と1文ずつ比べる。統合は、**書き直した方を土台にして、意味・事実・行動・因果が変わった所だけを元の原稿の言葉に戻す**。戻す時も、強い言葉を弱める方向には戻さない。

## §8 うまくいかない時

| 起きたこと | やること | なぜ |
|---|---|---|
| 数か所しか変わっておらず、ほとんど元のまま | 「一回で全部やる」の段落を指示文の先頭に移して、もう一度頼む。長い原稿なら §2 の4 のとおり分けて渡す | 書き直しは、長い原稿ほど目立つ所だけ直して済ませやすい |
| 全体が軟らかくなりすぎた（語尾に「ね」「んです」が増えた） | 統合の時に、1行目と締めと強い約束だけ元の言い切りに戻す。ほかの口語化はそのまま使う | 話し言葉の良さを全部捨てると、書き直した意味がなくなる |
| 字数が大きく増えた | 前提メモに字数の範囲を書いたか確かめ、書き直し担当に「足した文を外して」と頼み直す | 字数の範囲が無いと、書き直しは説明を足して長くする |
| 例や体験が作られた | 作られた所を元の原稿の文に戻し、指示文の「足さないでください」を守らせて再度頼む | 作られた例は、公開すると作り話になる |
| 同じ失敗が2回続いた | 書き直しをやめ、原稿の方に戻る。多くは素材（読者1人の具体・例えの出どころ）が足りない | 同じ直しを繰り返しても、足りない素材は書き直しでは埋まらない |
