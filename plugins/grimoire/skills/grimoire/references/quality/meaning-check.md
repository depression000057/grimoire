# 意味のすり替わり点検

- 役割: 話し言葉に書き直した稿が、元稿の意味を変えていないかを確かめる。読みやすさと引き換えに、主張や数字や約束がずれるのを防ぐ
- いつ読むか: 品質工程の段5（`references/quality/pipeline.md`）
- 目次: §1 比べる7つ §2 やり方 §3 判定の決まり §4 記録の形

## §1 比べる7つ

| # | 比べるもの | ずれの例 |
|---|---|---|
| 1 | 主張 | 「〇〇するな」が「〇〇しなくてもいい」に弱まった |
| 2 | 事実・数字・固有名 | 「3か月」が「数か月」になった／商品名が消えた |
| 3 | 読者にしてほしい行動 | 「プロフィールのリンクから」が「気になったら」になった |
| 4 | 因果（なぜそうなるか） | 理由の文が消えて、結論だけが残った |
| 5 | 約束の強さ | 「〜できます」が「〜できるかもしれません」になった／逆に強まった |
| 6 | 対象の読者 | 「40代で子育て中の人」が「みなさん」になった |
| 7 | 否定と条件 | 「〜の時だけ」が消えて、いつでもそうだという話になった |

5 は両方向に気をつける。弱まると読者は動かない。強まると、元稿が言っていない約束をしたことになる（絶対ルールに触れることがある）。

## §2 やり方

1. 元稿と書き直し稿を、段落ごと（Threads は1本ごと）に並べる
2. 段落ごとに §1 の7つを順に当てる
3. ずれた所を §4 の表に書く
4. 表に書いた所だけを、統合の段（`pipeline.md` §3 段6）で元稿の言葉に戻す

## §3 判定の決まり

- **言い方が変わっただけで意味が同じなら、ずれではない**。書き直し稿のまま残す（話し言葉にした効果を消さないため）
- 数字・固有名・期間・値段が変わったら、必ずずれとする
- 元稿に無かった例・体験・効果が足されていたら、ずれとする（作り話が混ざるのを防ぐため）
- 迷ったら、「読者がこの2つを読んで、違う行動をとるか」で決める。違う行動をとるなら、ずれ

## §4 記録の形

```yaml
- 場所: 3段落目（Threads なら投稿番号）
  種類: 5 約束の強さ
  元稿: 「3日で変わります」
  書き直し稿: 「変わっていくはずです」
  判定: ずれ → 元稿の「3日で」を戻す
```

記録は本文に混ぜない。ファイルが書ける環境では、制作物のフォルダに `意味の点検.md` として残す（受講生が見返せるように）。
