# モード3 ローンチ→エバー

- 役割: note を「期間を区切って一気に売る（ローンチ）」計画と、「常設の入口から売れ続ける（エバー）」形への切り替えを、本人の数字と段階に合わせて設計する
- いつ読むか: 「ローンチしたい」「販売期間の計画」「エバーにしたい」「導線を作りたい」「売れ続ける形にしたい」と言われた時
- 目次: §1 現在地の診断 §2 読むもの §3 ローンチ計画 §4 エバー化の設計 §5 切り替えの手順 §6 数字の見張り方 §7 提出 §8 やってはいけないこと

## §1 現在地の診断

最初に、今どの段階かを決める。段階によって、やることがまったく違うため。

| 段階 | 目印 | このモードでやること |
|---|---|---|
| A まだ売る物が無い | 有料 note が無い | 需要の確かめ方と、最初の note の方向（→ モード2へ） |
| B ローンチ準備 | note はある／これから出す | §3 ローンチ計画 |
| C ローンチ中 | 販売期間の途中 | 残りの期間の投稿と、数字の見張り（§6） |
| D ローンチ後 | 販売期間が終わった | 振り返り（→ モード5）と §4 エバー化の設計 |
| E エバー運用中 | 常設で売っている | §4 の見直しと、月1回の点検 |

聞くこと（設定と実績で分かる所は聞かない）: 今の段階、フォロワー数、1投稿あたりの閲覧のおおよそ、note の販売数、LINE の登録数（使っていれば）。数字が無い時は「分からない」で進めてよい。

## §2 読むもの

1. `00_わたしの設定.md`（売りたいもの・読者1人・センターピン）
2. `40_実績/` の数字
3. カード: stage `launch` `evergreen` `threads-cta` `account`
4. `references/knowledge/sales-launch-evergreen.md` の全文

## §3 ローンチ計画

**期間**: 最初のローンチは7〜14日を目安にする。短すぎると告知が届かず、長すぎると期間を区切る意味が薄れるため。本人の投稿ペースで回せる長さに合わせる。

**流れ**: 予告 → 公開 → 締切前 → 締切。それぞれで出す投稿の種類は `sales-launch-evergreen.md` §3。

**カレンダー表**:

| 日 | 段階 | 投稿の種類 | 1行目の方向 | 狙い | CTA |
|---|---|---|---|---|---|

- 毎日販売の投稿にしない。教育や有益の投稿を混ぜる（売り込みだけが続くと、フォロワーが離れるため）
- 締切は本当に終わる日にする（§8）
- 用意する物の一覧も付ける: note 本体・告知用の投稿・プロフィールの一文・固定投稿・（使っていれば）LINE の案内

表ができたら、投稿そのものはモード1で作る（「このカレンダーの投稿を作りますか」と聞く）。

## §4 エバー化の設計

エバーとは、販売期間を区切らず、いつ来た読者でも買える状態を作ること。そのために「常設の入口」と「定期的に思い出させる仕組み」を作る。

**常設の入口**

| 入口 | 作るもの |
|---|---|
| プロフィール | 誰の何を解決する人か＋ note への一文 |
| 固定投稿 | note を読む理由が1投稿でわかるもの（ツリーで中身の一部を見せる形が作りやすい） |
| 無料 note | 有料 note の手前の入口になる記事（有料で扱う壁の1段目を越えさせる） |
| note の中の回遊 | 無料 note → 有料 note → LINE（使っていれば）のリンク |

**定期的に思い出させる仕組み**

- 週の中で、再告知の型を決めて回す（例: 月曜＝読者の悩みの言い当て、木曜＝買った人の声、土曜＝中身の一部を見せる）。型の候補は `sales-launch-evergreen.md` §4
- 読者の声は、本人の了承を取ったものだけを使う
- 価格と特典は、ローンチの時と常設の時で分けて決める（ローンチ限定の特典を常設で続けると、ローンチで買った人を裏切るため）

**月1回の点検**: どの入口から売れたか（§6）を見て、弱い入口を1つだけ直す。

## §5 切り替えの手順

ローンチが終わった後、エバーに切り替える順番:

1. ローンチの振り返り（モード5）: どの投稿から売れたか、どこで止まったか
2. ローンチ中に note の販売やプロフィールへの移動が多かった投稿を、常設の入口（固定投稿・再告知の型）に作り替える
3. プロフィールと固定投稿を常設の形に直す
4. 常設の価格と特典を決め、note の本文の期間限定の表現を消す
5. 週の再告知の型を決めて、最初の2週分の投稿をモード1で作る

## §6 数字の見張り方

導線のどこで読者が落ちているかを、段ごとに見る。

| 段 | 見る数字 | 低い時にまず疑う所 |
|---|---|---|
| 見られる | 投稿の閲覧数 | 1行目・投稿の時間帯 |
| 興味を持たれる | プロフィールへの移動・フォロー | 投稿とプロフィールの話がつながっているか |
| note が読まれる | note の閲覧数 | プロフィールと固定投稿の誘導の一文 |
| 買われる | 販売数 | 無料部分と有料ラインの位置・値段 |

数字の読み方の詳細は `sales-launch-evergreen.md` §6。1回の数字で決めつけず、同じ傾向が続いた時に直す。

## §7 提出

- 診断の結果（段階と根拠1行）
- ローンチならカレンダー表と用意する物、エバーなら入口の表と週の型
- **使ったカード**・**確かめてほしいこと**（最大3つ）・**次の一手**（1つ。多くの場合「このカレンダーの最初の3日分の投稿を作ります」）

ファイルが書ける環境では `ティルナノーグ_制作物/YYYY-MM-DD_launch_<テーマ>.md` に保存する。

## §8 やってはいけないこと

- **本当には終わらない締切を書く**（「今日で終わり」と言って翌日も売る）。読者をだますことになり、信用を失う
- **根拠のない実績や、誰でも稼げるような表現**で煽る（`references/quality/absolute-rules.md`）
- **買った人の声を作る・言い換えて盛る**
- **ローンチ限定と言った特典を、そのまま常設にする**
