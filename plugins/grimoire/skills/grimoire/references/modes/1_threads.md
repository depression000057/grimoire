# モード1 Threads

- 役割: Threads の投稿（単発・ツリー）を、本人の設定とカードとお手本を使って作り、仕上げて渡す
- いつ読むか: 「投稿作って」「N本作って」「ツリーにして」「この投稿直して」と言われた時
- 目次: §1 最初に決めること §2 読むもの §3 企画 §4 1行目 §5 本文 §6 ツリー §7 仕上げ §8 提出 §9 既存の投稿を直す時 §10 よくある失敗

## §1 最初に決めること

依頼から、次の3つを決める。言われていないものは、おすすめで決めて提出時に伝える（聞き返して手を止めない）。

| 決めること | 言われていない時のおすすめ |
|---|---|
| 本数 | 5本 |
| 目的 | 設定の「今の段階」に合わせる。note を出す前は集客と教育、販売期間中は販売、エバー運用中は教育と再告知 |
| テーマ | 設定のセンターピンから、読者の「止まっている壁」に近い順に選ぶ |

## §2 読むもの

書く前に、次の順で読む。

1. `00_わたしの設定.md`（読者1人・センターピン・声・禁止したい言葉）
2. カード: stage `threads-plan` `threads-hook` `threads-body` `threads-cta`（ツリーなら `threads-tree` も）。マイナレッジの `索引.md` → `references/course/索引.md` の順に、各 stage の上から読む（Python が動くなら `tn_kb.py select`）
3. お手本: マイナレッジの `10_お手本/` から、今回の型に近い投稿を1〜2本。無ければ `assets/golden-samples/` から1〜2本。全文を読む
4. `references/knowledge/threads-posting.md` の §1（1行目）・§3（型カタログ）・§5（CTA）・§6（企画の混ぜ方）・§8（投稿前チェック）

## §3 企画

2本以上の時は、書く前に企画表を作る。1本ずつ思いつきで書くと、同じ型・同じ入り方が続いて、読者に「またこの話」と思われるため。

| # | 軸 | 型 | ボリューム | 1行目の方向 | この投稿で読者に起きてほしいこと |
|---|---|---|---|---|---|

- **軸**は、有益・興味付け・集客・教育の4つを混ぜる。有益だけで埋めない（役に立つだけの投稿は保存されても、発信者への興味や note への関心が育たないため）
- **型・1行目の型・入り方・見せ方**の散らし方は `references/knowledge/threads-posting.md` §6 の数に従う（数の決まりはそのファイル1か所に置き、ここでは繰り返さない）
- **ボリューム**（ミディアム・ロング・ヘビー・ツリー）は、先に本数ぶん割り振ってからテーマを当てる（`threads-posting.md` §4-1 の割り振り例）
- note・LINE・プロフィールへの案内（CTA）の割合は `threads-posting.md` §5 に従う
- 10本以上の時は、企画表を先に見せて「1: この企画で書く／2: 直す」を1回だけ聞く。9本以下は確認せずに書く
- 企画表は、本数にかかわらず制作物のファイルの末尾（`## 提出メモ` の下）に残す（振り返りで、どの軸・型・ボリュームの投稿が伸びたかを数字と突き合わせるため）。1本だけの時は、書く前に表は作らなくてよいが、提出メモに1行（軸・型・ボリューム・狙い）を残す

## §4 1行目

1本ごとに、1行目の候補を5案出してから選ぶ（10本以上の時は3案）。1行目で読まれるかどうかが決まるので、最初に思いついた1案で決めない。

- 候補の作り方と選ぶ観点は `references/knowledge/threads-posting.md` §1・§9
- 選ぶ時に当てる3つの問い:
  1. 読者は、自分のことだと思うか（主語は読者か、誰にでも起きる現象か）
  2. 具体的な物・数字・場面が入っているか
  3. 本当に人が口にする日本語か（紙の上でしか成立しない言い回しは落とす）
- マイナレッジに `threads-hook` のカードがあれば、候補を作る前に読んで、候補の半分以上をそのカードに沿わせる

## §5 本文

- 流れの基本は「主張 → 理由 → 具体例 → コメントを誘う一言」。1投稿に1テーマ
- 読者1人を思い浮かべて、その人に話しかける言葉で書く。例え話は、その人が毎日手で触る物から作る（設定の「読者1人」に書いてある）
- 声は `00_わたしの設定.md` の「声」に合わせる。一人称・語尾・絵文字・改行の癖を守る
- 実績・体験は、設定に書いてある事実だけを使う。無い実績を作らない（`references/quality/absolute-rules.md`）
- 1パート500字以内（Threads の上限）

## §6 ツリー

ツリー（続き投稿で1つの話をつなぐ形）にする時:

- 1パート目だけで読んでも意味が通るように書く（1パート目で離れる人が多いため、前置きで終わらせない）
- 各パートの最後に、次を読みたくなる一文を置く
- 分け方・本数の目安は `references/knowledge/threads-posting.md` §4
- 区切りは `### ツリー2` のように見出しで書く（機械チェックがパートを数えられるように）

## §7 仕上げ

`references/quality/pipeline.md` の「Threads の場合」の順で仕上げる。要点:

1. 1本ずつ、日本語の破綻を点検する（`references/quality/breakdown-checklist.md`）
2. 書き直し担当に切り替えて、話し言葉に書き直す（`references/quality/rewrite-pass.md`）
3. 書き直す前と後で意味がすり替わっていないかを確かめ、書き直した方を土台に統合する（`references/quality/meaning-check.md`）
4. 事実と声の照合（`references/quality/pipeline.md` §3 段6b）: 本人について書いた期間・回数・数字・結果・読者の反応を、設定・お手本・実績と1つずつ照らし、裏付けの無い盛りを消す。改行の癖・一人称・絵文字を設定の「声」と照らす
5. 機械チェック: `python3 <スキルのフォルダ>/scripts/tn_check.py threads <ファイル> --settings <マイナレッジ>/00_わたしの設定.md`。動かない時は `references/knowledge/threads-posting.md` §8 のチェックリストを1本ずつ当てる
6. 最後に、読者になったつもりで1本ずつ読み、「ここでスクロールを止めるか」「最後まで読むか」を自分に聞く。止まらない投稿は、1行目から作り直す

## §8 提出

投稿ごとに次の形で出す。

```yaml
## 投稿1（軸: 教育／型: 〇〇／ボリューム: ロング／狙い: 読者に起きてほしいこと1行）
（本文。ここをそのままコピーして投稿できる形。本文の中にメモを書かない）
```

見出しの行に軸・型・狙いをまとめるのは、本文だけをそのままコピーできるようにするため（機械チェックも見出しの行は字数に数えない）。

全部の後に `## 提出メモ` という見出しを置き、その下に次を書く（この見出しから後ろは、機械チェックが投稿として数えない）:

- **使ったカード**: id とタイトル
- **書き直しで直した所**・**事実と声の照合で直した所**: それぞれの数（`references/quality/pipeline.md` §3）
- **確かめてほしいこと**: 最大3つ（例: 「3本目の数字はあなたの実績ですか？」）
- **次の一手**: 「投稿して2〜3日たったら、各投稿の数字（閲覧・いいね・返信・フォロー増）を貼ってください。どれが効いたかを振り返ります」

ファイルが書ける環境では `ティルナノーグ_制作物/YYYY-MM-DD_threads_<テーマ>.md` に保存し、末尾に使ったカードを残す。

## §9 既存の投稿を直す時

- 直す前の投稿を残してから直す（前後がそろうと、受講生が自分で直した時にお手本カードにできるため）
- 何を変えたかを1〜3点で伝える
- 受講生が「これいいね」と言った直し方は、`references/modes/4_grow.md` の手順でお手本カードにする

**1行目の主語を読者に入れ替える**（自分の体験から書き始めた投稿が伸びない時・受講生の下書きが「私は〜」で始まっている時）:

1. 下書きの体験の中から、読者の多くが「自分にもある」と思える現象や場面を1つ取り出す（例: 仕事から帰って台所に立った瞬間に、何を作るか決まっていない）
2. 1行目は、その現象を主語にして書く。「〜な人は、」「〜のは、」の形でよい
3. 2行目で、読者が思い込んでいそうな常識を1つ否定する
4. 答えは言い切らず、ツリーの2本目で出す前提で切る
5. 本人の体験は3行目以降に、証拠として1〜2文で入れる。肩書きは最後に1行
6. 年代・性別・病名などで1行目の対象を狭めない
7. 書き直し案を3つ出し、それぞれの1行目の主語が何かを1行添える。下書きの事実は変えない（体験を足さない・数字を作らない）

体験そのものが誰もが知りたい珍しい話の時は、自分が主語のままでも読まれるので、入れ替えない。

## §10 よくある失敗

| 失敗 | なぜ起きるか | 防ぎ方 |
|---|---|---|
| 1行目が状況説明（「今日は〜について話します」） | 書き手が説明から入りたくなる | §4 の候補5案を必ず出す |
| どの投稿も同じ入り方 | 企画表を作らずに1本ずつ書く | §3 の企画表を先に作る |
| 誰にでも当てはまる文 | 設定の読者1人を読まずに書く | §2 の1を飛ばさない |
| 売り込みが多い | CTA を毎回入れる | CTA の割合は `threads-posting.md` §5 に従う |
| 全部が同じ長さ | テーマから書き始める | 先にボリュームを割り振る（`threads-posting.md` §4-1） |
| 実績を盛る（「何年も」「一番よく届く」「0分」） | 説得力を足したくなる。小さな盛りは書き手が気づかない | §7 の4（事実と声の照合）で1つずつ照らす。無ければ「確かめてほしいこと」で聞く |
| 本人の声とずれる（改行・一人称） | 書き直しで文をつなげる | §7 の4で設定の「声」と照らす |
