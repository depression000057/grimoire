# モード2 note

- 役割: note 記事（無料・有料・セールスレター）を、設計→タイトルと冒頭→通しの執筆→仕上げ→貼り付け用の書き出し、まで作る
- いつ読むか: 「note 書いて」「有料 note を作りたい」「タイトル案」「セールスレター」と言われた時
- 目次: §1 最初に決めること §2 読むもの §3 設計 §4 タイトルと冒頭 §5 確認（1回） §6 通しで書く §7 仕上げ §8 貼り付け用の書き出し §9 提出 §10 長い記事の時 §11 よくある失敗

## §1 最初に決めること

| 決めること | 言われていない時のおすすめ |
|---|---|
| 種類 | 設定の「売りたいもの」が有料 note なら有料記事。売る物がまだ無ければ、無料記事（読者を集め、次に売る物の需要を確かめる） |
| 目的 | 有料記事＝買った人の壁を越えさせる／無料記事＝有料 note や LINE への入口／セールスレター＝買う理由をそろえる |
| 値段 | 設定の値段。無ければ `references/knowledge/note-writing.md` §1 の考え方で候補を2つ出す |
| 目標の字数 | 有料記事は 8,000〜15,000字、無料記事は 3,000〜6,000字を目安に、中身の量で決める（字数のために薄めない） |

## §2 読むもの

1. `00_わたしの設定.md`（読者1人・センターピン・見てくれない理由・声・禁止したい言葉）
2. カード: stage `note-title` `note-intro` `note-structure` `note-paid-line` `note-body` `note-cta`（マイナレッジ → 講座ナレッジの順）
3. `references/knowledge/note-writing.md` の全文（設計の前に一度）
4. お手本: 書く直前に、`10_お手本/` か講座ナレッジ（`references/course/`）から note の実物1本の全文。note の実物がどちらにも無い時は、本人の投稿のお手本（声と事実）と `assets/golden-samples/long-form.md`（長文の地の文のリズム）の2つで代える。代えたことを提出メモに1行書き、「あなたの note や、講座で配られた note があれば `10_お手本/` に入れてください。次から、その書き方に近づけます」と伝える

## §3 設計

書く前に設計表を作る。設計の無い長文は、途中で読者の気持ちが置き去りになるため。

**章の表**

| 章 | 読者の気持ち（入る時→出る時） | この章で伝えること | 型 | 字数 |
|---|---|---|---|---|

- 章は「読者の気持ちが1段進む」単位で区切る。話題の区切りで分けない（`note-writing.md` §2）
- 字数の合計は目標の±15%に収める
- **有料ライン**の位置を決める（`note-writing.md` §3）: 無料部分だけで「この人の話は信用できる」「続きに自分の答えがある」と思える所まで見せる
- **CTA は2段**: 本編の途中に軽い誘導、最後に本命の誘導（`note-writing.md` §4）。設定に LINE などの行き先が無い時は、本命の誘導を「読み終えた読者が今日やる行動を1つ」にする（行き先を作り話で足さない）
- 使う心理効果を3〜5個決めて、どの章に置くかを書く（`note-writing.md` §8。読者をだます使い方はしない）
- センターピンの「本当に欲しい場面」が、どの章で読者の目の前に出てくるかを書く
- 無料部分の10の役割（`note-writing.md` §2-2）のうち、飛ばす・置き換える役割があれば、その理由を1行ずつ書く（実績や声がまだ無い時の置き換えも §2-2）

**中身の素材の表**（有料記事では必須）

有料本編で読者に渡すやり方（手順・分量・レシピ・道具・具体例・つまずいた時の対処・本人の数字）は、**本人が実際にやっていることでなければならない**。お金を払った読者は、書き手の経験だから信じて買うため。AI が考えた手順を本人のやり方として書くと、それは作り話になる（`references/quality/absolute-rules.md` の決まり2）。

設計表と一緒に、章ごとに「この章で渡す中身」と「その素材が本人の素材の中にあるか」を表にする。

| 章 | この章で渡す中身 | 本人の素材にあるか（ある時は出どころ） | 無い時に本人に聞くこと |
|---|---|---|---|

- 素材が無い中身は、§5 の確認の時に、章ごとに2〜3問にまとめて本人に聞く（「下味は、実際にどの肉に、何の調味料をつけていますか」のように、答えやすい形で）
- 答えが無いまま書く時は、その部分を `<!-- ここに、あなたが実際にやっている〇〇を入れる -->` の枠にする。枠の周りに一般的な知識を書く時は「一般的には〜と言われています」と、本人の経験と分けて書き、「〜でした」「私は〜」の経験の言い方にしない
- **読者が真似する手順のうち、健康・食品の安全・お金・法律に関わるもの**（保存期間・解凍・加熱・体のケア・お金の動かし方・手続き）は、公的機関などの一次情報で確かめられる範囲だけで書き、確かめ先を確認メモに残す（`references/quality/absolute-rules.md` の決まり5と §4）。本人の答えは「本人がそうしている」という事実の裏付けにしかならない。本人のやり方が公的な案内と違う時は、読者に勧める形で書かず、公的な案内のやり方を書く。その時に「私もこの方法でやっています」とは書かない（本人の実際と違うため）。違っていたことは「確かめてほしいこと」で本人に伝える。確かめられない手順は書かないか枠にする

## §4 タイトルと冒頭

**タイトル案10〜20個**: 作り方は `note-writing.md` §5。カテゴリを散らして出し、各案に「カテゴリ・狙い」を添える。似た案ばかり並べない（選ぶ意味がなくなるため）。

**冒頭300字を2案**: 同じ内容で、読者との距離感が違う2案（例: A＝寄り添って話しかける／B＝言い切って引っ張る）。1行目の要件は `note-writing.md` §6。

## §5 確認（1回）

設計表・タイトル案・冒頭2案を一度に見せて、1回だけ聞く。チャットに出すのは、タイトル案の一覧（案・字数・入口・おすすめ）、冒頭2案の全文、設計表の要約（無料部分の流れ・有料ライン・章の見出しと字数）まで。採点の理由や設計の細部はファイルに保存し、場所を伝える（受講生が1画面で選べる量にするため）。

タイトル案と冒頭2案にも、品質工程の段6b（事実と声の照合）だけは先に当てる。「何年も」「0分」のような盛りが入った案を選ばせると、選んだ後で本文ごと直すことになるため。

> タイトル: 番号で選んでください（直したい言葉があれば一緒に）
> 冒頭: A か B
> 設計: 1: このまま／2: 直したい所（章の番号と内容）
> 中身の素材: 次の質問に、分かる所だけ答えてください（答えが無い所は、本文で【ここに〜を入れる】の枠にして、あとで埋められるようにします）

中身の素材の質問は、1回に10問まで。多すぎる時は、有料本編の核になる章（読者が一番お金を払う理由になる章）から聞く。設計・タイトル・冒頭は設定の事実だけで作れるので、素材の質問と同じ1回の確認で一緒に出す（確認の回数を増やさないため）。

答えが返るまで本文を書かない。本文を書いた後に設計が変わると、全部書き直しになるため。

**本人の答えは、受け取ったらすぐ保存する**。ファイルが書ける環境では `ティルナノーグ_制作物/YYYY-MM-DD_note_<テーマ>/中身の素材_本人の答え.md` に、質問と答えを並べて、答えを受け取った日付と一緒にそのまま写す（言い換えない）。会話が変わると前の答えは見えなくなり、次の点検で「本人がそう言った」という裏付けが無くなるため。ファイルが書けない環境では、提出の最後に質問と答えを1つのまとめにして出し、続きを頼む時に貼ってもらう。くり返し使えるやり方（下味の配合など）は、提出の「次の一手」で「このやり方をカードにして、告知の投稿でも使えるようにしますか」と聞く。

## §6 通しで書く

- **書き始める前に、素材の量と目標字数を見比べる**。中身の素材が集まった後、素材だけで書くと目標字数の半分に届かないと見込まれる時は、書く前に1回だけ「1: 今ある素材で短めに書く（目安〇〇字）／2: 追加で聞く（質問を3つまで）」を聞く。字数のために一般論や作り話で埋めない（無料部分と有料部分の釣り合いと、値段への納得に響くため）
- **章ごとに止めずに、最初から最後まで通しで書く**。章ごとに区切ると、章をまたぐ気持ちの流れが途切れるため
- 見出しの形: 記事タイトル＝`#`、章＝`##`、章の中の小見出し＝`###`
- 有料ラインの位置に、この1行だけを置く: `---- ここから有料 ----`
- 制作メモ（点検結果・迷った点）は本文に書かない。本人が後で埋める所（本人の一言・証拠の画像など）は `<!-- ここに〇〇を入れる -->` の形で置く（貼り付け用の書き出しで消えるため、読者に作りかけに見えない）
- 実績・体験は設定にある事実だけ。数字の無い所に数字を作らない
- 有料本編のやり方は、§3 の中身の素材の表にあるものと、§5 で本人が答えたものだけで書く。無い所は枠にする（AI が補った手順を、本人のやり方として書かない）
- 章をまたいで前の章を指す時（「〇章で見たとおり」）は、書き終えた後に、指した章に本当にその話があるかを確かめる
- 章の1行目は、前の章の終わりを受ける言葉で始める（話が飛んだと読者に思わせないため）

## §7 仕上げ

`references/quality/pipeline.md` の「note の場合」を全段通す。note は長いので、Threads より丁寧に行う。

1. 日本語の破綻点検（全文・1文ずつ）
2. 書き直し担当として話し言葉に書き直す（章ごとに行ってよい。ただし字数は元の±5%以内）
3. 意味のすり替わり点検 → 書き直した方を土台に統合
4. 事実と声の照合（`references/quality/pipeline.md` §3 段6b）: 本人の経験・期間・数字・結果・読者の声を、設定・実績と1つずつ照らす。note は長いので、本人について書いた文を先に全部抜き出して表にしてから照らす
5. 機械チェック: `python3 <スキルのフォルダ>/scripts/tn_check.py note <ファイル> --target-chars <目標字数> --settings <マイナレッジ>/00_わたしの設定.md`
6. 読者目線の点検: 冒頭300字だけを読んで「続きを読むか」、有料ラインの直前で「買うか」、最後まで読んで「次に何をすればいいか分かるか」を自分に聞く。別の AI に本文だけを渡せる環境では、読者役を頼む（書いた本人の目では、飛ばした説明に気づけないため）

## §8 貼り付け用の書き出し

- Python が動く: `python3 <スキルのフォルダ>/scripts/tn_paste.py <統合稿のファイル> --settings <マイナレッジ>/00_わたしの設定.md` で、書き出す前に機械チェックが走り、違反が残っていれば書き出さずに止まる（先に直す）。違反が無ければ`貼り付け_無料部分.txt`・`貼り付け_有料部分.txt`・`貼り付け_全文_確認用.txt` ができる。本人が埋める枠（`<!-- ここに〇〇を入れる -->`）は、確認用には【ここに〇〇を入れる】として残り、無料部分と有料部分からは消える。実行の最後に枠の一覧が出るので、そのまま「確かめてほしいこと」に写す
- 動かない: HTML コメント（`<!-- -->`）を消し、`---- ここから有料 ----` の上と下に分けて、2つのテキストとして出す
- 受講生への案内: 「note の編集画面に無料部分を貼り、有料ラインを入れてから、有料部分を貼ってください」

## §9 提出

- 貼り付け用のテキスト（または3つのファイル）
- **使ったカード**
- **確かめてほしいこと**（最大3つ。例: 「〇章の数字はあなたの実績と合っていますか」「〈本人の一言〉を入れる所が2か所あります」）
- **次の一手**: 「公開したら、1週間後に販売数・読者の感想を貼ってください。どの章が効いたか振り返ります」／告知の投稿が必要なら「この note の告知投稿を作りますか」

ファイルが書ける環境では `ティルナノーグ_制作物/YYYY-MM-DD_note_<テーマ>/` に、設計表・タイトル案・統合稿・貼り付け用を保存する。

## §10 長い記事の時

- 設計表と章ごとの要点を先にファイルへ保存してから書く（会話が長くなって前半を忘れても、ファイルから読み直せるように）
- 書く順は通しのまま、保存だけ章ごとのファイルに分けてよい
- 仕上げの工程は章ごとに行ってよいが、最後の読者目線の点検だけは全文を通しで行う

## §11 よくある失敗

| 失敗 | なぜ起きるか | 防ぎ方 |
|---|---|---|
| 無料部分で答えを全部言う／何も言わない | 有料ラインの意味を決めずに書く | §3 で「無料部分で読者に起きること」を先に決める |
| 章が教科書の目次のよう | 話題で章を分ける | 読者の気持ちが1段進む所で章を切る |
| 最後に何をすればいいか分からない | CTA を最後に1回だけ置く | CTA 2段と「次の一手」を設計表に書く |
| 冒頭で説明していない言葉を使う | 書き手は知っているので気づかない | 冒頭で使う言葉のうち、読者がまだ知らない言葉を書き出して確かめる |
| 字数が足りなくて同じ話を繰り返す | 字数を先に決めて中身を後から合わせる | 字数は中身の量で決め、足りなければ設計に戻って具体例を足す |
