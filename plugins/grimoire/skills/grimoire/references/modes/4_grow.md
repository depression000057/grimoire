# モード4 育てる（取り込み）

- 役割: 講師のフィードバック・セミナーの文字起こし・自分の数字・自分で直した文を受け取り、マイナレッジのカードにする。次の制作では、そのカードを書く前に読み、文の作り方に反映する
- いつ読むか: 「取り込んで」「覚えて」と言われた時／講師のコメントや文字起こし、数字、直した文が貼られた時（言われなくても入る。`SKILL.md`「自動で育てる場面」）
- 目次: §1 受け取れるもの §2 手順1 受け取る §3 手順2 仕分ける §4 手順3 取り出す §5 手順4 照らし合わせる §6 手順5 索引に載せる §7 手順6 報告する §8 カードの書き方 §9 ファイルが書けない環境 §10 運営が講座ナレッジを育てる時 §11 大量の素材（ファイル・長い文・フォルダごと） §12 やってはいけないこと

## §1 受け取れるもの

| 種類 | 例 | 主にできるカード |
|---|---|---|
| 講師FB | 添削のコメント・「ここは〜にしましょう」・直した後の文 | お手本（直す前→後）・原則 |
| セミナー | 講義や勉強会の文字起こし | 原則・手順・絶対NG・お手本 |
| 実績 | 投稿の数字・note の販売数・LINE 登録数 | 数字（振り返りと一緒に） |
| 自分の手直し | エージェントが出した文を本人が直したもの | お手本・声 |
| 講座の資料 | ワークシート・配布資料 | 原則・手順 |

## §2 手順1 受け取る

原文を、そのまま保存する。要約してから保存しない（後で読み直した時に、講師の言い方そのものが判断材料になるため）。

- 講師FB → `20_講師FB/YYYY-MM-DD_<何へのFBか>.md`
- セミナー → `30_セミナー/YYYY-MM-DD_<回の名前>.md`（ファイル名の日付は、セミナーを行った日が分かればその日。分からなければ受け取った日。後で「第何回の話だったか」を日付で探せるようにするため）
- 実績 → `40_実績/YYYY-MM-DD_<何の数字か>.md`
- 自分の手直し → `10_お手本/YYYY-MM-DD_<何を直したか>.md`

ファイルの先頭に、次の4行を書いてから原文を貼る:

```yaml
from: 講師（名前があれば名前）／自分／セミナー名
date: 受け取った日
about: 何についてか（例: 3月2日の Threads 投稿の1行目）
target: FB の対象になった制作物（あれば、そのファイル名か本文の最初の1行）
```

講師FBの対象の文が会話の中にある時は、その文（直す前）も一緒に保存する。直す前が無いと、お手本カードが作れないため。一部（1行目と締めだけ、など）しか分からない時は、分かっている所だけを保存し、「本文の途中は受け取っていない」と書いておく。お手本カードも、分かっている所だけで作る。

カードの本文は、一時ファイルを作らず、`--body-file -` で道具に直接渡す（例: `python3 .grimoire/scripts/tn_kb.py add-card ティルナノーグ_マイナレッジ --title … --body-file - <<'EOF'` の次の行から本文、最後の行に `EOF`）。一時ファイルを作ると、あとで消す操作のたびに受講生へ確認が出るため。

## §3 手順2 仕分ける

受け取った中身を、次のどれに当たるかで分ける。1つの原文から複数の種類が出てよい。

| 種類（kind） | 見分け方 |
|---|---|
| example（お手本） | 直す前と直した後がそろっている |
| principle（原則） | 「〜する方がいい。なぜなら〜」と、やり方と理由が言える |
| procedure（手順） | 順番がある（「まず〜、次に〜」） |
| ng（絶対NG） | 「これは絶対にやらない」と講師が言い切っている |
| metric（数字） | 何を測って、いくつだったか |

雑談・近況・宣伝・他の受講生の個人的な話はカードにしない。

## §4 手順3 取り出す

取り出す順番は、**お手本 → 原則 → 手順 → 絶対NG → 数字**。お手本を最優先にする理由は、文章の質はルールの数よりお手本の量と近さで決まるため。

種類別の決まり:

- **講師FB**: 直す前と後から、お手本カードを1枚作る。講師が理由を言っていれば、その理由を原則カードにする。理由を言っていない時は、推定の理由を書いて `confidence: 推測` にする（講師の言葉と自分の推定を混ぜない）
- **セミナー**: 話題ごとに区切り、1話題から原則・手順・絶対NG・お手本を取り出す。講師の言葉は1〜2文までなら引用で残し、残りは自分の言葉でまとめる。長い回（1時間以上）は、まず話題の一覧を作ってから取り出す（途中で抜けを出さないため）
- **実績**: `references/modes/5_review.md` の振り返りと一緒に、数字カードを作る。1件だけの数字で原則カードを作らない（偶然を法則と取り違えないため。同じ傾向が3件そろったら原則にする）
- **自分の手直し**: 直す前と後を並べ、何を変えたか（語尾・言葉選び・順番・長さ）を1〜3点書いてお手本カードにする。言葉の癖が見えたら、`00_わたしの設定.md` の「声」の節も更新する

入力に書かれていないことをカードにしない。一般論や、このエージェントがもともと知っていることを足さない。

## §5 手順4 照らし合わせる

新しいカードを書く前に、似たカードが既にあるかを確かめる。

1. 似たカードを探す
   - Python が動く: `python3 <スキルのフォルダ>/scripts/tn_kb.py similar <マイナレッジ> --text "<新しいカードのタイトルと要点>"`
   - 動かない: `索引.md` の同じ stage の見出しを読んで、タイトルで探す
2. 上位3件は、点数に関係なく開いて読み、次の3つのどれかに決める。点数は文字の重なりで測るので、同じ話でも言い方が違うと低く出る（講師が同じ話を別の言葉でくり返した時、0.2 に届かないことがある）。点数が 0.35 以上なら、ほぼ同じ話と考えてよい

| 判定 | やること |
|---|---|
| 同じ内容 | 新しいカードは作らず、既存のカードを「強める」（`tn_kb.py strengthen <id> --source-ref <原文のパス>`。出典が増え、読む順が上がる） |
| 食い違う | 新しいカードを作り、古いカードを「更新済み」にする（`tn_kb.py supersede <古いid> --by <新しいid>`）。講師の言葉同士なら新しい方を優先する。講座ナレッジやエンジンと食い違う時は、マイナレッジのカードが勝つ（本人専用に育てるため）ので、そのまま作る |
| 新しい | カードを作る（`tn_kb.py add-card …`） |

絶対ルール（`references/quality/absolute-rules.md`）と食い違う内容は、カードにしない。報告の中で「このFBは絶対ルールと合わないため保存しませんでした」と伝え、理由を1文で添える。

## §6 手順5 索引に載せる

カードを書き終えたら、`索引.md` を作り直す。

- Python が動く: `python3 <スキルのフォルダ>/scripts/tn_kb.py index <マイナレッジ>`
- 動かない: `索引.md` の各 stage の見出しの下に、`- <id> <タイトル>（<kind>・強さ<strength>）` を足す。更新済みにしたカードは、末尾の「更新済み（読まない）」へ移す

## §7 手順6 報告する

最後に、受講生へ次の形で報告する。育っている実感が、使い続ける理由になるため、毎回必ず出す。

```yaml
取り込み完了: <何を取り込んだか>
新しく覚えたこと: N 件（1件1行で id とタイトル）
強まったこと: M 件
更新したこと: K 件（古い → 新しい）
次の制作で変わること: <1行。例: 次の投稿から、1行目を読者の行動を否定する形で始めます>
```

育成ログに1行足す（`tn_kb.py log <マイナレッジ> --input "<何を>" --new N --strengthened M --superseded K --next "<1行>"`）。

先には聞かずに作る（受講生は渡すだけで済むようにするため）。6枚以上になった時は、報告でタイトルの一覧に番号を付けて見せ、「要らないカードがあれば番号で言ってください。更新済みにして使わないようにします」と添える。

## §8 カードの書き方

雛形は `assets/card-template.md`。決まり:

- **1枚に1つの知見**。2つ入れたくなったら2枚に分ける（食い違いの判定がしやすくなるため）
- **タイトルは行動の形**で書く: 「1行目は読者の行動を否定する形で始める」。「1行目について」のような名札にしない（索引を見ただけで使えるように）
- **stages** は、そのカードを読むべき工程を1〜3個。多すぎると、関係ない工程でも読まれてしまう
- **confidence** は、カードの中で一番弱い所に合わせる（例: やることは講師が言い切ったが、理由は推測 → `推測`）。本文では、講師の言葉と推定をはっきり分けて書く（「講師: 〜」「推定: 〜」）。後で講師が理由を言ったら、そのカードを `tn_kb.py strengthen <id> --source-ref <新しい原文> --confidence 講師明言` で強めて確かさを上げる（下げる方向の変更はできない。内容が変わった時は新しいカードを作って `supersede` する）
- 本文の形:
  - お手本: 「直す前」「直した後」「何を変えたか（1〜3点）」「なぜ（講師の言葉か推定か）」
  - 原則: 「何をするか」「なぜか」「どの場面で使うか」「使わない場面」
  - 手順: 番号つきの手順と、各手順でやること
  - 絶対NG: 「やらないこと」「なぜか」「代わりにどうするか」
  - 数字: 「何を」「いくつ」「いつ」「どの投稿か」「その投稿で使ったカード」
- 他の受講生の名前・個人的な事情は書かない（セミナーに出てきても消す）

## §9 ファイルが書けない環境

ブラウザ版の AI や ChatGPT のプロジェクトなど、ファイルを保存できない環境では、半自動で育てる。

1. 手順1〜5を会話の中で行う（原文もまとめの中に入れる）
2. 最後に、更新した「マイナレッジ_まとめ.md」を丸ごと1つ出す（作り方と受講生への案内は `references/environments.md` §4）
3. 報告（手順6）の最後に「新しいまとめをプロジェクトの古いまとめと入れ替えてください」と1行添える


## §10 運営が講座ナレッジを育てる時

講座の運営がこのモードを使う時は、書き込み先をマイナレッジではなく講座ナレッジのフォルダ（`course-knowledge/`）にする。手順は同じ。違いは3つ:

- `said_by` に講師の名前を入れる（受講生が、誰の教えかで重みを判断できるように）
- 1人の受講生への個別の添削は、講座ナレッジにしない（その人の文脈でしか正しくないことがあるため）。全員に当てはまる原則だけを入れる
- 書き終えたら、配布用の更新パックを作る（運営用の手順書に従う）

## §11 大量の素材（ファイル・長い文・フォルダごと）

受講生がチャットに渡した長い素材（数時間〜数十時間分の文字起こし・講義の資料・字幕・過去の投稿の書き出し）を、**受講生に何もさせずに**取り込む手順。講座の運営が講座ナレッジに取り込む時（§10）も同じ手順を使う。

**いつ入るか**（言われなくても入る）:

- ファイルが添付された、またはファイルの場所（パス）がチャットに書かれた
- 長い文が貼られた。フックが原文を `ティルナノーグ_マイナレッジ/_受け取り/<日時>.json` に保存し、「長い文を保存しました」とその場所を伝えてくる
- 「続きを取り込んで」と言われた、または `ingest-status` に残りがある

**原文は書き写さない**: 長い原文を AI が書き写して保存すると、遅く、途中で切れ、写し間違いも入る。原文の保存と区切りは、必ず道具（`tn_kb.py add-source`）に任せる。

### 手順

1. **原文を受け取る**（どれか1つ）
   - ファイルの場所が分かる時: `python3 <スキルのフォルダ>/scripts/tn_kb.py add-source <マイナレッジ> --kind <種類> --file <ファイル> [--file <次のファイル> …] [--date <日付>]`。フォルダごとなら `--from-dir <フォルダ>`
   - 長い文が貼られた時（フックが保存済み）: `python3 <スキルのフォルダ>/scripts/tn_kb.py add-source <マイナレッジ> --kind <種類> --prompt-json <フックが伝えた .json>`
   - 添付されたファイルの場所が分からず、中身だけが会話にある時: 中身が短ければ（目安1万字まで）原文を `<マイナレッジ>/_受け取り/<日時>.txt` に書き出してから `--file` で渡す。長ければ、受講生に1回だけ「そのファイルをグリモワールのフォルダに入れてもらえますか（Finder でドラッグ）」と頼む。それもできない時は、会話の中の文からカードだけを作り、育成ログに「原文は会話の中だけ」と書く
   - 種類（`seminar`＝セミナー・講義／`feedback`＝講師FB／`results`＝数字・実績／`sample`＝お手本）は中身から判断する。日付は、セミナーの日が分かればその日、分からなければ省略（受け取った日になる）
   - 道具は原文を `30_セミナー/` などにそのまま写し、1万2千字ごとの区切り（`<原文の名前>_分割/part-001.md` …）と、進み具合の記録（`取り込み状況.json`）を作る。前に取り込んだのと同じ中身は、自動で飛ばして「取り込み済み」と表示する（受講生が「取り込み直して」と言った時だけ `--allow-duplicate`）
   - 元のファイル（受講生のパソコンのどこか・`_受け取り/`）は消さない
2. **見通しを1行で伝えて、そのまま進める**: 「全部で N 区切り（約 X 万字）あるので、順に覚えていきます」。確認は挟まない
3. **1区切りずつ読む**: `tn_kb.py ingest-status <マイナレッジ>` で次の区切りを確かめ、その区切りのファイルを**全文**読む。§3〜§5（仕分ける→取り出す→照らし合わせる）の手順でカードを作る。1区切りから作るカードは5枚くらいが目安だが、**講師が言い切った原則・手順・絶対NGは、5枚を超えても落とさない**（落とすと、講師の教えがマイナレッジから消えるため）。数を抑えるのは、雑談・言い換え・1回きりの例え話の方で行う。似たカードがあれば新しく作らず `strengthen` で強める（同じ話が何度も出てくるのは、講師がそれだけ大事にしている証拠なので、強化の回数に残す）。読み終えたら記録する

   ```bash
   python3 <スキルのフォルダ>/scripts/tn_kb.py ingest-done <マイナレッジ> <素材のid> --part <番号> --cards C-…,C-…
   ```

   カードにする話が無い区切りも、`--note "雑談と告知のみ"` のように理由を書いて済みにする（飛ばした区切りと区別するため）
4. **前の区切りの本文は覚えておかなくてよい**: 区切りをまたぐ話は、カードの本文と `source_ref`（区切りのファイル名）で後から追える
5. **区切りが多い時**: 1回の返事で全部を終わらせようとしない。会話が長くなってきたら、そこまでの報告をして「残り N 区切りは、次に話しかけてもらった時に続けます」と伝える。次の会話では「毎回、最初にやること」の4で、言われなくても続きから進む
6. **全部済んだら**: `index` → `log`（取り込んだもの: 素材の題名と区切りの数）→ §7 の報告。報告では、作ったカードを種類ごとの枚数で示し、次の制作で一番効きそうな3枚だけをタイトルで見せる（全部並べると読まれないため）。種類の判断・講師名・日付で分からなかった所は、最後に1行で聞く

### Python が動かない時

- 原文のファイルは、ファイルを写す道具（`cp`）でマイナレッジの `30_セミナー/` などに写す。AI が本文を書き写さない
- 区切りは、ファイルを読む道具で行の範囲を決めて少しずつ読む（例: 1回に300行）
- 進み具合は、マイナレッジの `取り込み状況.md` に「素材・読んだ行・作ったカード」を表で書き足す

### やってはいけないこと（大量の素材）

- 長い原文を、会話の中で書き写して保存する
- 受講生に「取り込み用のフォルダに移してください」「取り込んでと言ってください」と頼む（渡された物は、そのまま受け取る）
- 区切りを飛ばして「だいたい分かった」で済ませる（講師の大事な話は後半にあることも多い）
- 同じ話の言い換えでカードを増やす（`similar` で確かめてから作る）

## §12 やってはいけないこと

- 原文を捨てる・要約だけ残す
- 入力に無いことをカードにする
- 1件の数字から原則を作る
- 古いカードを消す（消さずに「更新済み」にする。後で経緯を追えるように）
- 絶対ルールと食い違う内容をカードにする
- 他の受講生の個人情報を残す
