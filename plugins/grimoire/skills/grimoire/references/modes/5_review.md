# モード5 振り返り

- 役割: 投稿や note の数字を受け取り、その制作で使ったカードと突き合わせて、次にやることを1つに絞る。数字は実績カードとして残し、カードの読む順に反映する
- いつ読むか: 数字が貼られた時／「伸びない」「どれが良かった？」「今週の振り返り」と言われた時
- 目次: §1 受け取る数字 §2 手順 §3 原因の切り分け §4 カードへの反映 §5 提出 §6 やってはいけないこと

## §1 受け取る数字

| 対象 | 数字 |
|---|---|
| Threads 投稿 | 閲覧・いいね・返信・再投稿・引用・フォロー増（分かれば）・プロフィールへの移動（分かれば） |
| note | 閲覧・スキ・販売数・どこから来たか（分かれば） |
| LINE | 登録数（使っていれば） |

スクリーンショットの時は、読み取った数字を表にして「この数字で合っていますか」と1回だけ確かめる（読み違いのまま振り返ると、結論が全部ずれるため）。

## §2 手順

1. 数字を `40_実績/YYYY-MM-DD_<対象>.md` に表で保存する
2. 対象の制作物を探す: `ティルナノーグ_制作物/` の保存ファイル（使ったカードが末尾に書いてある）。見つからなければ本文を貼ってもらう
3. 上位と下位を並べる。比べる数字は、閲覧に対する反応の割合（いいね÷閲覧、返信÷閲覧）も見る（閲覧が多いだけの投稿を良い投稿と取り違えないため）
4. 上位と下位の違いを §3 の観点で1つずつ見比べる
5. 原因を1つに絞る。次にやることも1つに絞る（2つ以上を同時に変えると、次の数字が上がった時に、どちらの変更で上がったのか見分けられなくなるため）
6. §4 でカードに反映する

## §3 原因の切り分け

上位と下位で、次の順に違いを探す。上から順に見るのは、上ほど数字への影響が大きいため。

1. 1行目（主語・具体語・主張の強さ・長さ）
2. 型とボリューム
3. テーマ（読者の止まっている壁に近いか）
4. 投稿した曜日と時間
5. CTA の有無

段階ごとの見方（フォロワーが少ない時期は閲覧の伸び、増えてきたら反応の割合、など）は `references/knowledge/threads-account-ops.md` §4・§5。

## §4 カードへの反映

- 数字は、対象ごとに数字カード（`kind: metric`・`confidence: 実測`）を1枚作る。本文に「どの投稿か」「数字」「その投稿で使ったカード」を書く
- **1件の数字だけで原則カードを作らない**。同じ傾向（例: 読者が主語の1行目の方が、反応の割合が高い）が3件そろった時に、原則カード（`confidence: 実測`）を作る
- 上位の投稿で使ったカードは、同じ傾向が3件そろった時に `strengthen` して読む順を上げる
- 受講生が「この投稿はお気に入り」と言ったものは、数字に関係なく `10_お手本/` に入れる

作ったカードは、`references/modes/4_grow.md` §5〜§7 の手順（照らし合わせ・索引・報告）を通す。

## §5 提出

```yaml
振り返り: <対象と期間>
よかった投稿: <1〜2本と理由1行>
伸びなかった投稿: <1〜2本と理由1行>
原因: <1つ>
次にやること: <1つ。例: 次の5本は、1行目の主語を全部読者にする>
覚えたこと: <作ったカード・強めたカード>
```

次にやることが制作なら、「その方針で次の投稿を作りますか」と聞く。

## §6 やってはいけないこと

- 1件の数字から法則を言い切る
- 数字が悪い投稿を責めるだけで終わる（次にやることを必ず1つ出す）
- 受講生が貼っていない数字を推測で埋める
