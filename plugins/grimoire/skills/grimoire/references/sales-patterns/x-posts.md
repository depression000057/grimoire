# x-posts — X の短文・長文ポストの型

目次: 1 投稿の3つの役割／2 型の選び方／3 短文の型（S1〜S4）／4 長文の型（X1）／5 運用の原則

使い方: 投稿の役割を決め、1本ごとに型を1つ選んで枠を埋める。複数本まとめて作る時は、同じ型を3本続けない。短文は1本につき全角140字まで（半角は0.5字として数える）。依頼に字数が無ければ、この上限の内で目標を仮に置く。記入欄のある本は、書き手が埋めても上限を超えないよう、記入欄に字数の上限（「20字以内」など）を書く。点検は改行を数えないので、改行の多い投稿は上限より少し短めにする。

- 短文で書き手が何者かを示す1行を足す時は、1行目（型の最初の枠）を優先し、何者かの1行は締めの前に置いてよい
- 目指す姿を想定の場面（「〜になったら」）で描く時は、場面を描くことにとどめ、続く文でも効果（減る・増える）を言い切らない

- 目的がフォローを増やすことでも、フォローを頼む一文は入れなくてよい。入れる時は、フォローすると読者が何を得るか（次に何を出すか）を添える

- S1・X1 は順番のある枠の型。枠を上から全部埋める
- S2〜S4 は選択肢の表。1本につき切り口・題材・形を1つ選ぶ。設計シートの枠の表では、選んだ行の名前を最初の枠（`本1-切り口: よくある思い込みを批判する` のように）にし、その行の中身の列には、この本で何を扱うか（何を疑うか・何を描くか）を1行で書く。その下に本文の段ごと（1行目・中身・締め）に行を分ける。選ばなかった行は並べない。型に無い物（書き手が何者かの1行・フォローで届く物）を足す時は「追加」の行にする（`#` の列は「本4-追加1」のように本の番号を付け、次の行の通し番号はそのまま続ける）
- S3 の題材はどれも書き手の経験や様子が要る。依頼に経験が書かれていなければ S3 は選ばず、S1・S2・S4 から選ぶ（どうしても使う時は、経験の部分を記入欄にし、出力④にその本は経験がある時だけ出すと書く）
- 冒頭の一言は、`hooks.md` の30の型のほか、§3 の要素（数字・呼びかけ・得られること など）から作ってもよい。設計シート §6 の型の列にはその名前を書く
- 設計シートでは、枠の名前の頭に「本1-」「本2-」を付けて、本ごとに並べる
- `hooks.md` の型で1行目を作る時は、その1行を型の最初の枠（S1 なら「対象と推奨」、X1 なら「一文目の見出し」、S2〜S4 なら切り口の下の「1行目」の行）の中身として書く。2行目に置く読者の「あるある」も同じ枠に入れる。別の枠として後ろに並べない（設計シートの順番と本文の順番をそろえる）
- 書き手の体験（失敗・苦労・変化）を題材にする投稿は、依頼に書かれた事実だけを使う。無ければ体験の部分を `【書き手が記入: 〜】` にする

## 1 投稿の3つの役割

| 役割 | 何につながるか | 使う型 |
|---|---|---|
| 興味をひく | フォロー・続きを追ってもらう | S1・S2 |
| 信頼と共感を育てる（教育） | 購入・申し込み | S3・X1 |
| 役に立つ情報を渡す | 実力の証明・保存・追う理由 | S4 |

伝えたいことは毎回ほぼ同じでよい（目指す姿／うまくいかない原因／推す方法が効く理由／今すぐ動く意味／学び続ける意味／特別な条件が無くても再現できること）。変えるのは、それを運ぶエピソードと切り口。要素だけを並べると、誰の投稿も似てしまう。

## 2 型の選び方

| 目的 | 型 |
|---|---|
| 短い一文で「自分のことだ」と止めたい | S1 |
| フォロワーを増やしたい初期・反応を取りたい | S2 |
| 書き手を信じてもらいたい・買う前の気持ちを育てたい | S3 か X1 |
| 保存・シェアされる情報を出したい | S4 |
| 出来事から学びを渡したい・長く読ませたい | X1 |

## 3 短文の型

### S1 対象の宣言＋推奨＋理由

| 順 | 枠 | 中身 |
|---|---|---|
| 1 | 対象と推奨 | 「〈こういう状態の人〉は、〈これ〉を試した方がいい」と言い切る |
| 2 | 理由 | ほかの方法と比べて何が違うか、使うと何が変わるか（言い切れる事実だけ） |
| 3 | 具体 | 使い方の一例（指示の一文・手順の一つ） |
| 4 | 続きへの誘導 | 返信欄・固定投稿などに詳しい物を置き、「短い時間でいいので見てみて」と誘う（詳しい物を置く場所が無い時は飛ばしてよい。飛ばした理由を設計シートに書く） |

変化の付け方: 悩み→解決策／「この資料が役に立つ」（公的機関など出典のはっきりした資料）／「この道具が役に立つ」。2行目に、対象の人だけが分かる「あるある」を置くと止まりやすい。

### S2 興味をひく4つの切り口

| 切り口 | 中身 | 注意 |
|---|---|---|
| 目指す姿を見せる | 読者がなりたい状態を、等身大の場面で見せる（お金・時間・暮らし方・不安が消えた状態など） | 書き手の暮らしとして見せる時は実際の事実だけ（盛らない）。読者の理想の場面として描く時は、想定だと分かる書き方（「〜になったら」）にする |
| よくある思い込みを批判する | 界隈でよく言われる方法・考え方を、理由つきで疑う | 人や会社を名指ししない。批判するのは方法と考え方 |
| 常識を壊す | みんなが当然と思っていることの逆を、根拠つきで言う | 根拠の無い逆張りをしない |
| 差を見せる | 過去の自分と今の自分／目指す姿と今の読者 の差を、出来事と感情で見せる | 実績が無い人は、今の弱さと目標の差を実況する形にできる |

### S3 信頼と共感を育てる7つの題材

| 題材 | 中身 |
|---|---|
| 動いている様子 | 行動の量・速さ・徹底ぶりを、口でなく実際の様子で見せる |
| 学び続けている様子 | 本や人から学ぶ、学んだことを試す様子（読者に借金や無理な出費を勧めない） |
| 失敗やトラブル | うまくいかなかった話と、そこから得たこと。最後は前向きな一言で締める |
| 挑戦 | これから始めること、やってみていること |
| 目標 | 目指していること（何度繰り返してもよい。いつも同じ方向を向いている） |
| 再現できること | 特別な条件が無くてもうまくいった例（本人の許可を得た実例だけ） |
| 弱い所を見せる | 苦手なこと・裏側を見せて近さを作る（出来事の事実は盛らない） |

### S4 役に立つ情報の3つの形

| 形 | 中身 |
|---|---|
| まとめ | 手順・一覧・図解。保存されやすい |
| やり方＋考え方 | 読者がやっていることを言い当てる→気づいていない原因を示す→なぜそうなるかを掘る→締めで、読者が試せるやり方を1つ置く |
| やり方＋具体 | 会話の形／AとBの比べ／やり方＋例／良い例と悪い例 |

役に立つ投稿が伸びない時は、投稿の中身より、普段の「興味をひく」投稿が足りていないことが多い。

## 4 長文の型

### X1 出来事から学びを渡す7枠

| 順 | 枠 | 中身 |
|---|---|---|
| 1 | 一文目の見出し | 数字・大きな損・常識と逆・「Aしたいけど B なあなたへ」の呼びかけ・得られること、のどれかを入れる。情報を少し欠けさせて続きを読ませる（嘘にはしない） |
| 2 | 導入 | いつ・どこで・誰と、から書き出し、過去の話だと分かるようにする。序盤ほど具体的に |
| 3 | 出来事 | 会話や頭の中の声を入れて、実際にあったことを描く |
| 4 | 気持ちの動き | 教訓に入る前に、読者が同じ気持ちになるまで書く（ここを飛ばすと説教に聞こえる） |
| 5 | 気づき | 伝えたいことを、はっきり一言で言う |
| 6 | 行動の呼びかけ | 読者にしてほしいことを1つ（反応する→返信する→登録する→感想を書く、の順に深くなる）。書き手への反応を頼む枠 |
| 7 | 前向きな一言 | 前向きに締める（決めゼリフにしない。新しい情報か次の行動で）。書き手の気持ちでなく、読者に向けた一言（次に試せること・同じ立場の人への一言）で書けば、依頼が薄くても記入欄にしなくてよい |

7 の前向きな一言には、読者が自分の仕事や暮らしで次に試せる一歩（誰でも試せる一般的な工夫で、書き手のサービスの手順ではない物）を置いてよい。出力④の差し替え候補に並べる（6 は書き手への反応、7 は読者自身の行動、と分ける）。無名のうちに書き手が何者かを示す1行は、2 導入の頭に置く。気づきの段で一般的な理屈を添えるのは任意。添える時は「ここからは私の経験を離れて、一般によく言われることを書きます」のように、書き手の話と切り離す言葉を入れる（「私の場合に限らず」のようにつなげると、書き手の学びと同じだと読める）。依頼に字数が無い時は、自分が書く枠の数から目標字数を見積もって仮に置く。

書き手の体験で進む型なので、依頼に体験の中身（いつ・何が起きたか・どう感じたか・何を学んだか）が無い時は、2〜5の枠を記入欄にする（仮の例より記入欄を優先する）。5の気づき（書き手が学んだこと）も書き手の経験に当たるので、一言は記入欄にする。一般的な理屈を添える時は、出力④に「書き手の学びと違えば差し替える」と並べる。

組み立ての順: 出来事が起きる→伝えたいことを決める→気持ちを書いて大きくする→出来事と気持ちを教訓へつなぐ理屈を組む。人は気持ちで決めて理屈で納得するので、気持ち→理屈の順に置く。

## 5 運用の原則

- 本数より、力を込めた1本を毎日出す
- 冒頭に目を止める言葉を置く（数字・否定・意外な組み合わせ）。言い切りで書く
- 無名のうちは、投稿の頭で書き手が何者かを1行で示し、役に立つ情報に書き手の実例を混ぜる（情報だけだと、情報に人が付いて書き手には付かない）
- 誰でも知っている話より、その界隈の人だけが分かる「あるある」を入れる
- 長文は途中で飽きさせない。小さな脱線や具体的な場面を散らす
- 1文を長くしすぎない。主語と述語をはっきりさせる
- 「知りたい人は反応して」で隠した情報は、必ず後で出す
- 伸びた投稿は、しばらく空けて言い方を変えて出し直してよい
- ほかの人の投稿を自分の分野に置き換える時は、構造だけを借りて中身と言葉は自分の物にする
- 基本は短文。長文はたまに出すから読まれる。中身の薄い長文を続けると注目が落ちる
- ほとんどの投稿は売上に直結しない。いろいろな話題を出し、反応が大きく取れた話題が出たら、そこに集中する
- 世の中の話題や盛り上がっている分野のうち、自分の強みと重なる物にだけ乗る
- 目指す姿を見せる投稿は、全体の3割くらい（始めたばかりなら半分でもよい）
- 日常の様子（食事・移動・作業）に、伝えたいことを混ぜる
- 勧めることを、書き手自身の行動で見せる
- 「〜しましょう」と命令するより、「あなたは〜に向いている」と適性で伝える
- 特定の立場の人だけに深く刺さる投稿は、その人たちがどんな場面で気持ちが動くかを調べてから書く
- 読者にしてほしい行動（通知の登録・感想・参加）ごとに、それが読者の得になる理由を用意する。頼むだけでは動かない
- ネタは、競合の分析より、書き手自身の行動から拾う
- 流行った施策をすぐ真似しても埋もれる。見せ方・時期・分野をずらす
- わざと炎上させる・挑発して反論させる・名指しで批判する・投稿を消して見逃した人を後悔させる、はしない（`guardrails.md`）
