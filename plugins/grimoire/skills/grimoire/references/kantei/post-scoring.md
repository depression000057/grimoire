# 投稿の自己採点（冒頭10点満点・全体100点満点）

投稿は、書いたら必ず採点してから出す。出してよいのは **冒頭スコア7点以上・全体80点以上** の投稿だけ。足りない投稿は、足りない項目を直して採点し直す（2回直しても届かない投稿は、型ごと作り直す）。

この採点表は、講座運営者が実際の運用で使っている2つの物差しを元に、どの占い・スピの発信者でも使える形に作り直したもの。
- 冒頭スコア: 「断言・情景・わかってくれてる感」の3本柱（合格7点）
- 全体スコア: 投稿の管理画面で使っている7項目・100点（80点以上で「出せる」、64〜79点は手直し）

100点のうち、道具が機械で決めるのは長さ・重複・呼びかけの25点だけ。残りの75点はスキル自身が付ける自己採点で、品質の保証ではなく、直す所を見つけるための目安として使う。利用者にもそう伝える。

## 1. 冒頭スコア（1行目〜2行目・10点満点）

| 柱 | 点 | 基準 |
|---|---|---|
| 断言 | 0〜4 | 1行目の先頭で短く言い切っている＝4／言い切りが後ろにある＝2／説明から入る＝1／言い切りなし＝0 |
| 情景 | 0〜3 | 誰が・何を・どの場面か、読んだ瞬間に映像が浮かぶ＝3／少しぼんやり＝2／「何を」が抜けている＝1 |
| わかってくれてる感 | 0〜3 | 読者が薄々感じているのに言葉にできていないことを言い当てている＝3／共感どまり＝2／一般論＝1 |

言い切りは「未来の断定」とは別物。「はっきり言いますが、〇〇は△△じゃないです」のように、見立て（物の見方）を言い切る。未来や効果は言い切らない（`safety.md`）。

冒頭で落ちやすい形:
- 挨拶・自己紹介・肩書きから入る（読者にとって他人事になる）
- 主語が「私」（読者か、読者の身近な人を主語にする）
- 説明なしの専門用語（チャクラ・マヤ暦・ライフパスなど。使うなら同じ行で意味を言う）
- 対象をしぼりすぎる（「既婚で50代で〜の人」のように条件を重ねる）
- 抽象的な言葉だけ（魂・波動・流れ）で、場面が無い

## 2. 全体スコア（100点満点）

| 項目 | 配点 | 満点の条件 | 誰が採点するか |
|---|---|---|---|
| 冒頭 | 20 | 冒頭スコア9〜10＝20／7〜8＝14／5〜6＝9／4以下＝4 | 道具が冒頭スコアから換算 |
| 具体性 | 20 | 場面・物・数字・体の感覚など、読者が思い浮かべられる細部が2つ以上＝20／1つ＝12／無い＝4 | スキル |
| 一次性 | 20 | 発信者本人にしか言えない体験・見立て・鑑定の現場の話が入っている＝20／本人の見立てはあるが体験が無い＝14／誰でも言える内容＝5 | スキル |
| 読者とのつながり | 15 | 読者に直接呼びかけ、読者の「今」に戻して終わる＝15／呼びかけはある＝11／一般論で終わる＝3 | スキル |
| 長さ | 10 | 140〜360字＝10／100〜139字・361〜460字＝7／60〜99字・461〜520字＝4／それ以外＝1 | 道具 |
| 重複 | 10 | 過去の投稿・同じ回の他の投稿と似ていない（近さ0.0＝10点、0.72以上は書き直し） | 道具 |
| 呼びかけ | 5 | 本文を読ませたあとに「コメントで」「プロフィールから」などの次の一歩が1つある＝5／無い＝4／次の一歩から始まっている＝2 | 道具 |

- 点は表の段階の数字だけを使う（具体性は20・12・4、一次性は20・14・5、読者とのつながりは15・11・3）。間の点は付けない。道具も段階以外の点を受け付けない
- 「一次性」は、利用者の設定（経歴・体験・鑑定の現場）に書かれた事実からしか取らない。設定にある経験を、利用者が言っていない具体的な出来事（「あの日、〇〇さんに言われて」など）に膨らませない。体験が設定に無い時は、作らずに「（ここにあなたの体験）」と空けて、その投稿は一次性14点で採点する

## 3. 道具で集計する

投稿を `ティルナノーグ_制作物/鑑定/` に保存し、1本ずつ本文の下に採点の行を書く。

```
【1】型：日常のしぐさ／テーマ：金運
（本文）
採点: フック=8 具体=20 一次=14 読者=15
```

- フック＝冒頭スコア（10点満点）、具体・一次・読者＝全体スコアのスキル採点分（冒頭20点は道具がフックの点から換算する）
- 集計: `python3 .grimoire/scripts/kantei/check_post.py <投稿ファイル> --past ティルナノーグ_マイナレッジ/鑑定/過去の投稿.md --past ティルナノーグ_マイナレッジ/鑑定/集めた投稿.md`（無いファイルは付けなくてよい。付けたのに見つからない時は道具が止まって知らせる）
- `集めた投稿.md` はリサーチで貼られた他人の投稿。これと近い投稿（近さ0.72以上）は、言い回しを借りているので書き直す
- 道具が冒頭20点の換算と、長さ・重複・呼びかけを計算して合計し、「合格／手直し／書き直し」を出す。安全ルールの一部の言葉、日付がずれる言葉（明日・今週・曜日）、冒頭で落ちやすい形も拾う
- Python が動かない時は、表の基準で長さ・呼びかけを手で数え、重複は「前の投稿と1行目・結びが同じでないか」を見て採点し、「手計算です」と添える

## 4. 利用者に見せる形

投稿本文のすぐ下に、1行で見せる。

```
冒頭 8/10 ・ 全体 86/100（冒頭14・具体20・一次14・読者15・長さ10・重複8・呼びかけ5）→ 合格
```

甘く採点しない。迷ったら低い方の点を付ける。
