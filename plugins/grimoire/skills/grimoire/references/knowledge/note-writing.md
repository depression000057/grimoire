# note の設計と執筆

このファイルの役割: note 記事（無料・有料・LINE 登録へつなぐ記事）を、設計から通し書きまで迷わず作るための決まりと手順をまとめたもの。

いつ読むか: 「2 note」モードで、記事の設計に入る前（§1〜§4）、タイトルと冒頭を出す前（§5〜§6）、本文を通しで書く直前（§7〜§9）。書き終えた後の点検は `references/quality/` の各ファイルに進む。

目次:

- §1 note という場所の仕組み（冒頭の見え方・有料ライン・字数・価格の考え方）
- §2 記事の骨格の選び方と、章として成立する条件
- §3 有料ラインの置き方
- §4 CTA の2段（本編途中の軽い CTA・末尾の本 CTA）
- §5 タイトル（10〜20案を出して選ぶ手順・散らし方・採点）
- §6 冒頭300字（1行目の要件・距離感の違う2案）
- §7 章の1行目の型と、連発の上限
- §8 心理効果の使い方と倫理
- §9 通しで書く時の決まり

このファイルで使う言葉:

| 言葉 | 意味 |
|---|---|
| 読者1人（N1） | `00_わたしの設定.md` に書いた「この記事を一番読んでほしい1人」。平均的な読者像ではなく、年代・状況・口にする言葉・毎日触る物まで決まった1人 |
| センターピン | 読者が本当に欲しい場面→そこへ行けずに止まっている壁→この note で越えられる理由、を1行にしたもの。設定ファイルにある |
| 有料ライン | note の記事で「ここから先はお金を払った人だけが読める」という境目 |
| CTA | 読者に次の行動をお願いする文。LINE 登録・購入・フォローなど。英語の Call To Action の略 |
| 無料部分・有料本編 | 有料ラインより上（誰でも読める）と下（買った人だけ読める） |

## §1 note という場所の仕組み

ここに書く note の仕様は、note 公式ヘルプセンターの記述で確かめられる範囲だけに絞った。仕様は変わることがあるので、公開前に下の「確かめ先」で見直す。

### 1-1 タイトルと冒頭の見え方

| 事実（公式ヘルプの記述） | だから書く時にこうする |
|---|---|
| タイトルは長すぎると一覧や X で「…」と省略される。推奨は15〜25字程度 | タイトル案には毎回字数を書く。25字を超える案は、後半が切れても意味が通るように主張を前半に置く（なぜ: 切れた後半に主張があると、一覧で何の記事か分からない） |
| タイトルに【】や●などの記号を入れて無理に目立たせるのは逆効果、と公式が書いている | 記号で飾らず、言葉で止める（なぜ: 公式が逆効果と明言しているものを、わざわざ使う理由がない） |
| 冒頭には要点をまとめた短いリード文を置くのが推奨。目安は50字程度で、X でシェアされても省略されない長さ | 本文の1行目〜3行目だけで「何の記事か」が分かるように書く（§6）。なぜ: 一覧・シェア・埋め込みで見えるのは冒頭の一部だけだから |
| 一覧やタイムラインで本文の何字目までが見えるかは、公式に数字が無い | 「何字まで見える」と決めつけず、1行目だけで意味が通る形にしておく（なぜ: 数字が無い以上、一番短く切られた時に備えるしかない） |
| 長い段落は5行ほどで改行・改段落するのが推奨（PC なら3〜4行） | 1段落は1つの話にし、スマホで5行を超えたら段落を分ける（なぜ: 画面いっぱいの文字の塊は、読む前に閉じられる） |
| 見出しは「大見出し」「小見出し」の2段。見出しがあれば目次を自動で作れる | 見出しは §9 の形で付け、長い記事は目次を入れる（なぜ: 有料本編で読者が読みたい章へ飛べると、買った後の満足が上がる） |
| 見出し画像の有無でページビューやスキの数に数十パーセントの差がある、と公式が書いている。推奨サイズは 1280×670 | 見出し画像は必ず付ける（なぜ: 公式が数字つきで推奨している数少ない項目だから） |
| ハッシュタグは5つぐらいが効果的 | 記事の中身を表す語を5つ前後付ける |

### 1-2 有料ラインの仕組み

| 事実（公式ヘルプの記述） | だから書く時にこうする |
|---|---|
| 有料ラインは段落と段落の間にしか置けない（段落は Enter 2回、改行は Enter 1回） | 原稿では有料ラインの位置に区切り行を1行置き、その前後を段落で分けておく（§9） |
| 自分のアカウントでログインしたまま自分の記事を開くと、全文が見えて購入ボタンが出ない | 公開後は、ログアウトした状態かシークレットモードで開いて、有料ラインの位置を確かめる |
| 有料部分に入れた画像はサムネイル（一覧に出る小さな画像）にならない | 見せたい画像は見出し画像にするか、無料部分に置く |
| 購入した人が読むのは、いつでも最新版。値上げ・値下げしても、買った人は全部読める | 記事を後から書き足すと、前に買った人にも届く。売れ続ける記事（エバー）にする時は、中身を足していく前提で章を組む（なぜ: 更新が全購入者の得になり、書き足す理由が作りやすい） |
| 有料記事は「返金申請を受け付ける」が初期設定で、購入から24時間以内の申請を note が審査する | 無料部分で約束したことを本編で必ず果たす（なぜ: 約束と中身がずれると、返金と低い評価の両方につながる） |
| はじめて有料記事を公開する時は「本人情報の登録」が要る。18歳未満は保護者の同意が要る | 公開予定日より前に登録を済ませておく |
| 有料記事の値段は、公開した後でも編集画面から変えられる。値上げ・値下げの前に買った人に、差額の支払いや返金は無い | 値段を試す時は、1つずつ変えて数字を比べる（値段・タイトル・無料部分を同時に変えると、どれが効いたか分からなくなるため） |
| 買ってくれた人に、ダッシュボードの販売履歴からお礼のメッセージを送れる（2,000字まで・1人に1回・メールで届く） | 送るなら、読み始める順番や、つまずいた時に読む章を1つ伝える。追加の売り込みはしない |
| 有料マガジンは、作った後で値段は変えられるが、有料と無料は切り替えられない | まとめ売りを始める前に、有料で続けるかを決めておく |
| 有料ラインより上に何をどれだけ置くべきか、本文の字数の上限、有料記事の最低字数は、どれも公式に記載が無い | 字数と配分は §2-4 の目安で自分で決める |

### 1-3 字数の考え方

- 字数は中身で決める。目標字数を先に決めても、中身が足りなければ短くし、引き延ばさない（なぜ: 水増しした段落は読者にすぐ見抜かれ、有料部分の信用ごと下がる）
- 目標字数を決めたら、書き上がりは目標の±15%に収める（なぜ: これを大きく外れる時は、設計の段階で章の数か中身の量を見誤っている）
- 超えた時は、同じことの言い直しや重なった段落を「文ごと」落とす。1文の中を削って縮めない（なぜ: 文の中を削ると、主語や目的語が抜けて意味の取れない文ができる）

### 1-4 価格の考え方

公式で決まっていること:

| 項目 | 内容 |
|---|---|
| 付けられる価格 | 通常の会員は1記事100円〜50,000円。有料会員（note プレミアム・月額500円）と note pro は上限100,000円 |
| 引かれる手数料 | 支払い方法ごとの事務手数料（カード払いなら5%）と、そこから残った額への利用料（有料記事は10%）。売上を振り込むたびに振込手数料270円 |
| 公式の計算例 | 1,000円の記事がカード払いで1本売れると、事務手数料50円＋利用料95円が引かれて855円。振り込む時にさらに270円が引かれる |

価格を決める時の決まり:

1. **いくらが売れるかの数字は、このファイルには置かない**。価格帯を決める材料は、講座ナレッジのカードと、自分の実績カード（`40_実績/`）の数字を使う（なぜ: 裏付けの無い「売れる価格帯」は、あなたのジャンルと読者に合う保証が無い）
2. **価格の理由は、無料部分の終わり（有料ラインの直前）に書く**。何が手に入り、なぜこの値段なのかを、読者が自分に置き換えられる言葉で書く（なぜ: 値段だけ見せられると、読者は高いか安いかしか判断できない）
3. **根拠の無い金額は断定せず、幅で書く**。「〜にかかる費用は数千円から数万円」のように書き、確かめた数字だけを一点で書く（なぜ: 出典の無い一点の金額は、外れた時にそのまま嘘になる）
4. **手取り・手数料・控除の数字は無料部分に置かない**。無料部分は「入ってくるお金」の数字で語り、引かれる話は有料本編で扱う（なぜ: 無料部分は読者の「やってみたい」が上がる場所で、差し引きの数字はそれを下げる。数字は消さず、置き場所を変える）
5. 誇大な収益表現・偽の締切・作り話の実績は、価格の説明でも使わない（`references/quality/absolute-rules.md`）

## §2 記事の骨格の選び方と、章として成立する条件

### 2-1 書く前に決める4つ

設計に入る前に、次の4つを設計メモに書く。どれか1つでも空欄なら、本文を書き始めない（なぜ: この4つが無いまま書くと、誰にでも当てはまる文になり、読者1人に届かない）。

1. **センターピン**: 設定ファイルの1行をそのまま写す
2. **読みたいはずなのに読まれない理由を3つ**: 例として「入口が自分の話に見えない」「どこかで見た話に見える」「読者の考え方とぶつかる」。この3つを先に書いておくと、冒頭とタイトルで潰すべき壁が分かる（なぜ: 読者が欲しい中身でも、入口でこの3つに引っかかると開かれない）
3. **例えの出どころを3つ**: 読者1人が毎日手で触る物・家事・移動の場面を3つ挙げる。例えはこの3つからしか作らない（なぜ: 例えは正しくても、読者が触らない物で作ると意味を追う間に自分の話でなくなる）
4. **この記事のしくみ（なぜそうなるか）**: 記事が教えるやり方が複数あるなら、「Aをすると Bが起きる。Bの後に C」の1本の因果で並べる。「運がよくなる」のような結果は因果の最後に置く（なぜ: やり方がバラバラに並ぶと、読者はどれからやればいいか分からない）

### 2-2 無料部分の骨格（読者を「買う」まで連れていく順番）

無料部分は、次の役割を上から順に置く。役割の名前は本文に出さない。

| 順 | 役割 | 中身 | なぜこの位置か |
|---|---|---|---|
| 1 | タイトル | §5 | 一覧で指を止める |
| 2 | 冒頭 | 主張と理由を3行で。§6 | タイトルの期待を受け止め、読む理由を渡す |
| 3 | 心当たり | 読者1人の生活の場面を、具体的に言い当てる | 「自分のことだ」と思えないと、その先の説明を読まない |
| 4 | 免罪 | 今うまくいっていないのは、読者の性格や努力不足のせいではない、と伝える | 責められていると感じた読者は、防御して読み飛ばす |
| 5 | しくみ | なぜそうなっているのか、どこを変えれば変わるのかを説明する | ここが「買う理由」の土台になる。しくみが分かると、やり方にお金を払う意味が出る |
| 6 | 無料の1手 | 読者がその場でできることを1つだけ、番号を付けて渡す | 小さく試した読者は、続き（本編）の中身を信じやすくなる。2つ以上渡すと、どれもやらずに終わる |
| 7 | 本編の中身 | 有料本編の章を「手に入る状態」の言葉で並べる | 何にお金を払うのかが見えないと、買う判断ができない |
| 8 | 向いていない人・よくある不安 | 誰に向かないか、買う前によく聞かれる不安とその答え | 合わない人が買って不満を持つのを防ぎ、合う人の最後のためらいを消す |
| 9 | 価格の理由 | §1-4 の2 | 値段の意味が分かってから、有料ラインに来てもらう |
| 10 | 追伸 | 冒頭で約束したことを1つ思い出させる | 長い無料部分の後で、読み始めた理由に戻す |

無料部分で守ること:

- **「買う理由」は、違いの正体を一言で言い当てる**。「Aは消える、Bは残る」のような、事実として成り立たない対比を使わない。読者が「でもAも残るよね」と反論できる対比は、買う理由を弱める（なぜ: 反論の余地がある対比は、読者に疑う理由を渡してしまう）
- **通説をひっくり返す時は、読者自身の行動で確かめさせる**。「〜は要りません」と言い切ったら、「あなた自身、この1か月で〜したことがありますか」のように読者の記憶で確かめてもらい、最後に違いの正体を一言で置く（なぜ: 否定と説明だけだと、読者は「そうかもね」で止まる）
- **読者の頭の中への操作を予告しない**。「思い込みを外しておきます」「先に答えておきます」「冒頭の話に戻ります」は書き手の作業予告で、会話では言わない。中身をそのまま置く（なぜ: 予告の文は読者に何も渡さず、読む手間だけ増やす）
- **役割を飛ばす・置き換える時は、理由を設計表に1行書く**（`2_note.md` §3）。10の役割は全部そろわなくてよいが、黙って抜けると「なぜ買うのか」の説明に穴が開く（なぜ: 理由を書いておくと、売れなかった時に、抜いた役割が原因かどうかを後から確かめられる）

**実績や証拠がまだ無い時の置き換え**: 無料部分には、実績の数字・お客様の声・権威を置きたくなる。まだそれが無い時は、作り話で埋めず、次のように置き換える（`references/quality/absolute-rules.md` の決まり1〜2）。

| 本来置きたい物 | 代わりに置く物 | 理由 |
|---|---|---|
| 実績の数字・ビフォーアフター | 自分が実際に試した事実（期間と、何をしたか）。それも無ければ、しくみの説明（「〜と言われています」と留保をつける） | 架空の実績は、ばれた時に記事ごと信用を失う |
| お客様の声・推薦 | 書かない。代わりに「読者が自分で確かめる方法」を置く（例: 毎朝、台所に立つまでの分数を紙に書いて比べる） | 声の作り話は禁止。自分で確かめた読者は、声よりも強く信じる |
| 権威（資格・人数・メディア） | 「なぜ私が話せるのか」を、調べた資料と、しくみの理解で書く | 無い資格・人数は書かない |
| 自己紹介のストーリー | 本人に一言もらう枠を残す。事実が無ければその節ごと削る | 本人のプロフィールを作らない |
| 特典・保証・割引 | 実物・実際の設定があるものだけ | 無いものを約束しない |
| このままだとどうなるか（悪い未来） | 読者の生活の場面で書く（毎晩の献立で10分迷い続ける、など）。病名や破産・孤独で脅さない | 恐怖で動かすと、買った後の不満と返金につながる |

### 2-3 有料本編の組み立て（読者に渡す物で選ぶ）

有料本編は、読者の気持ちが1段進むごとに章を切る（`2_note.md` §3）。その並べ方は、この記事で読者に何を渡すかで決める。

| 渡す物 | 章の並べ方 | 合う時 | 合わない時 |
|---|---|---|---|
| やり方 | 今のやり方のどこで止まっているか → なぜ止まるのか → 新しいやり方（手順ごとに章） → つまずいた時にやること → 続け方 | 本人が実際に続けているやり方を、読者に真似してもらう時 | やり方がまだ本人の中で固まっていない時 |
| 考え方 | 一番言いたいことを言い切る → そう言える本人の事実 → 毎日の中で具体的にどうするか → よく返ってくる反論への答え → 最初の一歩 | 読者の当たり前を1つ変えれば、あとは読者が自分で動ける時 | 言い切りを支える本人の事実が無い時 |
| 体験 | 何が起きたか → どこで気持ちや状況が変わったか → 何をしたか → その後どうなったか → 読者が自分の場合に使える判断 | 本人に、読者と同じ悩みを抜けた実際の体験がある時 | 実際の体験が無い時（作らない） |
| 選び方 | 選ぶ時の物差し → 候補を1つずつ同じ物差しで → 読者の状況ごとのおすすめ | 読者が、いくつかの方法や道具から選べずに止まっている時 | 物差しをそろえられない時 |

- 1本の記事で渡す物は1つに決める。2つ以上を混ぜる時は、主に渡す物の並べ方を土台にして、もう1つを1章だけ足す（なぜ: 並べ方が混ざると、読者は今どこにいるのか分からなくなる）
- 体験の章は、実際にあった順に書く。本人がしていないこと・起きていないことを足さない。読者や過去の自分を責めない。うまくいった結果を奇跡のように書かない。最後の判断は、説教にせず、読者が自分に当てはめられる形で渡す

### 2-4 字数の配り方

字数は中身から決める（§1-3）。そのうえで、次の3つだけ守る。

1. **無料部分は、買う判断に要る分だけにする**。§2-2 の役割がそろえば、それ以上は延ばさない（なぜ: 無料部分が長いと、読者は有料ラインに着く前に疲れる。短すぎると、なぜ買うのかが育たない）
2. **一番字数を使うのは、読者が実際に手を動かす章にする**。原因やしくみの説明の章が、やり方の章より長くなったら組み直す（なぜ: お金を払った読者が一番欲しいのは、自分がやることの中身だから）
3. **1章は、読者が一息で読み切れる長さにする**。短すぎる章は前後とまとめ、長すぎる章は読者の気持ちが進む所で2つに分ける（なぜ: 短すぎる章は中身が薄く見え、長すぎる章は途中で何の章か分からなくなる）

設計表を作ったら、章ごとの字数を並べて、この3つに合っているかを見る。

### 2-5 記事の部位ごとに、読者はどんな状態か

| 部位 | 読者の状態 | その部位の仕事 |
|---|---|---|
| タイトル・見出し画像 | まだ悩みをはっきり自覚していない人も含む | スクロールを止め、自分の話かもと思わせる |
| 冒頭 | 開いたが、読むか迷っている | 自分の状態を扱う記事だと分からせる |
| 前半 | 自分の悩みを別の原因のせいだと思っている | 悩みを代わりに言葉にし、思い込んでいる原因を揺らす |
| 中盤 | 本当の原因を知りたい | 本当の原因を示し、整理する |
| 後半 | やり方を知りたい | 具体の手順と、最初の1歩を渡す |
| CTA の直前 | 動くか迷っている | 判断の材料と、不安への答えを渡す |
| CTA | 動くと決めかけている | やることを1つに絞り、手間を最小にする |

### 2-6 章として成立する条件（全部満たす）

1. **章の1行目が主張か具体で始まる**（§7）。なぜ: 前置きで始まる章は、読者が「この章は何の話か」を探す手間を負う
2. **1章に言いたいことは1つ**。章の見出しは、読み終えた読者が「手に入る状態」で書く（例の形: 「〜について」で止めず、「〜を自分で決められる」のように読後にできることまで書く）。なぜ: 見出しが状態で書かれていると、目次だけで買った価値が見える
3. **章の終わりは、次の章へ渡す1文か、読者がその場でやる1手で終える**。要約・教訓・決めゼリフで閉じない。なぜ: 決めゼリフで閉じると余韻は出ても、次へ読み進める理由が消える
4. **章の中に、読者の疑問を先回りして拾う文が1つ以上ある**。拾う疑問は次の5種類のどれか: 「それ本当？」「自分にもできる？」「なぜ？」「で、どうすれば？」「それで何が変わる？」。拾う時は、読者の言葉で代わりに言ってから答える。なぜ: 読者が心の中で出した疑問に答えない章は、そこで読むのを止められる
5. **章のどこかに具体（場面・数字・実物の名前）が1つ以上ある**。固有名詞を消したら誰にでも書ける章にしない。なぜ: 具体が1つも無い章は、ほかの記事でも読める章になる
6. **同じ動作（自己診断・チェック・判定）を3章続けない**。章ごとに「分かる」「比べる」「やる」など役割を変える。なぜ: 同じ作業が続くと、読者は作業に飽きて本編を閉じる

### 2-7 段落の決まり

1. 1段落に言いたいことは1つ（なぜ: 原因とやり方と事例が1段落に混ざると、どれが大事か分からない）
2. 段落の1行目は主張か具体で始める。接続詞だけで始めない（なぜ: 1行目で段落の中身が分かれば、読者は拾い読みでも迷わない）
3. 抽象→具体→実物（場面・数字）の3段で書く（なぜ: 抽象だけだと納得せず、実物だけだと何の話か分からない）
4. 箇条書きだけの段落を続けない。箇条書きは具体を短くまとめる所だけに使い、項目どうしの因果や順番は地の文でつなぐ（なぜ: 抽象語を並べた箇条書きは、説明を放棄したように見える）

### 2-8 設計メモの形

設計メモは次の形で作る。本文より先に作り、「2 note」モードの確認でこの表を見せる。

| 章 | 見出し（手に入る状態で） | この章が答える読者の疑問 | 1行目の入口（§7） | 目安字数 | 読者の気持ち（始め→終わり） | 章末の渡し方 |
|---|---|---|---|---|---|---|
| 0 | | | | | | |
| 1 | | | | | | |

表の下に、次の5行を書く: 字数の合計（目標の±15%か）／有料ラインの位置（無料部分のどの役割の直後か）／軽い CTA の位置と中身／本 CTA の中身／心理効果の配置予定（§8・3〜5個）。

## §3 有料ラインの置き方

1. **有料ラインは、無料部分の10の役割（§2-2）を置き終えた後に引く**。価格の理由と追伸の後が基本（なぜ: 買う理由・不安への答え・値段の意味がそろう前に線を引くと、読者は判断できないまま止まる）
2. **有料ラインの直前まで読んだ読者が「なぜ買うのか」を一言で言えるか、書いた後に確かめる**。言えない時は、しくみ（§2-2 の5）か本編の中身（同7）が弱い（なぜ: 一言で言えない理由では、読者は財布を開かない）
3. **有料ラインのすぐ近くに「今すぐ」「限定」「残り」を置かない**（なぜ: 線の直前でせかされると、読者は中身ではなく売り込みを読んだと感じる。本当に期限や数の制限がある時だけ、事実として CTA で伝える）
4. **無料部分で出した数字と、有料本編の数字をそろえる**。「10の質問」と書いたら本編の質問は10個、「3日ほどで戻る」と書いたら本編でも同じ3日で扱う（なぜ: 読者は無料部分で読んだ数字を覚えていて、ずれた所で約束を疑う）
5. **有料本編の最初の章は、無料部分とのつながりを1〜2文で作ってから本題に入る**。無料部分で扱った現象を本編で深める時は、「無料部分だけ読んだ人はこうなる／本編までやった人はこうなる」の違いを先に置く（なぜ: 買った直後の読者は、無料部分の続きとして読み始めるから）
6. **原稿では区切り行 `---- ここから有料 ----` を1行だけ置く**。note に貼る時にこの行は消し、note の画面で同じ位置に有料ラインを設定する（§9）。なぜ: 区切り行が決まった形なら、道具で自動的に無料部分と有料部分に分けられる
7. **無料で読み切る記事（LINE 登録が目的の記事など）では有料ラインを置かない**。代わりに、本 CTA（§4）を記事の終わりに1つ置く

## §4 CTA の2段

CTA は「本編途中の軽い CTA」と「末尾の本 CTA」の2段で置くのが基本。

| | 軽い CTA | 本 CTA |
|---|---|---|
| 位置 | 本編の途中、章の終わり。1か所以上 | 記事の終わり。1か所 |
| 中身 | 読むのを止めずにできる1つの動作（保存・スキ・短いコメント・「続きは本編で」） | 得られるもの・条件・行き先（LINE・購入・フォロー）をはっきり書いた1つの動作 |
| なぜ | 読んでいる途中で小さく動いた読者は、最後の大きな動作にも進みやすい。読む流れを切る大きなお願いは、途中では逆効果 | 本文で根拠を渡し終えた場所でだけ、大きなお願いが自然になる |

CTA の決まり:

1. **本 CTA は、本文で作った「次の壁」から飛ばない**。本文の最後に読者が感じている「でも、ここから先は？」に答える行き先を案内する（なぜ: 本文と関係の無いお願いは、読者に売り込みとして読まれる）
2. **強さは3段階で考え、1記事で上げるのは1段まで**。提案（〜してみてください）＜案内（〜はこちらです）＜指示（〜を1つだけやってください）。本文で積み上げた納得より強くしない（なぜ: 納得より強いお願いは、読者を引かせる）
3. **CTA は重なりを含めて1記事3〜4回まで**。同じお願いを続けて並べない（なぜ: 同じお願いの連打は、書き手が焦っているように見える）
4. **本 CTA では、読者がやることを一言で言えるようにする**。書いた後に「末尾を読んだ読者は、何をすればいいか一言で言えるか」を確かめる（なぜ: 行き先が2つ以上あると、読者はどちらも選ばない）
5. **「今夜」のように読む時刻を決めつける言葉を使わない**。「今日の夜」「今日寝る前に」のように、いつ読んでも成り立つ言い方にする（なぜ: note は公開してからずっと読まれ、朝や昼に読む人もいる。時刻を決めつけた CTA は、合わない時刻に読んだ人を置いていく）
6. **偽の締切・作った残り数は使わない**（`references/quality/absolute-rules.md`）

## §5 タイトル

### 5-1 タイトルが満たす条件

1. 一覧で指を止める（なぜ: 開かれない記事は、中身がどれほど良くても読まれない）
2. 中身の約束になっている。タイトルで期待させたことを、冒頭と本編で必ず受け止める（なぜ: 約束と中身がずれると、冒頭で閉じられ、買った後は不満になる）
3. 25字前後に収める。長い案は主張を前半に置く（§1-1）
4. 日本語として自然で、読んだ瞬間に意味が分かる。短くするために造語や省略を作らない（なぜ: タイトルで一度つまずいた読者は、開かずに次へ行く）

### 5-2 10〜20案を出して選ぶ手順

1. **記事の型を決める**（5-5 の表から1つか2つ）。なぜ: 型が決まると、タイトルが約束する中身の形がぶれない
2. **入口を散らして10〜20案出す**（5-3）。1案ごとに、テーマ・読者1人・具体の場面・数字を当てはめた完成した文で書く。空欄のひな形（「〇〇は△△じゃない」）のまま出さない（なぜ: ひな形のままでは、読者の目にどう見えるかを比べられない）
3. **1案ごとに字数・入口・型を書く**（5-7 の表）
4. **3本柱で採点する**（5-4）
5. **よくある失敗5つ（5-6）に当たる案を外す**
6. **残った案から、読者1人の顔を思い浮かべて上位3〜5案に絞る**。点数は並べ替えの手がかりで、最後は「この1人がスクロール中にこれを見たら止まるか」で選ぶ（なぜ: 点数は形を測るだけで、その読者に刺さるかまでは測れない）
7. **選んだ案と、選んだ理由を1行残す**。選ばなかった案も捨てずに残す（なぜ: 公開後の数字と突き合わせると、どの入口でこの読者の指が止まったかが分かり、次のカードになる）

### 5-3 入口の散らし方

入口とは「何で読者の指を止めるか」の種類。講座の運営者のアカウントで「強い冒頭」と判断された実例から取り出した5種類を使う。

| 入口 | 形 | 実際に使われた例（講座の運営者のアカウント） |
|---|---|---|
| A 言い切り | 本質を一言で言い切る | 「はっきり言いますが、優柔不断は欠点じゃないです」 |
| B 打ち明け | 普段は言わない場所の話だと示す | 「これあんまり言われないんですが、〜」 |
| C 告白と気づき | 書き手が経験から気づいたことを打ち明ける | 「正直に言うと、長く人を見てきて、相性で一番大事なのは性格じゃないと気づきました」 |
| D 場面の言い当て | 読者の生活の一場面をそのまま言い当てる | 「初対面はうまく話せないのに、心を許した相手にはびっくりするほど甘えてしまう」 |
| E 寄り添いと問い直し | 読者が自分に言い聞かせていることを代わりに言い、見方を問い直す | 「まだ大丈夫、まだいける。そう言い聞かせて無理を重ねていく。頑張り屋さんほど休んでいい合図を見落とします」 |

散らし方の決まり:

- 10案なら5種類すべてを使う。20案でも1種類に5案以上偏らせない（なぜ: 同じ入口ばかりだと、比べているつもりで同じ案を並べていることになる）
- 並べる時、同じ入口を3案続けない（なぜ: 続けて並べると、どの案も同じに見えて選べなくなる）
- B の「普段は言わない場所」は、本当に価値のある場所に限る（例の形: 「有料の相談でしか話さないんですが」）。どこでも言っている話に使わない（なぜ: 打ち明けが嘘だと、読者は一度で気づく）
- 読者の状態で入口の相性が変わる。悩みにまだ名前が付いていない読者には D・E、やり方を探している読者には A・C が合いやすい。迷ったら両方から出す（なぜ: 自覚していない悩みに言い切りをぶつけても、自分の話と思われない）

### 5-4 採点の観点（3本柱・10点）

| 柱 | 見る所 | 点 |
|---|---|---|
| 柱1 言い切り | 強い言い切りが先頭にあるか | 先頭で言い切る＝4／言い切りが後ろ＝2／説明から入る＝1／言い切り無し＝0 |
| 柱2 場面 | 誰が・何を・どんな場面で、が省かれず浮かぶか | 3つとも具体＝3／やや曖昧＝2／目的語が抜けて説明不足＝1 |
| 柱3 わかってくれてる感 | 読者が薄々感じているのに言葉にできていない本音を言い当てているか | 言い当てている＝3／共感止まり＝2／一般論＝1 |

- 7点以上を候補に残す。9〜10点はそのまま出せる強さ
- 柱3は機械的に付けられない。設定ファイルの「読者1人が口にする言葉」と照らし、なぜその点かを1行書く（なぜ: 柱3こそ、その読者を知っている人にしか付けられない点だから）
- 3本の柱のどれか1本でも欠けると弱く見える。点が足りない案は、欠けた柱を足して書き直すか外す

採点で直した例（講座の運営者のアカウント）:

- 柱1が弱い: 「自分にはこれといった強みがない。そう思っていることはありませんか」→「自分には、これといった強みがない。そう思ってる方に、朗報です」
- 柱3を足す: 「人といたあとに、なぜかどっと疲れる」→「人といたあとに、なぜかどっと疲れる。これ、結構多くの人に当てはまるんですけど、体力の問題じゃないんです」

### 5-5 記事の型（タイトルが約束する中身の形）

| 型 | 使う時 | 避ける時 |
|---|---|---|
| 完全攻略 | 1つのテーマを入口から完了まで体系立てて扱う | 範囲が狭く、答えが1つで終わる |
| 手順 | 初心者が順番どおりにやればできる | 分かれ道が多い |
| 秘訣の公開 | 自分の体験・検証から得た、当たり前でない知見を出す | 根拠になる体験・検証が無い |
| 比較 | 複数の選択肢を同じ基準で選び分ける | 比べる基準がそろわない |
| 失敗を避ける | 前もって確かめられる危険と、避け方を示す | 不安をあおるだけで避け方を示せない |
| 体験記 | 書き手の実際の体験と、変化のしくみを書く | 作った話・まだ起きていない成果に頼る |
| チェックリスト | やる前・やった後に判定できる項目を並べる | 判定の基準があいまいで、確かめても結論が変わらない |
| 質問と答え | 実際に何度も聞かれる疑問にまとめて答える | 質問を作る |
| 総まとめ | 十分な一次情報を整理して、テーマ全体の結論を示す | 素材が薄く、網羅に見せるために水増しする |
| 逆説 | 通説と違う結論を、しくみと証拠で示す | 根拠の無い逆張りになる |
| 共感と解決 | 実際のつまずきと、抜け出すための条件を扱う | 葛藤・解決・成果のどれかを作る |

### 5-6 よくある失敗5つ（当たる案は外す）

1. 抽象語だけ、または目的語が無く、何を・どうするのかが分からない。具体にするために、実在しない数字や権威を足さない（なぜ: 作った数字は、読者に確かめられた瞬間に記事全体の信用を落とす）
2. 説明や定義の宣言から入り、読者への主張が無い（なぜ: 「〜について解説します」は、読む理由を渡していない）
3. 読者1人の条件を重ねすぎて、当てはまる人まで入口で追い出す（なぜ: 条件が3つ重なると、2つ当てはまる人も自分の話と思わない）
4. 同じ語・同じ主張を、短い前半と長い後半で繰り返す（なぜ: 同じことを2回言うタイトルは、中身も薄いと思われる）
5. 短さを優先して、不自然な造語や省略を作る（なぜ: タイトルの造語は、まだ説明していない言葉を読者にぶつけることになる）

### 5-7 記録の形

| 番号 | 案 | 字数 | 入口（A〜E） | 型 | 柱1 | 柱2 | 柱3 | 合計 | 柱3の理由 | 選んだか・理由 |
|---|---|---|---|---|---|---|---|---|---|---|

## §6 冒頭300字

### 6-1 1行目の要件（全部満たす）

1. **主張がある**。説明・前置き・問いかけだけで終わらない（なぜ: 1行目に主張が無いと、読者は2行目を読む理由を持たない）
2. **読者が場面で「自分のことだ」と分かる**。誰が・どこで・何をしている時の話かが浮かぶ（なぜ: 場面が浮かばない1行目は、自分以外の誰かの話に見える）
3. **タイトルの期待を3秒で受け止める**。タイトルが「〜の順番」なら、1行目も順番の話をする（なぜ: タイトルと1行目が別の話だと、読者は開いた瞬間に「違った」と閉じる）
4. **40字以内**。50字を超えたら2つに分ける（なぜ: スマホで2行に折り返した1行目は、主張が目に入る前に流される）
5. **その場面の人が、声に出して言う言葉である**（なぜ: 紙の上でしか成り立たない言い回しは、読者を一拍止め、その一拍で「作られた文だ」と感じさせる）
6. **接続詞だけで始めない**（なぜ: 「さて」「では」で始まる1行目は、前に何かがあった前提になり、冒頭として成り立たない）

### 6-2 冒頭3行で成り立たせる

1行目で主張し、2〜3行目で理由を言う。この3行だけが切り取られて表示されても意味が通るように書く（なぜ: 一覧・シェア・埋め込みで読まれるのは冒頭の一部だけで、そこで読むかどうかが決まる）。

### 6-3 冒頭で読者を離れさせない

- **固い言い回しで入らない**。「結論から申し上げると」のような改まった入り方をしない（なぜ: 最初の1文の固さが、そのまま記事全体の距離になる）
- **前提の講義から入らない**。「まず〇〇とは」の説明を3文続けない（なぜ: 読者はまだこの記事を読むと決めていないので、講義を聞く理由が無い）
- **ぼんやりした共感で入らない**。「疲れていませんか？」ではなく、読者1人の生活の具体の場面で今いる所を代わりに言う（なぜ: 誰にでも言える共感は、誰の心にも引っかからない）
- **専門用語は、出したその場で説明する**（なぜ: 前提知識の無い読者は、分からない言葉が1つ出た所で閉じる）
- **本編で後から説明する言葉を、冒頭で先に使わない**。自分で作ったラベルや短い呼び名は、説明の後で初めて使う。冒頭を書いたら「この冒頭に出てくる、読者がまだ知らない言葉」を書き出し、1つでもあれば直してから出す（なぜ: 冒頭は説明ゼロの場所で、読者は書き手のラベルを1つも知らない）
- **冒頭で有料本編の手順そのものを出さない**。冒頭で出すのは「主張」「その理由」「この記事で手に入るもの」まで（なぜ: 冒頭で答えを全部出すと、続きを読む理由も、買う理由も消える）
- **冒頭で約束したことと、本編をずらさない**（なぜ: 期待外れは、冒頭で閉じられるより悪い評価につながる）

### 6-4 距離感の違う2案の作り方

冒頭300字は、同じ中身で「読者との距離」だけを変えた2案を作り、選んでもらってから本文を書く（なぜ: 声や距離のずれは冒頭300字を読めば分かり、全文を書いた後に直すと全部を書き直すことになる）。

手順:

1. **2案で変えないもの**を先に決める: 1行目の主張・言い当てる場面・この記事の約束（なぜ: 中身まで変えると、何の違いで選んだのか分からなくなる）
2. **変えるもの**を決める。次のうち2〜3個を変える:
   - 書き手の立ち位置（一歩前に立って言い切る専門家／隣に座って打ち明ける経験者）
   - 言い切りと問いかけの割合
   - 一人称の出し方（最初から出す／後半まで出さない）
   - 語尾の丁寧さ（です・ます中心／です・ますに言い切りを混ぜる）
3. **2案とも300字前後にそろえる**（なぜ: 長さが違うと、長さで選ばれてしまう）
4. **2案とも、設定の「声」の範囲に収める**。設定に無い口調（急に砕けた言葉・急に硬い敬語）は作らない
5. **提示する時は、違いを1行ずつ添える**（例の形: 「A＝言い切って前に立つ／B＝隣で打ち明ける」）。受講生が選んだら、その距離感で本文を通して書く

冒頭2案には、どちらもまだ書き直し（`references/quality/rewrite-pass.md`）を通していない途中の原稿であることを、提示する時に一言添える。

### 6-5 年上の読者・丁寧な声の時

設定の声が丁寧な文体で、読者が書き手より年上の時は、1行目を「〜するな」「〜しなさい」の命令・禁止の形にしない。「〜してみてください」「〜はいったん置いてください」のような、許す形に落とす（なぜ: 年上の読者は、初対面の相手からの命令に反発して読むのをやめる）。

## §7 章の1行目の型と、連発の上限

### 7-1 章の1行目に使う型

章の1行目にも、§5-3 の5つの入口を使う。加えて、章の1行目に向く形が1つある。

| 型 | 章の1行目での使い方 |
|---|---|
| A 言い切り | その章の結論を先に言う |
| B 打ち明け | その章の中身が、ほかではあまり書かれない話だと示す |
| C 告白と気づき | 書き手が実際にやって気づいたことから入る |
| D 場面の言い当て | その章が扱う悩みの場面を言い当てる |
| E 寄り添いと問い直し | 読者が章の手前で抱いている思い込みを代わりに言い、問い直す |
| F 具体から入る | 数字・物の名前・一つの動作から入り、2文目で意味を言う |

### 7-2 連発の上限

- **同じ型を3章続けない**。5章あるなら、最低3種類の型を使う（なぜ: 同じ入り方が続くと、章が変わっても同じ話に見え、飛ばし読みされる）
- **「〜ありませんか」「〜していませんか」の問いかけは、3回以上続けない**（なぜ: 問いかけが続くと、読者は答えさせられることに疲れる）
- **「はっきり言います」「正直に言うと」のような切り替えの言葉は、1記事でそれぞれ1回まで**（なぜ: 切り替えの言葉は1回目だけ効き、2回目からは口癖に聞こえる）
- **章のタイトルの語尾を、全章同じにしない**。手順型（D）と列挙型（E）だけは揃ってよい（なぜ: 語尾がそろった目次は、中身まで同じ作りに見える）

### 7-3 章の1行目で使わない言葉と形

- **次の言葉で章を始めない**: 続いて／次に／さて／では／ところで／ちなみに／とはいえ／もちろん（なぜ: どれも前の章に寄りかかる言葉で、章の1行目から主張が消える）
- **段落の1行目で「つまり」「実は」を使う時は、前の段落の言い直しになっていないか確かめる**。言い直しなら段落ごと削る（なぜ: 同じ内容を言い換えた段落は、読む時間だけを取る）
- **前の章のおさらいで始めない**（「ここまでで〜を見てきましたが」）。なぜ: おさらいから入ると、読者はもう知っている話を読まされる
- **章の説明で始めない**（「この章では〜を解説します」）。なぜ: 何をするかの予告は、中身そのものより弱い

### 7-4 章の1行目を書いた後の5問（「で？」チェック）

1. 「で？」「だから何？」で終わらず、確かめたくなる主張があるか
2. 読者自身の体験や記憶を呼び起こす具体があるか
3. 対象を狭めすぎず、読者1人が「自分のことだ」と感じられるか
4. 主張を先に置いたうえで、理由ややり方を読み進める必要が残っているか
5. 誰でも言える一般論で終わらず、根拠のある切り口・比較・数字があるか

1問でも「いいえ」なら、その1行目を書き直す（なぜ: 章の1行目で止まった読者は、その章の残りを読まない）。

## §8 心理効果の使い方と倫理

心理効果とは、人がものを判断する時の「くせ」を説明した心理学の言葉。文章では、読者のくせに沿って情報を並べる道具として使う。嘘や大げさな表現で人を動かす道具ではない。

### 8-1 使う量

- **1記事に3〜5個**。同じ効果は2回まで（なぜ: 多すぎると文章が操作的になり、読者に見抜かれる）
- **効果の名前は本文に出さない**（なぜ: 技の名前を見せた瞬間、読者は操作されていると感じる）
- 書いた後に数えて6個以上あったら、最後に足したものから削る

### 8-2 どこに何を置くか

| 置き場所 | 効果（かっこ内は意味） |
|---|---|
| 冒頭 | バーナム効果（誰にでも当てはまることを、自分のことだと感じる）／カリギュラ効果（禁止されたり隠されたりすると見たくなる）／確証バイアス（自分の考えに合う情報を集めたくなる）／プライミング効果（先に見た言葉が、後の受け取り方に影響する） |
| 本編 | アンカリング効果（最初に見た数字が判断の基準になる）／権威の原理（専門家の情報を信じやすい）／社会的証明（多くの人がしていることに従いやすい）／ハロー効果（1つの目立つ長所で全体をよく見る）／ピーク・エンド・ルール（一番強い場面と最後の印象で全体を覚える）／ツァイガルニク効果（終わっていないことが記憶に残る）／単純接触効果（何度も触れたものに好感を持つ）／認知的不協和（考えと行動が食い違うと落ち着かず、どちらかを変えたくなる） |
| CTA | 損失回避（得るより失うことを強く避ける）／希少性の原理（数や時間が限られたものを欲しくなる）／フット・イン・ザ・ドア（小さなお願いに応じた人は、次のお願いにも応じやすい）／コミットメントと一貫性（一度決めたことと矛盾しない行動をとりたくなる）／ピグマリオン効果（期待されると応えたくなる） |
| 章と章の間 | ツァイガルニク効果／プライミング効果／単純接触効果 |

組み合わせの例:

- 章の終わりに答えの出ていない問いを残し（ツァイガルニク）、次の章の1行目でその答えを言い切る。なぜ: 読者が次の章を読む理由が、内容の中から生まれる
- 無料の1手（§2-2 の6）で小さく動いてもらい（フット・イン・ザ・ドア）、本 CTA で同じ方向の次の1歩を案内する（コミットメントと一貫性）。なぜ: 小さく試した方向の延長にある CTA は、読者にとって飛躍が小さい

### 8-3 倫理（どの層のカードからも上書きできない）

1. **嘘・誇大表現を使わない**。数字・効果・実績・読者の声を、事実より強く見せない
2. **扱うジャンルの法律を守る**。景品表示法（誇大な広告の禁止）・薬機法（健康や美容の効果の表現の決まり）・特定商取引法（ネットで売る時の表示の決まり）・金融商品取引法（投資の勧誘の決まり）など
3. **説得とあおりを分ける**。本当にある損失・本当にある制限（希少性）・実際の記録・関係のある権威だけを使う。不安・期限・読者の声を作らない。読者を見下さない

判断の基準は1つ: **読者が後で読み返した時に、情報にも自分の選択にも納得したままでいられるか**。いられないなら、その効果は使わない。詳しい禁止事項は `references/quality/absolute-rules.md`。

## §9 通しで書く時の決まり

### 9-1 書く前にそろえるもの

1. 設定ファイル（`00_わたしの設定.md`）の全文
2. 索引で選んだカード（`note-body` `note-paid-line` `note-cta` など、今の工程のもの）
3. お手本を1〜2本、全文（マイナレッジの `10_お手本/` と `assets/golden-samples/`）。お手本は、文の組み立て方・リズム・具体の細かさ・有料ラインの置き方を吸収するために読む。フレーズ・場面・数字は持ち込まない（なぜ: お手本の言葉を写すと、別の読者に向けた文がそのまま入る）
4. 受講生が選んだタイトル・冒頭案・設計メモ（§2-8）

### 9-2 見出しの形

| 部位 | 形 |
|---|---|
| 記事タイトル | `# タイトル`（1つだけ） |
| 無料部分の小見出し | `## 小見出し` |
| 有料本編の章 | `## 0章｜見出し`（数字＋「章」で始める） |
| 章の中の小見出し | `### 小見出し` |

なぜ: この形にそろえると、チェックの道具が章の数や見出しを正しく数えられ、note に貼った時もそのまま大見出し・小見出しになる。

### 9-3 通しで書く

- **無料部分→区切り行→有料本編→本 CTA を、章ごとに止めずに1回で書く**（なぜ: 章ごとに止めて書くと、読者の気持ちの流れが章の境目で途切れる）
- 長くて1回で出し切れない時は、ファイルを分けて保存してよい。ただし書く順番は頭から通しで
- 有料ラインの位置には、次の1行だけを置く:

```
---- ここから有料 ----
```

### 9-4 本文に書かないもの

- **制作メモを本文に書かない**。点検の結果・統合の方針・貼り付け時の注意は、本文とは別のメモに書く（なぜ: 本文に混ざったメモは、貼り付けた時に読者の目に入る）
- **公開前に自分で埋める枠（著者の一言・証拠の画像など）は、HTML コメントの形で置く**。例: `<!-- 著者の一言: ここに実際のエピソードを1つ入れる。無ければこの枠ごと消す -->`。【】で本文に置かない（なぜ: 【】の枠は貼り付け用テキストに残り、読者に「作りかけ」と読まれる。HTML コメントは貼り付け用の書き出しで自動的に消える）
- **実績・感想・相談事例を作らない**。無いものは枠のままにし、公開前に本人が事実を入れるか枠ごと消す（`references/quality/absolute-rules.md`）
- **設計の言葉を本文に出さない**。センターピン・読者1人・入口・有料ライン・CTA・教える順番、のような作り手だけが使う言葉は、読者の生活の言葉に言い換える（なぜ: 作り手だけが使う言葉は、読者にとっては説明されていない専門用語になる）

### 9-5 書き上げた直後にやること

1. **数字と参照を数え直す**。本文の「N問・N章・Nか所・N分・N日・約N字」を全部拾い、実際の数と合っているか確かめる。点検や書き直しで文を直した後も、毎回やり直す（なぜ: 後からの小さな修正で「10問と書いたのに9問」はすぐに起きる）
2. **字数を確かめる**（§1-3）。60字を超える文は、意味の切れ目で2文に分けられないか見る
3. **仕上げの10項目を確かめる**（下の表）
4. 品質工程へ進む: `references/quality/breakdown-checklist.md`（日本語の破綻点検）→ `references/quality/rewrite-pass.md`（話し言葉への書き直し）→ `references/quality/meaning-check.md`（意味のすり替わり点検）。全体の順番は `references/quality/pipeline.md`

仕上げの10項目:

| # | 確かめること | なぜ |
|---|---|---|
| 1 | 固有名詞・自分で作った言葉は、初めて出た所で説明している | 説明の無い言葉で読者が止まる |
| 2 | 便益を書いた直後の2文以内に、その動作をすると何が起きるかが書いてある | 起きることの無い便益は、ただの宣伝文句に読まれる |
| 3 | 主張には「なぜなら」にあたるしくみがある | しくみの無い主張は、読者に信じる理由を渡さない |
| 4 | 無料の1手は1か所だけで、番号が付いている | 2つ以上あると、どれもやらない |
| 5 | 同じ主張の繰り返しは2回まで | 3回目からは水増しに見える |
| 6 | 意味の取れない文が0 | 1文の意味が取れないだけで、その段落ごと読まれなくなる |
| 7 | 事実に反する主張・出典の無い統計っぽい言い切りが0 | 1つの嘘で全体の信用が崩れる |
| 8 | 実績・感想・相談事例の作り話が0（枠は枠のまま） | 作り話は、規約と法律の両方に触れる |
| 9 | 書き手が実際にやっていることだけを、書き手の話として書いている | 読者は「誰が言っているか」で中身を信じる |
| 10 | 無料部分の10の役割（§2-2）がそろっている | 1つ欠けると、読者は買う手前で止まる |

### 9-6 貼り付け用に書き出す

- Python が動く環境では `python3 scripts/tn_paste.py <統合稿.md>` で、HTML コメント・制作メモ・区切り行を除いた3つのファイル（無料部分・有料部分・全文の確認用）を書き出す。動かない環境では、同じものを手で作る: HTML コメントと区切り行を消し、区切り行の上と下で2つに分ける
- note には、無料部分を貼る→ note の画面で有料ラインを入れる→有料部分を貼る、の順で入れる（なぜ: 有料ラインは段落の間にしか置けないので、先に無料部分を置いてから線を入れると位置がずれない）
- 公開後、ログアウトした状態で開き、有料ラインの位置・見出し・目次・画像を確かめる
