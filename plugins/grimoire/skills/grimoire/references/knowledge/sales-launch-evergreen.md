# 販売の導線・教育・ローンチ・エバー化

- 役割: Threads から note（と LINE）へつなぐ導線を組み、販売期間を区切って売るローンチと、常設で売れ続ける形（エバー）を設計するための判断基準
- いつ読むか: 「導線を作りたい」「ローンチの計画を立てて」「エバーにしたい」「売れない」「どの投稿から売れたか知りたい」と言われた時。進め方の手順は `references/modes/3_launch-evergreen.md`、note の本文の設計は `references/knowledge/note-writing.md`、アカウントの運用と分析は `references/knowledge/threads-account-ops.md`
- 目次: §0 このファイルの使い方 §1 導線の全体像 §2 教育 §3 ローンチ §4 エバー化 §5 ローンチからエバーへ切り替える手順 §6 数字の見方 §7 収益の段階ごとの次の一手 §8 やってはいけない売り方

## §0 このファイルの使い方

- マイナレッジと講座ナレッジに stage `launch`・`evergreen` のカードがあれば先に読み、食い違ったらカードに従う。講座で教わったローンチの型や本人の販売の実績は、このファイルの一般的な基準より本人に合っているため
- 例に出る導線と数字は、講座運営者の占いジャンルのアカウントの実物だけ。販売の数字（売上・購入率）の例は載せていない。架空の数字を例にすると、それが目標や相場のように読まれてしまうため
- 金額・日数・本数は「〇〇」で書いている。自分の数字を入れて使う
- 絶対ルール（`references/quality/absolute-rules.md`）は、このファイルのどの基準よりも上。特に §8 は、どんな依頼でも破らない

このファイルで何度も出る言葉:

| 言葉 | 意味 |
|---|---|
| 導線 | 読者が投稿を見てから買うまでに通る道順 |
| 受け皿 | 導線の途中で読者が着地する場所（プロフィール・固定投稿・note・LINE） |
| 教育 | 買う前に読者の中にある「でも…」を、投稿で1つずつ外していくこと。売り込みのことではない |
| ローンチ | 販売する期間を区切り、予告→公開→締切の流れで知らせる売り方 |
| エバー | 期間を区切らず、いつ来た人でも自分のタイミングで買える常設の売り方。エバーグリーン（常緑）の略 |
| 案内の一言 | 投稿の最後に置く「次にしてほしいこと」の一文。CTA とも呼ぶ |
| テスト歩行 | 新しく来た人になったつもりで、投稿から購入や特典の受け取りまでを、自分で通しで歩いて確かめること |

## §1 Threads→note→LINE の導線の全体像

### 1.1 基本の形

```
Threads の投稿
  ↓ 気になった人がプロフィールへ
プロフィール（行き先1つ）
  ↓
固定投稿（行き先1つ）
  ↓
note（無料→有料、または有料へ直接）
  ↓ 買った人・迷っている人
LINE
  ↓
次の note・次の商品
```

| 段 | 役割 | 見る数字（§6） |
|---|---|---|
| 投稿 | 新しい人に届き、フォローやプロフィールへの移動を生む | 閲覧・フォロー |
| プロフィール | 「何の人か」を数秒で伝え、行き先を1つ示す | プロフィールのリンクのクリック |
| 固定投稿 | 代表作として、このアカウントで何が得られるかを見せる | 固定投稿の閲覧・リンクのクリック |
| 無料の note（ある場合） | 中身の一部を読んでもらい、有料 note で続きを読みたいと思ってもらう | 閲覧・有料 note へのクリック |
| 有料 note | 売る | 閲覧・購入数 |
| LINE（ある場合） | こちらから届けられる場所。買った人に次を、迷っている人に後日の案内を届ける | 登録数・配信からのクリック |

LINE がまだ無くても始められる。Threads の投稿はフォロワーの画面にいつ出るかを選べないが、LINE は届けたい時に届けられる。note が売れ始めてから足しても遅くない（§7）。

運営者の占いアカウントの導線（実物）:

```
投稿 → プロフィール → 固定投稿 → 無料の診断ページ → 診断結果（LINE 登録の案内）→ 有料の場
```

無料の診断ページが「無料の入口」にあたる。受講生の導線では、ここが無料の note や LINE の登録特典になる。

### 1.2 導線を組む時のルール

| ルール | なぜ |
|---|---|
| 各段で案内する行き先は1つにする。運営者はプロフィールと固定投稿の目的を「無料診断への案内」1つに絞った | 行き先が2つあると、読者がどちらも押さずに戻るため |
| 各段の約束をそろえる。投稿で「〇〇がもらえる」と書いたら、プロフィール・固定投稿・行き先の1行目にも同じ〇〇が書いてあるようにする。運営者の受け皿の点検では、行き先の画面にある LINE 登録の案内が「最新情報を受け取る」のままで、用意した特典の名前と合っていなかったことがある | 約束が途中で変わると、読者は「違う所に来た」と感じて離れるため |
| 受け皿を作る順番は、行き先→特典→固定投稿→プロフィール→テスト歩行→投稿で案内、の順（`references/knowledge/threads-account-ops.md` §1.5） | 投稿で案内を始めた後に行き先が壊れていると、押した人の信用を失うため |
| 受け皿ができあがったと言えるのは、テスト歩行が終わった時 | 設定画面を見ただけでは、リンク切れや約束の食い違いに気づけないため |
| note と LINE のリンクはプロフィールと固定投稿に置き、投稿の本文には貼らない。投稿からは「プロフィールの固定投稿」へ案内する。note のリンクをどうしても投稿に置くなら、ツリーの最後のパートにする（`references/knowledge/threads-posting.md` §5） | 運営者は、外へ出るリンクが本文にあると読まれにくくなり、LINE のリンクはアカウントの制限につながるおそれもあると判断して運用しているため。表示への影響は公式に確かめられる情報がないので、Threads の決まりではなく運営者の判断として扱う |
| 投稿から直接 note や LINE へ誘うのは、フォロワーとの関係ができてからにする。運営者は、フォロワーが700人ほどの段階では、投稿から直接誘うのを強めるより、プロフィールを経由する2段構えを選んだ | 初めて見た人に、いきなり外へ出る行動を頼むのは、信用の順番として早いため |

## §2 教育

### 2.1 教育とは

教育は、買う前に読者の中にある「でも…」を、投稿で1つずつ外していくこと。note の良さを説明し続けることではない。読者は、自分の「でも…」が外れた時に、自分から続きを知りたくなるため。

### 2.2 壁の見つけ方

読者が買うまでに越える壁は、ジャンルと読者で違う。次の4か所から、自分の読者の壁を書き出す。

| 見る所 | 書き出し方 |
|---|---|
| `00_わたしの設定.md` のセンターピン | 「止まっている壁」を、もっと小さな壁に分ける |
| 読者の声（コメント・DM・引用） | 「でも〇〇だから」「私には無理」「〇〇が怖い」のような言葉を、そのまま写す |
| 設定の「見てくれない理由」 | 入口で止まる理由を、最初の壁として置く |
| note の目次 | 各章が外す「でも…」を書き出し、note を開く前に外れていないと買われない壁がどれかを選ぶ |

### 2.3 よくある壁の並び

壁は、たいてい次の順に並ぶ。自分の読者の言葉に書き換えて使う。

| 順 | 読者の中の「でも…」 | 投稿での外し方 | 使わない手 |
|---|---|---|---|
| 1 | 自分の話だと思えない | 読者が毎日出会う場面、口にする言葉から入る | 属性で呼びかけて絞りすぎる |
| 2 | なぜうまくいかないのか分からない | 原因の仕組みを、1本の投稿に1つだけ見せる | 読者の性格や努力のせいにする |
| 3 | 変えられると思えない | 変わる前と後の差を、本当にあった例で見せる | 作った体験談・作ったビフォーアフター |
| 4 | この人を信じていいか分からない | 根拠（経験・資格・実績の事実）と、日々の投稿の中身で見せる | 盛った実績、他人の実績を自分のもののように見せる |
| 5 | 自分の条件でもできるか分からない | 読者と同じ条件（時間・お金・年代・経験）の場合を書く | 「誰でも」「必ず」と言い切る |
| 6 | お金を払うほどか分からない | 無料で読めるものと、note で得られるものの違いを具体的に書く | 実在しない通常価格と比べる |
| 7 | 今でなくてもいい | 締切がある場合は、その事実を伝える | 偽の締切、不安をあおる |

順番を守るのは、1の壁（自分の話だと思えない）を越えていない人に、6（値段）や7（今でなくてもいい）の話をしても届かないため。値段と時期の話は、販売期間の近くでまとめて扱う（§3）。

### 2.4 投稿への割り当て

| ルール | なぜ |
|---|---|
| 1本の投稿で外す壁は1つにする | 複数の壁を1本に詰めると長くなり、どれも外れないまま読み終わるため |
| 投稿の最後に、次の壁へ渡る一言を置く（例:「じゃあ、なぜ〇〇なのか。次の投稿で書きます」） | 運営者のアカウントで、よく読まれた投稿でも、読んだ後に進む先がないと、フォローや診断への移動につながらなかったため |
| 約束の強さと、同じ投稿に置く根拠の量をそろえる。強いことを言うほど、根拠（事実・例）を同じ投稿に置く | 根拠のない強い約束は読者に疑われ、誇大な表現にもなりうるため |
| 普段の企画表で、どの壁の投稿を何本出したかを数える（`references/modes/1_threads.md` §3 の企画表に「壁」の列を足す） | 入口の壁の投稿ばかりで、途中の壁（原因・自分の条件）が抜けていることに気づけるため |
| 読者を責める言い方や、不安で動かす言い方で壁を外そうとしない | 一時的に反応が出ても読者の信用を失い、規約や法律の問題にもなりうるため（§8） |

## §3 ローンチ

### 3.1 使う場面と、始める前の確認

ローンチは、新しい note を出す時、値段を変える時、note を大きく書き直した時に使う。期間を区切ると、その期間にまとめて知らせる理由ができ、迷っている人が決めやすくなるため。

始める前に、次を全部確かめる。

| 確認 | なぜ |
|---|---|
| note の中身が完成し、公開の設定ができている | 公開日に中身が間に合わないと、予告を見て待っていた人を裏切るため |
| 受け皿（プロフィール・固定投稿・リンク）ができ、テスト歩行が済んでいる | 一番人が来る公開日に導線が壊れていると、取り返せないため |
| 締切の後の扱いを決めた（同じ値段で常設にする／値段を上げて常設にする／販売を止める） | 締切の後を決めずに「締切」と言うと、締切の言葉に嘘が混ざるため（§4.6） |
| 期間中に質問や返信に使える時間を確かめた | 販売期間の質問に答えられないと、迷っている人がそのまま離れるため |
| 数字を記録する表を用意した（§6.3） | どの投稿から売れたかは、期間中に記録しないと後から分からないため |

### 3.2 期間の決め方

ローンチは3つの期間に分ける。

| 期間 | 中身 |
|---|---|
| 予告期間 | 壁を外す投稿を出しながら、「〇月〇日に、〇〇の note を出します」と知らせる |
| 販売期間 | 公開日から締切まで。案内と、買う前の質問への答えを出す |
| 締切の後 | 締切を守り、常設の形に切り替える（§5） |

予告期間の長さは、外してもらう壁の数から決める。

```
予告期間の日数 ＝ 壁の数 × 1つの壁に使う投稿の本数 ÷ 1日に出せる「壁の投稿」の本数
```

例の形: 壁が〇個、1つの壁に〇本、1日に〇本なら、予告期間は〇日。

販売期間の長さは、毎日の案内と返信を続けられる日数で決め、延長しない前提で決める。延長すると、次のローンチから締切を信じてもらえなくなるため。

### 3.3 投稿カレンダーの作り方

1. 公開日と締切の日時を決める
2. 締切の後の扱いを決める（§3.1）
3. §3.2 の式で、予告期間の日数を出す
4. 予告期間の各日に、外してもらう壁を順番に割り当てる（§2.3 の順）
5. 販売期間の各日に、投稿の種類（§3.4）を割り当てる
6. 残りの枠に普段の投稿（広げる・つながる）を入れる。販売期間でも、案内する投稿は1日の中の一部にとどめる
7. 固定投稿とプロフィールを差し替える日（公開日・締切の後）を書き込む

6で普段の投稿を残すのは、案内の投稿だけになると新しい人に届かなくなり、フォロワーも「売り込みばかり」と感じて離れるため。

カレンダーの形:

| 日付 | 期間 | 投稿の種類 | 外してもらう壁 | 案内の一言（なし／軽い／行き先） | 固定投稿・プロフィールの作業 | メモ |
|---|---|---|---|---|---|---|
| 〇/〇 | 予告 |  |  |  |  |  |
| 〇/〇 | 販売 |  |  |  |  |  |
| 〇/〇 | 締切の後 |  |  |  |  |  |

### 3.4 期間中に出す投稿の種類

| 期間 | 投稿の種類 | 中身 | 注意 |
|---|---|---|---|
| 予告 | 壁を外す投稿 | §2 の壁を1本に1つ | ふだんの投稿と同じ品質で出す |
| 予告 | 中身の一部を見せる投稿 | note の中の考え方を1つ、無料で読める形で | 出しすぎて、note を読む理由を消さない |
| 予告 | お知らせ | 何が・いつ・誰に向けて出るか | 値段や特典が決まっていないなら書かない |
| 予告 | 質問の受付 | 「〇〇について聞きたいことがあればコメントで」 | 集まった質問は、販売期間の投稿の材料になる |
| 公開日 | 公開のお知らせ | 誰の・どんな壁を・どう越える note か、値段、締切の日時 | 固定投稿も同じ内容に差し替える |
| 販売期間 | よくある質問への答え | 実際に来た質問に、名前を出さずに答える | 同じ質問を持っていて聞けない人が多いため |
| 販売期間 | 読んだ人の声 | 本人の許可がある、実在する感想 | §4.4 のルールを守る |
| 販売期間 | 合う人・合わない人 | この note が向いている人と、向いていない人 | 合わない人に買わせない方が、買った後の不満や返金の相談が減るため |
| 締切の前 | 締切のお知らせ | 締切の日時（事実だけ） | 同じ文を何度も繰り返さない |
| 締切の後 | お礼と今後のお知らせ | 締切の後の扱い（常設・値段・販売停止） | 売れた数などの数字は本当のものだけ |

### 3.5 ローンチのルール

| ルール | なぜ |
|---|---|
| 締切は本当の締切だけにし、延長しない | 一度延長すると次から締切が信じられなくなり、ローンチという売り方そのものが使えなくなるため |
| 締切の後も同じ値段で売るなら、「締切」「今だけ」と言わない。「公開記念」のように事実どおりに書く | 締切の後も同じ条件で買えると、締切の言葉が嘘になるため |
| 数量の限定は、本当に数を決めている時だけ | 実在しない限定は、景品表示法で問題になるおそれがあり、見抜かれた時に信用を失うため |
| 公開日に、固定投稿とプロフィールを販売期間の内容に差し替える | 一番人が来る日に、プロフィールから note にたどり着けるようにするため |
| 期間中は、毎日1回リンクが生きているかを確かめる | 期間中のリンク切れは、そのまま売上の取りこぼしになるため |

## §4 エバー化

### 4.1 エバーとは

エバーは、ローンチが終わった後も、プロフィール・固定投稿・定期の再告知・note の中・LINE に入口が常にあり、新しく来た人が自分のタイミングで買える状態のこと。新しいフォロワーはローンチの後にも毎日来ていて、その人たちはローンチがあったことを知らないため。

常設の入口は5つ。

| 入口 | 置くもの | 直す時期 |
|---|---|---|
| プロフィール | 何の人か＋行き先1つ（note または無料の入口） | 行き先・値段が変わった日 |
| 固定投稿 | 代表作＋行き先1つ（期間の言葉は入れない） | 行き先・値段・特典が変わった日。月1回の見直し |
| 定期の再告知 | 決めた周期で出す note の案内（§4.3） | 周期ごと |
| note の中の回遊 | 無料 note→有料 note、有料 note→次の note・LINE（§4.5） | 新しい note を出した日。月1回のリンク点検 |
| LINE（ある場合） | 登録した人への案内、買った人への次の案内 | 新しい note を出した日 |

### 4.2 固定投稿とプロフィールの常設版

ローンチ中の固定投稿には、締切や期間の言葉が入っている。締切の後は、期間の言葉を消した常設版に替える。

常設版の固定投稿は、`references/knowledge/threads-account-ops.md` §1.4 の組み立てで作る。そこに載せた運営者の占いアカウントの固定投稿は、締切の言葉が無く、行き先が1つで、行き先で得られるものが書いてある常設の形になっている。

| ルール | なぜ |
|---|---|
| 固定投稿に、期間が過ぎた言葉（締切・今だけ・〇日まで）を残さない | 過ぎた締切が残っていると、アカウントが放置されているように見え、今の値段まで疑われるため |
| 用意できていない特典や配信を約束しない | 約束した物が届かないと、読者はその後のリンクも押さなくなるため |
| プロフィールと固定投稿の行き先を同じにする | 行き先が別々だと、どちらが本命か読者が迷うため |

### 4.3 定期の再告知の型

再告知は、ふだんの投稿の中に、決めた周期で note の案内を混ぜること。案内の一言がある投稿は、全体の3割前後までにする（`references/knowledge/threads-account-ops.md` §3.2）。

同じ告知文は繰り返さない。運営者の占いアカウントでは、伸びたネタを出し直す時の決まりを「30日以上あける・月2本まで・形を変える」にしている（9日後の出し直しで「いいね」が105から5に下がった実測から）。再告知にも同じ考え方を使い、同じ文の繰り返しはしない。

再告知の入り方（同じ note でも、入り方を毎回変える）:

| 入り方 | 中身 | 使える条件 |
|---|---|---|
| 壁から | §2 の壁を1つ外し、その先を note で読めると案内する | いつでも |
| 読者の声から | 読んだ人の感想を入口にする | 許可のある感想がある時（§4.4） |
| 中身の一部から | note の中の考え方を1つ見せる | いつでも（出しすぎない） |
| よくある質問から | 実際に来た質問に答え、詳しくは note で | 質問が来た時 |
| 書き足しのお知らせ | note に追記・更新した内容を知らせる | 本当に更新した時だけ |
| 自分の体験から | note を書いた理由・書いた後に起きたこと | 本当にあったことだけ |

| ルール | なぜ |
|---|---|
| 再告知の日を、月のカレンダーに先に入れる（`references/knowledge/threads-account-ops.md` §3.4） | 思い出した時に告知するやり方だと、忙しい月に告知が消え、その月の売上も消えるため |
| 再告知の投稿も、ふだんの投稿と同じ品質工程を通す | 告知の投稿だけ質が下がると、そこで読者が離れるため |
| 同じ入り方を2回続けない | 同じ入り方が続くと、フォロワーが「また告知だ」と読み飛ばすため |

### 4.4 読者の声の出し方

| ルール | なぜ |
|---|---|
| 出す前に、本人に許可をもらう | 本人の知らない所で感想が使われると信用を失い、もめごとにもなるため |
| 名前・アイコン・本人が特定できる細部は消す（本人が出してよいと言った時を除く） | 感想を書いた人のプライバシーを守るため |
| 本文を書き換えない（誤字を直す時も、意味を変えない） | 書き換えた声は、作った声と変わらなくなるため |
| 成果の数字が入った声を、「誰でもこうなる」ように並べない。数字入りの声を使う時は、個人の感想であることを添える | 一部の人の結果を全員の結果のように見せると、誇大な表現になるため |
| お礼や割引などと引き換えにもらった感想は、そのことを書く | 広告であることを隠した表示は、景品表示法で問題になるおそれがあるため |
| 声がまだ無いうちは、声を作らない。集まるまでは、壁から入る再告知を使う | 作った声は、§8 のやってはいけないことにあたるため |

集め方: note の最後や LINE の案内で「感想を聞かせてください」と頼む。届いた感想は、許可の有無と一緒にマイナレッジの `40_実績/` に残す。

### 4.5 note の中の回遊

回遊は、1本の note を読み終わった人が、次に読むものへ進める道を、note の中に作ること。

```
無料の note の最後 → 有料 note
有料 note の最後 → LINE か、次の note
関連する note 同士 → 1か所ずつ
```

| ルール | なぜ |
|---|---|
| 1か所に置く行き先は1つにする | 行き先が並ぶと、読者がどれも押さずに閉じるため |
| 値段・特典・行き先が変わったら、全部の note の案内を直す | 古い note に残った古い約束を信じて、読者が買ってしまうため |
| 月1回、全部の note のリンクを自分で押して確かめる | リンク切れは、自分で押さないと気づけないため |
| 回遊の地図（どの note からどこへつないでいるか）を1枚にまとめて、マイナレッジに残す | note が増えると、どこに何を書いたかを覚えきれなくなるため |

1本の note の中の案内の置き方（本編の途中の軽い案内と、最後の本命の案内の2段）は `references/knowledge/note-writing.md` §4 に従う。途中の軽い案内は保存やスキのような読むのを止めない動作にし、別の note や LINE へ送るのは最後の1か所にする。

### 4.6 価格と特典の常設版

| ルール | なぜ |
|---|---|
| ローンチの値段と常設の値段の関係は、公開の前に決める | 締切の後に値段を考えると、締切の言葉と実際が食い違うため |
| 期間限定の特典は、期間が終わったら本当に外す | 外さないと、期間限定という言葉が嘘になるため |
| 常設の特典は、最初から「いつでも付く特典」として書く | 常設なのに限定のように書くと、後から来た人をだますことになるため |
| 値段を上げる時は、上げる日を前もって知らせてから上げる | 知らせずに上げると、迷っていた人が損をしたと感じるため |
| 「通常〇〇円のところ」と書くのは、実際にその値段で売っていた期間がある時だけ | 売ったことのない通常価格と並べて安く見せるのは、景品表示法で問題になるおそれがあるため |

常設の特典の例（運営者の占いアカウント）: LINE の登録特典として、12タイプそれぞれを同じ5つの見出し（基本の気質／止まりやすい場面／家族・人間関係で／仕事・進め方で／今日の一手）でまとめたレポートの原稿を用意した。配信の設定が終わるまでは、固定投稿やプロフィールでこの特典を約束していない。

### 4.7 大きく伸びた投稿が出た時

1本の投稿がふだんの何倍も伸びたら、48時間以内に受け皿を確かめる（プロフィール・固定投稿・行き先が生きているか、約束がそろっているか）。運営者のアカウントでは、これを「もし〜なら」の表（`references/knowledge/threads-account-ops.md` §5.5）に入れている。伸びた投稿から来た人がプロフィールで迷うと、一番人が来た機会をそのまま逃すため。

## §5 ローンチからエバーへ切り替える時の手順

| 順 | やること | なぜ |
|---|---|---|
| 1 | 締切の日時に、言ったとおりに締める（値段を変える・特典を外す・販売を止める） | 締切を守ることが、次のローンチの信用になるため |
| 2 | 締切の後のお知らせを出す（お礼・今後の扱い）。数字を出すなら本当のものだけ | 締切の後に来た人が、今どうなっているかを知れるようにするため |
| 3 | 固定投稿・プロフィール・全部の note の案内から、期間の言葉を消す | 過ぎた締切の言葉が残ると、アカウントが放置されて見えるため |
| 4 | テスト歩行をする | 差し替えの時にリンクや約束が壊れることが多いため |
| 5 | ローンチの数字を振り返る（§6）。どの投稿の日に売れたか、どの段で落ちたかを1枚にまとめる | 次のローンチと常設の案内を、どの投稿から直すかを決めるため |
| 6 | 再告知の周期と入り方を決め、月のカレンダーに入れる（§4.3） | 決めないと、ローンチの後に案内が止まり、常設の売上が出ないため |
| 7 | 読者の声を集める仕組みを入れる（§4.4） | 常設の再告知で一番使いやすい材料になるため |
| 8 | 1か月たったら常設の数字を見て、入口を1つだけ直す | 同時にいくつも直すと、どの直しで売上が変わったのか分からなくなるため |
| 9 | 振り返りの結果をカードにする（`references/modes/5_review.md`・stage `launch` `evergreen`） | 次のローンチで同じ失敗をしないため |

## §6 数字の見方

### 6.1 導線の段ごとの数字

| 段 | 数字 | どこで見るか | 注意 |
|---|---|---|---|
| 投稿 | 閲覧・フォロー | Threads のインサイト | 閲覧は表示回数。比べる時だけ使う |
| プロフィール・固定投稿 | リンクのクリック | Threads のインサイト、またはリンクの印（§6.2） | 見られる数字は Threads の画面の仕様で変わる |
| note | 閲覧・購入数 | note の管理画面 | 見られる範囲は note の画面の仕様による |
| LINE | 登録数・配信からのクリック | LINE の管理画面 | 使っているサービスによって見られる数字が違う |

見られない数字は、推測で埋めない。見られない段は「見られない」と書き、前後の段の数字から判断する。推測の数字を混ぜると、その後の判断が全部ずれるため。

### 6.2 どの投稿から売れたかを知る

| 方法 | やり方 | なぜ・注意 |
|---|---|---|
| リンクに印を付ける | 同じ行き先でも、プロフィール用・固定投稿用・販売期間の投稿用で、リンクの末尾に付ける印（どこから来たかを見分けるための文字）を変える。運営者は、プロフィールのリンクと固定投稿のリンクで印を分けた | どの入口から来た人が多いかが分かるため |
| 印が数えられているか確かめる | 印を付けたリンクを自分で押し、行き先の管理画面で数が増えるかを見る | 運営者の受け皿の点検で、リンクに印は付いていたのに、行き先のページにそれを数える仕組みが入っておらず、数が取れていなかったことがあるため |
| 日ごとの表で見る | 投稿と売上を同じ表に1日1行で並べ、売れた日とその前の日の投稿を見る | 印が使えない時でも、売れた日の前後の投稿から候補を絞れるため |

1冊や2冊の売上で「この投稿から売れた」と言い切らない。数が少ない時は偶然が大きく、たまたま重なった投稿を原因だと思い込むため。候補としてメモし、次の販売期間で同じ種類の投稿を出して確かめる。

### 6.3 記録の表

| 日付 | 出した投稿（最初の20字・役割・種類） | 閲覧 | フォロー増 | リンクのクリック | note の閲覧 | 購入数 | LINE 登録 | メモ |
|---|---|---:|---:|---:|---:|---:|---:|---|
|  |  |  |  |  |  |  |  |  |

マイナレッジの `40_実績/` に残す。振り返りは `references/modes/5_review.md` の手順で行う。

### 6.4 導線のどこで落ちているかを見つける

上の段から順に、その段が働いている証拠になる数字を確かめる。最初に証拠が出ない段が、詰まっている所。直すのはその段だけにする。下の段をいくら直しても、上の段で止まっている人は下まで来ないため。

| 詰まっている段 | よくある原因 | 手当て |
|---|---|---|
| 投稿→プロフィール | 投稿を読んでも「この人の他の投稿も見たい」と思わない | シリーズの次回予告、人柄が見える投稿（`references/knowledge/threads-account-ops.md` §6） |
| プロフィール→リンク | 行き先が複数ある・何が得られるか分からない | 行き先を1つにし、得られるものと手間の少なさを書く |
| リンク→note の購入 | 投稿で約束したことと、note のタイトル・冒頭がずれている／教育が足りない | 約束をそろえる。抜けている壁の投稿を足す（§2） |
| 購入→次の購入 | 買った人への次の案内がない | 有料 note の最後と LINE に、次の行き先を1つ置く（§4.5） |

### 6.5 必要な数字を算数で出す

目標の売上から逆に、各段に必要な数を出す。

```
目標の購入数 ＝ 目標の売上 ÷ note の値段
必要な note の閲覧 ＝ 目標の購入数 ÷ 購入率
購入率 ＝ 自分の note の購入数 ÷ 閲覧
```

例の形: 月に〇〇円売りたい、値段が〇〇円なら〇冊。自分の note の購入率が〇%なら、note の閲覧は〇回必要。

計算に使う割合は、自分の過去の数字だけにする。「note の購入率は平均〇%」のような数字は、確かめられる一次情報が見つからず、ジャンルと値段で大きく違うため使わない。自分の数字がまだ無いうちは、最初の販売期間で測ることを目標にする。

## §7 収益の段階ごとの次の一手

段階は「今どこまでできているか」（note があるか・導線が通っているか・常設で売れているか）で決める。売上の金額で分けないのは、同じ金額でも止まっている所が違えば、やることが違うため。判定した段階は `00_わたしの設定.md` の「今の段階」に、アカウントの段階（`references/knowledge/threads-account-ops.md` §4）と並べて書く。

| 段階 | 状態 | 主な仕事 | 見る数字 | やらないこと |
|---|---|---|---|---|
| A note を出す前 | 発信はしているが、売る note がない | 読者の壁を集めて、note の中身を決める。フォロワーとの関係を作る | 返信に書かれた読者の言葉・フォロワー数 | 高い値段の商品を先に作る |
| B note はあるが売れていない | note を出したが、購入がほとんどない | 導線の完成（テスト歩行）と、抜けている壁の投稿を足す（§2・§6.4） | 導線の段ごとの数字 | 新しい note を増やす（詰まっている段が同じなら、増やしても売れないため） |
| C 販売期間中 | ローンチ中 | 予告→公開→締切を計画どおりに回し、毎日記録する（§3） | 日ごとの記録（§6.3） | 期間の延長、値下げの繰り返し |
| D エバー運用中 | ローンチの後、常設で売れ始めた | 常設の入口5つと、再告知の周期を回す（§4） | 入口ごとのクリック・再告知した日の購入 | 毎月ローンチをやり直す（常設の入口を育てる前に、本人が疲れて止まるため） |
| E 次の note・次の商品 | 常設で売れ続けている | 買った人から届く質問・感想のうち、今の note で答えきれていないものから次の note を決める | 買った人の声・質問 | 買った人の声を聞かずに、思いつきで次を作る |

`references/modes/1_threads.md` §1 の「今の段階」との対応: A と B は「note を出す前」と同じく集客と教育の投稿が中心、C は「販売期間中」、D と E は「エバー運用中」（教育と再告知が中心）。

| ルール | なぜ |
|---|---|
| 段階を飛ばさない。A の人が E の仕事（次の商品づくり）を始めない | 前の段階の土台がないまま次の段階の仕事をしても、売れる形にならないため |
| 段階の判定は月に1回、数字を見てから行う | 気分で段階を上げ下げすると、やることが毎週変わり、どの手で売上が動いたか分からなくなるため |

## §8 やってはいけない売り方

次のことは、受講生や読者から頼まれても書かない。`references/quality/absolute-rules.md` と合わせて守る。

| やってはいけないこと | なぜ | 代わりにやること |
|---|---|---|
| 「誰でも」「必ず」「月〇〇万円」のように、結果を約束する表現 | 結果は人によって違い、約束どおりにならなかった人とのトラブルになる。誇大な広告として法律上の問題にもなりうる | 本人に実際に起きたことを、条件つきで書く |
| 根拠のない実績、作った体験談、作った読者の声 | 見抜かれた時にアカウント全体の信用を失い、不当な表示にあたるおそれもある | 設定にある事実だけを使う。無いものは無いまま書く |
| 偽の締切、偽の数量限定、締切の後の延長 | 次から締切を信じてもらえなくなり、不当な表示にあたるおそれもある | 本当の締切だけを使う。締切がないなら言わない |
| 不安をあおる（「放っておくと大変なことに」「今やらないと手遅れ」） | 怖さで動いた人は買った後に後悔しやすく、読者との関係が続かない | 読者が今困っている場面と、変わった後の場面を具体的に書く |
| 実在しない通常価格と比べて安く見せる | 景品表示法で問題になるおそれがある | 今の値段だけを書く |
| 健康・美容・お金・占いの結果について、効果を言い切る | 法律や Threads・note の規約に触れるおそれがあり、読者に実害が出ることもある | 設定の「ジャンルの規約上の注意」に従い、断定しない書き方にする |
| 広告や紹介料があることを隠す | 景品表示法で問題になるおそれがある | 広告・紹介であることを書く |
| 用意していない特典や配信を約束する | 届かなかった人の信用を失う | できあがった物だけを約束する |
| コメント欄で個人情報（生年月日・住所・本名）を書かせる | 誰でも見られる場所に個人情報が残る | 必要なら DM や自分のフォームで受け取る |
| 頼まれていない売り込みを DM で送る | 迷惑に感じた人が離れ、通報されることもある | 聞かれた時だけ答える |
| 他人の投稿や note の文を写す | 盗用になり、読者にも「どこかで見た話」と思われる | 構造だけを学び、自分の言葉と事実で書く |
| 買わない人や迷っている人を責める、見下す | 今は買わない人も、あとで買う読者になりうる | 合わない人には「合わない」と伝えるだけにする |
