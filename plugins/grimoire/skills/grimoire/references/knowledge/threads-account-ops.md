# Threads アカウントの設計・リサーチ・運用・分析

- 役割: Threads のアカウントを「誰に何を届けるか」から組み立て、毎週の運用と数字の振り返りで育てるための判断基準
- いつ読むか: 「アカウントを作りたい」「プロフィールや固定投稿を直したい」「競合を調べたい」「投稿の本数や時間を決めたい」「伸びない」「数字の見方が分からない」と言われた時。投稿の文そのものの書き方は `references/knowledge/threads-posting.md`、販売の導線は `references/knowledge/sales-launch-evergreen.md`
- 目次: §0 このファイルの使い方 §1 アカウント設計 §2 リサーチ §3 運用の型 §4 成熟度の判定 §5 分析 §6 伸び悩みの症状別の手当て §7 AIで回す時の注意

## §0 このファイルの使い方

- マイナレッジと講座ナレッジに stage `account`・`review` のカードがあれば、このファイルより先に読み、食い違ったらカードに従う。カードは本人の数字と講師の判断から作られていて、このファイルの一般的な基準より本人のアカウントに近いため
- 例に出る数字は、講座運営者の占いジャンルのアカウント（動物占い＝生年月日から動物のタイプを出す占い）の実測だけ。数字を受講生のジャンルにそのまま当てはめず、見方だけを借りる。閲覧の多さや強い時間帯は、ジャンルと読者で大きく変わるため
- Threads の表示の仕組みは公開されていない部分が多い。このファイルは、確かめられない仕様（「〇〇をすると表示が減る」など）を前提にしない。噂を前提にすると、閲覧やフォローを実際に増やしていたやり方まで、根拠なくやめてしまうため
- 絶対ルール（`references/quality/absolute-rules.md`）は、このファイルのどの基準よりも上

このファイルで何度も出る言葉:

| 言葉 | 意味 |
|---|---|
| 閲覧 | Threads のインサイト（数字を見る画面）に出る表示回数。画面に表示された回数で、最後まで読まれた回数とは限らない |
| 中央値 | 数字を小さい順に並べた時の真ん中の値。1本の大当たりに引っ張られないので、ふだんの実力を見るのに使う |
| 受け皿 | 投稿を見て興味を持った人が着地する場所。プロフィール・固定投稿・note・LINE など |
| 固定投稿 | プロフィールの一番上に留めておく投稿。プロフィールを見に来た人が最初に読む |
| 案内の一言 | 投稿の最後に置く「次にしてほしいこと」の一文（フォロー・コメント・リンク先を見る など）。CTA とも呼ぶ |

## §1 アカウント設計

### 1.1 「誰に何を」を1行にする

アカウントの設計は、`00_わたしの設定.md` の「読者1人」「センターピン」「売りたいもの」から始める。名前やアイコンより先に、次の1行を決める。この1行が無いと、プロフィール・固定投稿・投稿のテーマがばらばらになり、見に来た人が「何の人か」を判断できないため。

```
〈読者1人〉が〈止まっている壁〉で困っている。私は〈根拠〉をもとに、それを〈どう変えるか〉を投稿で届ける
```

〈根拠〉には、経験・資格・実績のうち本人が事実だと言ったものだけを入れる。

運営者の占いアカウントのプロフィールの1行目は、この1行を縮めた形になっている。

```
動物占い×個性心理学で、人間関係と自分の「うまくいかない」をタイプ翻訳する認定講師🌙
```

分けると、誰に＝人間関係や自分のことで「うまくいかない」と感じている人、何を＝その原因をタイプの違いとして言い換えて見せる、根拠＝認定講師、になる。

決め方のルール:

| ルール | なぜ |
|---|---|
| 入口（プロフィールと投稿の1行目）は広い悩みにして、年代や属性での絞り込みは、投稿の本文や例え話の中で行う。運営者はプロフィールから「50代へ」という言葉を外し、年代に合わせた話は投稿の例え話で拾う形に変えた | 1行目で年代や属性を限定すると、当てはまらない人がそこで読むのをやめ、新しい人に広がる前に止まるため |
| 伸びない入口は、テーマごと捨てずに置き場所を変える。運営者のアカウントでは「副業」を1行目の入口にした投稿が伸びず、友達・家族・頼れる人のような身近な人間関係の話が伸びた。そこで副業の話は、LINE に登録した人に向けて、関心ごとに出し分ける設計に変えた | 入口では拾えない話題でも、関心を持って入ってきた人には役に立つため |
| 入口を広げる時に、具体（名前・物・数字）を消さない。運営者のアカウントで、タイプを知らない人に配慮して1行目に動物の名前を出さない一般論を32本出した月、その閲覧の中央値は684で、2〜3タイプを名指しする形（19本・中央値3,824）より弱かった | 具体がないと、流し見している人の目が止まる理由がなくなるため。広い入口は、具体を消すことではなく「誰にでも起きる場面」を選ぶことで作る |
| 実績・資格・数字は、本人が事実だと言ったものだけを使う | 作った実績は、見抜かれた時にアカウント全体の信用を失い、法律上の問題にもなりうるため |

### 1.2 名前とアイコン

| ルール | なぜ |
|---|---|
| 名前は、初めて見た人が読めて、声に出して呼べるものにする。何の発信か分かる言葉を1つ添える | 読めない名前は検索もコメントでの呼びかけもされず、覚えてもらえないため |
| アイコンは、小さな丸で表示されても何が写っているか分かるものにする | タイムラインではアイコンがかなり小さく表示されるため |
| 名前とアイコンは、一度決めたら頻繁に変えない | 覚えてくれた人が、次に見かけた時に同じ人だと気づけなくなるため |

### 1.3 プロフィール

プロフィールを見に来るのは、投稿を読んで「この人は誰？」と思った人。数秒で「フォローするか」「リンクを押すか」を決め、決めなければ戻っていく。

組み立ては3つの部品:

1. 何の人か（誰の・何を扱うか＋根拠）
2. 読者がよく口にする思い込みを、ひっくり返す1行
3. 行き先と、行き先の手間の少なさ（事実だけ。例: 生年月日だけ・無料）

運営者の占いアカウントで確定したプロフィール（93字）:

```
動物占い×個性心理学で、人間関係と自分の「うまくいかない」をタイプ翻訳する認定講師🌙
性格のせいだと思ってたこと、だいたいタイプのズレです。
↓ 自分のタイプを知る（生年月日だけ・無料）
```

| ルール | なぜ |
|---|---|
| 行き先（リンク）は1つに絞る。運営者は、プロフィールの目的を無料診断への案内1つにし、実績は投稿の中で見せる形にした | 行き先が複数あると、来た人が選べずに何も押さずに戻るため |
| 詳しい自己紹介（経歴・転機）は、投稿の1行目ではなくプロフィールと固定投稿に置く | プロフィールに来た人はすでに発信者に興味があるので、そこで初めて自分の話が読まれるため |
| 手間の少なさは事実だけ書く（「3分で」「無料」が本当かを確かめる） | 書いた条件と違えば、押した人がそこで離れ、次から信じてもらえないため |
| 書き換えたら、日付と変えた所を `00_わたしの設定.md` の変更履歴に残す | 変更の前と後で、フォローの増え方を比べられるようにするため |

### 1.4 固定投稿

固定投稿の役割は、プロフィールから来た人に「このアカウントで何が得られるか」を1本で見せて、行き先を1つ示すこと。

運営者の占いアカウント用に確定した固定投稿（408字・リンクは省略）:

> 「あの人、裏表がありすぎる」
> 「私、外面ばっかりいいな」——
>
> それ、性格の問題じゃないかもしれません。
>
> 動物占い（個性心理学）では、1人の中に
> 本質・表面・意思決定・希望・隠れ、5つの顔があると見ます。
>
> 外の顔と家の顔が違うのは、二重人格じゃなくて、構造です。
>
> ▼自分の5つのタイプを見る
> （生年月日を入れるだけ・名前もメールも要りません・無料）
> （ここに診断ページのリンク）
>
> 診断すると、あなたの5つの動物と、
> 仕事のスタイル・強み・キャリア適性まで出ます。
>
> このアカウントでは、家族・友達・職場の「うまくいかない」を
> タイプのズレとして毎日翻訳しています。
>
> 自分のタイプが分かると、ここの投稿が
> 「他人の話」から「自分の話」に変わります🌙

上の例の組み立て:

| 順 | 部品 | 例の該当箇所 |
|---|---|---|
| 1 | 読者が実際に口にする言葉 | 「あの人、裏表がありすぎる」 |
| 2 | 見方を変える一言 | 性格の問題じゃないかもしれません |
| 3 | 仕組みを1〜2行で | 1人の中に5つの顔がある |
| 4 | 行き先と手間の少なさ | 生年月日を入れるだけ・名前もメールも要りません・無料 |
| 5 | 行き先で得られるもの | 5つの動物と、仕事のスタイル・強み |
| 6 | このアカウントで毎日見られるもの | 「うまくいかない」をタイプのズレとして翻訳 |
| 7 | フォローした後の変化 | 投稿が「他人の話」から「自分の話」に変わる |

| ルール | なぜ |
|---|---|
| まだ用意できていない特典や配信を約束しない。運営者は、LINE の特典の配信設定が終わっていない段階で、固定投稿から LINE の特典の話を外した | 約束した物が届かないと、その人は二度とリンクを押さなくなるため |
| 500字以内に収める | Threads の1投稿の上限のため |
| 行き先・値段・特典が変わったら、その日のうちに差し替える | 古い約束が残っていると、読者がそれを信じて動き、裏切られたと感じるため |
| 販売期間が終わったら、期間の言葉（締切・今だけ）を消した常設版に替える | 過ぎた締切の言葉が残っていると、アカウントが放置されているように見えるため。詳しくは `references/knowledge/sales-launch-evergreen.md` §4 |

### 1.5 受け皿を作る順番

投稿で行き先を案内し始めるのは、受け皿が全部できてから。運営者のアカウントは次の順番で作った。

1. 行き先（note・無料の入口）が開けて、最後まで動くことを確かめる
2. 特典があるなら、中身を作って届く設定をする
3. 固定投稿を置く
4. プロフィールを書き換える
5. 新しく来た人になったつもりで「投稿→プロフィール→固定投稿→行き先→特典の受け取り」を通しで歩く（テスト歩行）
6. ここまで済んでから、投稿に行き先を案内する一言を入れ始める

順番を逆にすると、案内を見て押した人が壊れた行き先や空の固定投稿にたどり着き、その人はもう押してくれなくなる。だからテスト歩行が終わるまでは「受け皿ができた」と言わない。

## §2 リサーチ

### 2.1 目的を1つ決めてから見る

| 目的 | 見る所 |
|---|---|
| 1行目（入口）を学ぶ | 伸びた投稿の1行目と、その人のふだんの投稿の1行目との違い |
| 導線を学ぶ | プロフィール・固定投稿・リンク先・LINE の中身 |
| 立ち位置を探す | 同じジャンルの人が「誰に」「何を」言っているか。まだ誰も拾っていない読者や悩み |
| ネタを集める | コメント欄に書かれた読者の言葉 |

1回のリサーチで見る目的は1つにする。何となく眺めると、目についた派手な投稿の表面だけを真似ることになり、自分のアカウントに持ち帰れる物が残らないため。

### 2.2 競合アカウントの見方

1アカウントにつき、次の項目をメモする（メモは自分用。投稿や note に相手の名前を出さない）。

- 誰に・何を言っているか
- プロフィールの約束（フォローすると何が得られると書いてあるか）
- 固定投稿の役割（代表作・案内・自己紹介のどれか）
- 行き先（無料の入口・有料 note・LINE）
- 投稿の役割の配分（広げる・つながる・参加してもらう・案内する。§3.2）
- 伸びた投稿の、止める理由・読ませる理由・動かす理由（§2.3）
- 自分が真似する所
- 真似しない所と、その理由

| ルール | なぜ |
|---|---|
| 投稿だけでなく、プロフィール→固定投稿→リンク先→LINE まで実際にたどる | 売れる仕組みの多くは投稿の外（固定投稿や LINE の中）にあり、投稿だけ見ても分からないため |
| 本文は写さない。メモするのは構造（どう止め、どう読ませ、どう動かしたか）だけ | 丸写しは盗用になり、読者にも「どこかで見た話」と思われるため |
| 他の人の名前や投稿を、自分の投稿や note に出さない | 比べられた相手とのもめごとになり、読者には悪口に見えるため |

### 2.3 伸びている投稿の見方

1本の投稿に、3つの問いを当てる。

1. 止める理由: 1行目のどの言葉で、流し見している人の手が止まったか
2. 読ませる理由: 2行目以降のどこで「続きを知りたい」が続いたか
3. 動かす理由: 読み終わった人が、コメント・フォロー・プロフィールに動いたのはなぜか（コメント欄の言葉が答え合わせになる）

判断は、その人の「ふだん」と比べてからにする。フォロワーが多い人はどの投稿も数字が大きいので、数字の大きさだけでは、どの工夫で伸びたのかを見分けられないため。その人のふだんより明らかに伸びた投稿だけを、学ぶ対象にする。

### 2.4 ネタの集め方

| 出どころ | 集め方 | なぜ |
|---|---|---|
| 読者の声 | コメント・DM・引用に書かれた言葉を、そのままネタ帳に写す | 読者が自分で書いた言葉は、1行目に使うと「自分のことだ」と思われやすいため |
| センターピンの壁 | `00_わたしの設定.md` の「止まっている壁」を、もっと小さな壁に分けて1つずつ書く | 1つの壁を1本で扱うと、販売までの教育の順番が組みやすいため（`references/knowledge/sales-launch-evergreen.md` §2） |
| 自分の経験 | 本当にあったことだけを、日付と場面つきでメモする | 作った体験談は細部がぼやけて伝わらず、見抜かれると信用を失うため |
| シリーズ | ジャンルの中の「分かれ目」（タイプ・場面・年代・悩みの段階など）ごとに、同じ型で連作を作る | 次回を見逃したくない人がフォローする理由になるため |

シリーズについての運営者の実測: 占いアカウントで、タイプを1回ずつ取り上げるシリーズ投稿は、直近30日で4本・閲覧の中央値830で、全体の中央値の約2.5倍だった（4本しかないので参考値）。一方、同じ構造の投稿と同じネタの言い換えを続けた月には、閲覧は増えたのに「いいね」の週ごとの中央値が12から2まで下がった。シリーズは型をそろえても、取り上げる中身（タイプ・場面）を毎回変え、同じネタの言い換えはしない。

ネタ帳の形:

| 日付 | 出どころ | 読者の言葉（そのまま） | どの壁か | 使った日 |
|---|---|---|---|---|
|  |  |  |  |  |

## §3 運用の型

### 3.1 本数と時刻

| ルール | なぜ |
|---|---|
| 毎日続けられる本数を先に決め、週にまとめて作り置きして予約する。運営者の占いアカウントは、作り置きを予約で流して1日3〜5本を出している | その日に考えて書くと、忙しい日に止まり、止まった後に再開しにくいため |
| 時刻は、自分の数字で強い時間帯を見て決める。運営者のアカウントでは、ある月は9時台・19時台・22時台が強く、数か月後には8時台・16時台・7時台が上位に変わった | 強い時間帯は読者の生活と表示のされ方で変わるので、他人の時間表は当てにならず、自分の数字もいずれ古くなるため |
| 毎日同じ時刻に固定せず、時刻を少しずつ散らす | 同じ時刻にしか出していないと、他の時間帯の方が強いかを確かめられないため |
| 本文の中の時間の言葉（朝・夜・週末）と、投稿する時刻を合わせる。日付や曜日を書く時は、カレンダーで確かめてから書く | 夜に出る投稿に「おはようございます」とあると作り置きだと分かり、読者との距離が開くため |

### 3.2 投稿の役割を配分する

1本の投稿に全部を期待しない。投稿ごとに「どの数字を動かす投稿か」を1つ決めて、週の中で配分する。運営者の占いアカウントは、全部の投稿で全部を狙うのをやめて、次の4つの役割に分けた。

| 役割 | 動かしたい数字 | 投稿の例 | 運営者の配分 |
|---|---|---|---|
| 広げる | 閲覧（新しい人に届く） | 誰にでも起きる場面に具体を置いた言い切り、全員が当てはまる一覧 | 4割 |
| つながる | いいね・保存（フォロワーとの関係） | シリーズ、発信者の人柄が見える話、笑える「あるある」 | 2.5割 |
| 参加してもらう | 返信 | 2択・3択、自分のことを一言書いてもらう問い | 2割 |
| 案内する | フォロー・プロフィールへの移動・リンク | シリーズの次回予告、固定投稿や行き先への案内 | 1.5割 |

この配分は運営者のアカウントの設計で、効果はまだ検証している途中。自分のアカウントでは、この配分から始めて §5 の振り返りで動かす。`references/modes/1_threads.md` §3 の企画表に「役割」の列を1つ足すと、週の配分を数えられる。

| ルール | なぜ |
|---|---|
| 行き先への案内（リンク先を見て・note はこちら）は全体の3割前後までにする。返信のいらない軽い一言（「当てはまりましたか？」など）は、多くの投稿に付けてよい | 毎回売り込むと読まれなくなる。一方で、運営者のアカウントのある月は83本中71本（85%）に案内の一言がなく、閲覧が多くてもフォローに変わらなかったため |
| 「案内する」投稿は、受け皿ができてから始める（§1.5） | 行き先ができていないのに案内すると、押した人を失うため |

参加のはしご（軽い順）:

| 段 | 読者にしてもらうこと | 形の例 |
|---|---|---|
| 1 | 心の中で当てはめるだけ（返信はいらない） | 「あなたの周りの〇〇さん、当てはまってましたか？」 |
| 2 | 選ぶだけ | 「AとB、どっちでした？」 |
| 3 | 自分のことを一言 | 「あなたの〇〇、コメントで教えてください」 |
| 4 | 書くと返事がもらえる企画（週1回まで） | 「〇〇を書いてくれたら、〇〇を返信します」 |

| ルール | なぜ |
|---|---|
| 軽い段から始め、4段目は週1回までにする | いきなり重い参加を頼むと書く人がおらず、コメント欄が空のまま終わるため |
| 4段目は、返せる人数を先に決め、その日のうちに自分の手で返す。返せる数を超えそうなら「先着〇人」と書く | 「返します」と言って返せないと、参加してくれた人の信用を失うため |
| 読者がその場で答えられる問いにする。運営者のアカウントでは、自分のタイプを知っている人しか答えられない問いにしないよう、タイプが分からない人には無料診断を案内した | 答えるのに調べ物が要る問いには、誰も書かないため |
| 生年月日・住所・本名など、個人が分かる情報をコメント欄に書かせない | 誰でも見られる場所に個人情報が残るため。必要なら DM や自分のフォームで受け取る |

### 3.3 1週間の回し方

| 曜日 | やること |
|---|---|
| 月 | 先週の振り返り（§5.4 の表を埋める）。今週変えることを1つ決める。運営者は30分ほどで済む形にしている |
| 火 | ネタ帳から今週のテーマを選び、企画表を作る（役割の配分もここで決める） |
| 水 | 下書き（`references/modes/1_threads.md`） |
| 木 | 仕上げ（品質工程） |
| 金 | 予約。固定投稿・プロフィール・リンク先が生きているかを確かめる |
| 毎日 | コメントへの返信。読者の言葉をネタ帳に写す |

振り返りを週の最初に置くのは、振り返りで決めた「変えること」を、その週の企画にそのまま入れられるため。曜日は本人の生活に合わせて動かしてよいが、振り返る→企画→書く→仕上げる→予約、の順番は崩さない。

### 3.4 月のカレンダー

月の初めに、週ごとの枠だけ先に決める。中身は毎週の企画表で埋める。

| 週 | 今月のシリーズ | 参加企画（4段目）の日 | 案内する投稿の日 | 出し直し（§3.5）の枠 | 販売の予定 |
|---|---|---|---|---|---|
| 1 |  |  |  |  |  |
| 2 |  |  |  |  |  |
| 3 |  |  |  |  |  |
| 4 |  |  |  |  |  |

販売期間（ローンチ）がある月は、`references/knowledge/sales-launch-evergreen.md` §3 のカレンダーを先に作り、残りの日にこの表の枠を入れる。販売の日程は動かせないので、先に置かないと普段の投稿と重なるため。

### 3.5 伸びた投稿の出し直し

運営者の占いアカウントで、伸びたネタを9日後に言い換えて出し直したところ、閲覧は取れたが「いいね」が105から5に落ちた。これを受けて、出し直しの決まりを次の3つにしている。

| 決まり | なぜ |
|---|---|
| 同じネタの出し直しは30日以上あける | 間が短いと、前回を見たフォロワーが「また同じ」と感じて反応しなくなるため |
| 出し直しは月2本まで | 出し直しが増えると、アカウント全体が使い回しに見えるため |
| 形を変える（単発とツリーを入れ替える・視点を変える・例え話を替える）。同じ文のままのコピーはしない | 同じ文は、前回を覚えている人には読む理由がないため |

出し直した時は、元の投稿の日付をメモしておく。初回と比べて、出し直しで閲覧やいいねが増えたかを振り返りで確かめるため。

## §4 成熟度の判定

### 4.1 段階は「どこで止まっているか」で決める

フォロワー数や投稿数だけで段階を決めない。数字は「届く→フォローに変わる→反応が続く→行き先に進む」の順につながっていて、どこで止まっているかで次の一手が変わるため。同じフォロワー数でも、止まっている所が違えば、やることが正反対になる。

| 段階 | 自分の数字に出るサイン | 次の一手 | やらないこと |
|---|---|---|---|
| 0 準備 | 設定・プロフィール・固定投稿のどれかが無い | §1 と `references/modes/0_setup.md` | 投稿の本数を増やす（見に来た人の着地先がないため） |
| 1 届いていない | 閲覧がフォロワー数とあまり変わらない日が続く（フォロワー以外に届いていない） | 1行目とテーマの実験。型ごとに10本ずつ出して比べる | 販売の案内（見ている人がほとんどいないため） |
| 2 届くが、フォローに変わらない | 閲覧はフォロワー数の何倍も出るのに、フォロワーが増えない | フォローする理由を作る（シリーズの次回予告・人柄が見える話・プロフィールと固定投稿の手直し） | 本数を増やしてさらに広げる（広げても、フォローに変わらないまま流れていくため） |
| 3 フォローは増えるが、反応が細る | 閲覧は上がるのに、いいね・返信の「数」が週ごとに下がる | 同じ型の連続を止め、つながる・参加の投稿を増やす | 当たった型だけで埋める |
| 4 反応はあるが、行き先に進まない | 返信やフォローはあるのに、リンクが押されない・note が読まれない | 受け皿の点検（テスト歩行・書いた約束と中身が合っているか）と、案内の文の見直し | 新しい商品を作る |
| 5 行き先に進んでいる | リンクのクリック・note の閲覧・購入が出始める | 販売の段階の判定へ（`references/knowledge/sales-launch-evergreen.md` §7） | — |

運営者の占いアカウントは、ある月に段階2にいた。上位の投稿は閲覧がフォロワー数（702人）の30〜55倍あり、ほぼ全部がフォロワー以外に届いていたが、フォロワーは増えていなかった。同じ月の後半には、同じ型を続けたことで段階3のサイン（いいねの中央値の低下）も重なった。この時は、さらに広げる手は取らず、「受け皿を完成させる」「投稿に役割を分ける」を選んだ。

### 4.2 判定のルール

| ルール | なぜ |
|---|---|
| 投稿してから48時間たった投稿だけで判定する | 出したばかりの投稿は数字が育ちきっておらず、低く見えるため |
| 1つの型の良し悪しは、その型で10本出すまで決めない | 数本だけでは、テーマや曜日の偶然に振り回されるため |
| 段階は月に1回判定し、`00_わたしの設定.md` の「今の段階」に書く（節が無ければ足す）。販売の段階（`references/knowledge/sales-launch-evergreen.md` §7）も並べて書く | 投稿を作るモードが、この段階を見て投稿の目的を決めるため（`references/modes/1_threads.md` §1） |
| 全部の投稿の閲覧が同時に大きく落ちた時は、判定を2週間止め、いつもどおり出し続ける | Threads 側の表示のされ方が変わった可能性があり、自分の投稿のせいだと思い込むと、効いていた型まで捨ててしまうため |

### 4.3 目標は算数で置く

目標のフォロワー数を決めたら、必要な「閲覧からフォローに変わる割合」を計算して、現実的かを確かめる。

```
必要な割合 ＝ 1か月に増やしたいフォロワー数 ÷ 1か月の閲覧の合計
```

運営者の占いアカウントの例: 1か月の閲覧の合計が約23.6万、フォロワー702人の時点で「3か月後に2,700人」を目標にした。1か月に約670人増やす必要があり、閲覧からフォローに変わる割合は約0.28%が必要になる。今の割合を上げるだけで届くのか、閲覧そのものも増やす必要があるのかを、この計算で先に確かめた。

| ルール | なぜ |
|---|---|
| 「業界の平均は〇%」という数字を使わない。自分の数字と、自分で計算した必要な数字だけで判断する | 確かめられる一次情報の平均値が見つからず、ジャンルで大きく違うため |
| フォロワー数は毎日同じ時刻に記録する | 記録がないと、どの週の何が効いてフォローが増えたかが後から分からないため |
| 目標の途中に確認日を決め、その日までに目標ペースの半分に届いていなければ、目標を下げて施策を見直す | 届かないこと自体より、届かないことに気づかずに同じやり方を続ける方が損が大きいため |

## §5 分析

### 5.1 見る数字

| 数字 | 分かること | 注意 |
|---|---|---|
| 閲覧 | 1行目とテーマで、新しい人の手を止められたか | 表示された回数で、読まれた回数とは限らない。比べる時だけ使い、「〇人が読んだ」とは言わない |
| いいね | 読んだ人の気持ちが動いたか | 新しい人に広く届くほど、閲覧に対する割合は下がる |
| 返信 | 読者が自分のことを話したくなったか | 返信に書かれた読者の言葉はネタ帳へ |
| 再投稿・引用 | 人に見せたいと思われたか | 引用の言葉も読む。反対の意見も混ざる |
| フォロワー数 | 投稿やプロフィールで「次も見たい」と思われたか | 毎日同じ時刻に記録する |
| 行き先の数字（リンクのクリック・note の閲覧・購入） | 案内が行動に変わったか | `references/knowledge/sales-launch-evergreen.md` §6 |

反応率（いいね・返信・再投稿・引用の合計 ÷ 閲覧）は、新しい人に広く届くほど下がる。おすすめで初めて見た人は、フォロワーより反応しにくいため。反応率だけで「悪くなった」と判断せず、いいね・返信の数と並べて見る。運営者のアカウントでは、ある月に反応率の中央値が約2.9%から約0.3%まで下がった。その一部は広く届いたことによる自然な下がり方だったが、いいねの数そのもの（中央値12→2）も下がっていたので、こちらは同じ型の連続による飽きと判断した。

### 5.2 平均ではなく中央値で見る

平均は、1本の大当たりに大きく引っ張られる。ふだんの実力は中央値で見る。

運営者の占いアカウントの実測:

| 期間 | 投稿数 | 閲覧の中央値 | 閲覧の平均 | 最高 |
|---|---:|---:|---:|---:|
| これまでの全部 | 492 | 693 | 1,420 | 39,280 |
| 直近30日 | 74 | 338 | 493 | 3,478 |

月に1回、閲覧の「偏り」を見る:

1. 直近1か月の投稿を、閲覧の多い順に並べる
2. 平均 ÷ 中央値 を出す。3倍以上なら、少数の大当たりに頼っている形。1〜2倍なら、どの投稿も同じくらい届いている形
3. 上位1本・5本・10本が、1か月の閲覧の合計の何%かを出す

運営者のアカウントの直近30日は、上位1本が合計の10%、上位5本で28%、上位10本で40%、平均は中央値の1.5倍だった。大当たりに頼らず平均的に届いている形なので、次の一手は「当たりの1本を出せる型を試す」になる。偏りが大きい形なら、次の一手は「当たった1本の型を、中身を変えて出す」になる（同じネタの言い換えにはしない。§3.5）。

### 5.3 型ごとに比べる（伸び率）

```
伸び率 ＝ その型の投稿の閲覧の中央値 ÷ 全部の投稿の閲覧の中央値
```

1.0より大きければ、ふだんより届いている型。運営者の占いアカウントの直近30日（1行目の形で分けたものの一部）:

| 1行目の形 | 本数 | 閲覧の中央値 | 伸び率 |
|---|---:|---:|---:|
| 短い言い切り | 14 | 640 | 1.89 |
| 断言・打ち明け | 8 | 466 | 1.38 |
| 問いかけ | 14 | 311 | 0.92 |
| 数字から入る | 5 | 207 | 0.61 |

| ルール | なぜ |
|---|---|
| 3本未満の型は比べない | 1〜2本では、偶然の当たり外れと区別できないため |
| 1つの分け方だけで結論を出さず、2つの分け方を掛け合わせて確かめる | 別の理由が重なって、違う物が効いたように見えることがあるため（下の例） |
| 伸び率は「次に試す候補」を選ぶために使い、「これが原因」と言い切らない | 閲覧は時間帯・テーマ・フォロワー数の変化にも左右されるため |

見かけの原因の例（運営者のアカウント）: 自動の集計で「121〜200字の投稿が一番強い」と出たことがある。字数と形式（ツリーの1本目か、1本だけの投稿か）を掛け合わせると、121〜200字のツリーの1本目は34本・中央値2,678だったが、121〜200字の1本だけの投稿は1本しかなく491だった。閲覧を押し上げていたのは「2〜3タイプを名指しする型をツリーにした1本目」で、その投稿がたまたま121〜200字に収まっていただけだった。字数を121〜200字に合わせれば伸びる、という証拠はなかった。

### 5.4 週の振り返り表

振り返りは `references/modes/5_review.md` の手順で行い、結果をマイナレッジの `40_実績/` に残す。表の形:

**全体**

| 数字 | 今週 | 先週 | メモ |
|---|---:|---:|---|
| 投稿数 |  |  |  |
| 閲覧の中央値（48時間たった投稿） |  |  |  |
| いいねの中央値 |  |  |  |
| 返信の合計 |  |  |  |
| フォロワー数（週の最後の日） |  |  |  |
| 行き先の数字（クリック・note の閲覧・購入） |  |  |  |

**役割ごと**

| 役割 | 本数 | 閲覧の中央値 | いいねの中央値 | 返信の合計 |
|---|---:|---:|---:|---:|
| 広げる |  |  |  |  |
| つながる |  |  |  |  |
| 参加してもらう |  |  |  |  |
| 案内する |  |  |  |  |

**まとめ**

- 伸びた投稿の上位3本（型・役割・使ったカード）
- 伸びなかった投稿の下位3本（型・役割・使ったカード）
- 当てはまった「もし〜なら」（§5.5）
- 原因（1つ）
- 次の一手（1つ）
- 変えないこと

| ルール | なぜ |
|---|---|
| 原因と次の一手は1つずつに絞る | 1週間で3つ変えると、翌週にどれが効いたのか分からなくなるため |
| 「変えないこと」も書く | 効いている部分まで一緒に変えてしまうのを防ぐため |
| 使ったカードを書く | どのカードを使った投稿が伸びたかを突き合わせ、効いたカードを強めるため（`references/modes/4_grow.md`） |

### 5.5 原因の切り分け

原因は次の順番で探す。

1. 外の理由: 全部の投稿が同時に大きく落ちたか。落ちたなら §4.2 のとおり判定を2週間止める
2. どの段で止まったか: 届く（閲覧）→フォロー→反応（いいね・返信）→行き先（クリック・購入）の順に見て、前の段の数字は出ているのに次の段で出なくなった所が、止まっている所
3. その週に何を変えたか: 型・役割の配分・時間帯・本数・使ったカード・プロフィールや固定投稿の書き換え。変えた物が止まった段と関係しそうなら、それが一番の候補

「もし〜なら、こうする」の表を先に作っておく。数字を見てから考えると、その日の気分で判断がぶれるため。運営者の占いアカウントの表の一部（「基準」はそのアカウントの数字で決めている）:

| もし | こうする |
|---|---|
| 広げる投稿の閲覧の中央値が、2週続けて基準を下回った | テーマの鮮度切れを疑い、広げる投稿のテーマを入れ替える |
| いいねの中央値が、2週続けて基準を下回った | 同じ型の飽きを疑い、つながる投稿を一時的に増やして、当たった型を減らす |
| 「また同じ」「毎回これ」というコメントや引用が1件でも来た | その型を1週間止め、別の役割の投稿で回す |
| 案内する投稿を出した週に、フォロワーの増え方が前の週より伸びない | テスト歩行をやり直す（リンク切れ・行き先の不具合）。問題がなければ案内の文を変える |
| 1本の投稿が、ふだんの何倍も伸びた | 48時間以内に、プロフィール・固定投稿・行き先が生きているかを確かめる |

自分の表を作る時の「基準」には、自分の直近数週間の中央値を使う。他人の数字を基準にしない。ジャンルと読者が違えば、同じ数字の意味が変わるため。

## §6 伸び悩みの症状別の手当て

| 症状 | まず疑うこと | 手当て | なぜその手当てか |
|---|---|---|---|
| 全部の投稿の閲覧が、同時に半分以下になった | Threads 側の表示のされ方の変化 | 判定を2週間止め、いつもどおり出し続ける。2週間後も戻らなければ、時間帯と本数を変えて試す | 自分の施策のせいだと思い込むと、効いていた型まで捨ててしまうため |
| 特定の型だけ閲覧が落ちた | テーマの鮮度切れ・同じテーマの出しすぎ | その型のテーマを入れ替える。同じテーマは30日あける | 型が生きていても、中身が見慣れられると止まってもらえないため |
| 閲覧は出るのに、フォロワーが増えない | フォローする理由がない・受け皿がない | シリーズの次回予告、人柄が見える投稿、プロフィールと固定投稿の手直し（§1.3・§1.4） | 1本で満足できる投稿は、「次も見たい」という理由を作らないため |
| 閲覧は上がるのに、いいねの数が下がり続ける | 同じ型の連続による飽き（反応率の自然な下がり方と分けて見る。§5.1） | 当たった型を減らし、つながる・参加の投稿を増やす | 運営者のアカウントで、同じ型を続けた月にいいねの中央値が12から2に下がったため |
| 返信が来ない | 問いが重い・読者が答えを持っていない問い | 参加のはしご（§3.2）の1段目・2段目に戻し、その場で答えられる問いか見直す | 答えるのに調べ物が要る問いには、誰も書かないため |
| 入口を広げたら、かえって伸びなくなった | 具体（名前・物・数字）を消した | 具体は残し、「誰にでも起きる場面」を選んで入口を広げる（§1.1） | 運営者のアカウントで、具体を消した一般論の型が最弱クラスだったため |
| 案内してもリンクが押されない | 書いた約束と行き先の中身の食い違い・リンク切れ | テスト歩行。案内の文と行き先の1行目が同じ約束になっているかを見る | 運営者の受け皿の点検で、行き先の画面の案内文が、用意した特典の名前と合っていなかったことがあるため |
| ネタが切れた | ネタ帳に読者の言葉が貯まっていない | 返信とコメントを読み直してネタ帳に写す。シリーズの表を作る（§2.4） | 読者の言葉は、考え出したネタより「自分のことだ」と思われやすいため |
| 投稿を続けるのがつらい | 1日の本数が多すぎる・その日に書いている | 本数を減らし、週1回の作り置きに変える（§3.1） | 止まってしまうより、少ない本数で続く方が、数字を比べられるため |
| コメント欄に個人情報が書かれた | 問いの文が、個人情報を求めているように読める | 返信で「〇〇だけで大丈夫です」とやわらかく伝え、次の問いの文を直す | 書いた人を責めると、参加してくれた人が離れるため |

## §7 AIで回す時の注意

| 注意 | なぜ |
|---|---|
| 数字をAIに渡す時は、投稿ごとに「日時・本文の最初の20字・役割・型・閲覧・いいね・返信・投稿してからの時間」をそろえて渡す | 本文の頭と日時が無いと、AIがどの投稿の話か取り違えるため |
