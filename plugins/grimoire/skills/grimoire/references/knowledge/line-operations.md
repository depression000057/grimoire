# LINE の運用（登録から購入・その後まで）

- 役割: Threads と note から LINE に来てくれた人に、何をどの順で届け、どこで申し込んでもらい、返信をどう拾うかを決めるための判断基準
- いつ読むか: 「LINE の運用を見直したい」「登録はあるのに売れない」「ステップ配信を作りたい」「配信が読まれない」「返信にどう返す？」と言われた時。始動メニューの 28。導線の全体像と LINE の置き場所は `references/knowledge/sales-launch-evergreen.md` §1、占いの配信文と配信ツールへの設置シートは `references/kantei/line-utage.md`
- 目次: §0 このファイルの使い方 §1 どこで止まっているかを決める §2 登録の入口 §3 登録した直後 §4 ステップ配信 §5 申し込みと購入 §6 届ける前の点検 §7 返信への対応 §8 一斉配信と送り分け §9 数字の見方 §10 やらないこと

## §0 このファイルの使い方

- マイナレッジと講座ナレッジに stage `launch`・`evergreen` で LINE のカードがあれば先に読み、食い違ったらカードに従う
- ここにあるのは、個人で発信して note や鑑定などを売る人向けの基準。面談の担当者がいる・日程を予約してもらう・広告で人を集める、といった事業の前提は置いていない
- 金額・日数・通数は「〇〇」で書いている。何通送るか・何日おきに送るかの答えは人と商品で変わるので、自分の登録者の数字を取って決める（§9）
- どれも「必ず効く」ものではない。1度に1か所だけ変え、変える前と後の数字を比べる

## §1 どこで止まっているかを決める

打ち手を探す前に、LINE のどの段で人が減っているかを決める。段が違えば、直す場所がまったく違うため。

| 段 | 見る数字 | ここで止まっている時の形 | 読む節 |
|---|---|---|---|
| 登録 | プロフィールや固定投稿を見た人のうち、登録した人 | 投稿は読まれているのに登録が増えない | §2 |
| 登録した直後 | 登録した人のうち、最初の1通に反応した人（キーワードを送った・リンクを押した） | 登録はあるのに、最初の1通で動きが止まる | §3 |
| ステップ配信 | 配信ごとのリンクの押された数 | 途中の配信から急に押されなくなる・ブロックが増える | §4 |
| 申し込み・購入 | 案内を押した人のうち、申し込んだ・買った人 | 案内は押されるのに、申し込みや購入が無い | §5・§6 |
| その後 | 買った人のうち、次も買った人・感想をくれた人 | 1回買って終わる | §8 |

数字が取れていない段は、推測で埋めずに「まだ見えていない」と書き、次の1週間で取る数字を1つ決める。

## §2 登録の入口

| 基準 | 理由 |
|---|---|
| 登録してもらう理由を、登録特典で1つはっきりさせる。特典のテーマは、投稿で一番反応があったテーマにそろえる | 投稿で興味を持った話の続きが手に入ると分かれば、登録する理由が自分の中で通るため |
| いきなり「登録して」と頼まず、間に1段はさむ（無料の診断・無料の note・ひとこと鑑定など）。その結果の続きを LINE で受け取る形にする | 何ももらっていない段階で個人の連絡先を渡すのは、読者にとって身構える行動だから |
| 入口で約束した物を、登録した直後に必ず渡す。入口で話を広げすぎない | 約束と届いた物がずれると、最初の1通で信用を失うため |
| 友だち追加の画面（あいさつ・アイコン・説明文）を、自分で登録して一度見ておく。初めから入っている文や、特典と違う説明のままにしない | 登録ボタンを押した直後の画面が、読者が最初に見る「このアカウントの顔」だから |
| 登録の案内は、関係ができてから強める。価値観が動いていない人を急いで登録させない | 教育が済んでいない人は、登録しても配信を読まないため |

## §3 登録した直後

最初の1通は、全部の配信の中で一番読まれる。ここで「この人の配信は自分に関係がある」と思ってもらえるかどうかで、後の配信の読まれ方が決まる。

| 基準 | 理由 |
|---|---|
| 1通目は短くし、やってほしいことを1つにする（特典を受け取る・キーワードを送る・診断の結果を見る） | やることが2つ以上あると、どちらもやらずに閉じられやすいため |
| 1通目で、入口で約束した特典を渡す。渡し方は1通目で迷わせない | 約束をすぐ守ることが、次の配信を開いてもらう理由になるため |
| 返事をもらう形（キーワードや一言を送ってもらう）にできるなら、そうする。返ってきた言葉でタイプや悩みのラベルを付け、後の配信を分ける（§8） | 一度自分から送った人は、その後の配信も「自分宛て」として読みやすいため |
| 声や顔を出せる人は、1通目に短い動画やボイスを入れてもよい。長くしない | 文だけより人柄が伝わり、関係が早く温まるため。ただし長い動画は LINE の中では最後まで見られにくい |

## §4 ステップ配信

ステップ配信は、登録した日から自動で順に届く配信。書く前に「何日目に・誰に・何をしてもらう通か」の表を先に作り、本文はその後に書く。受け取る人の頭の中は、日ごとに変わるため。

並べ方の基本（自分の商品と読者に合わせて変える）:

| 順 | その通の役割 |
|---|---|
| 1 | 特典を渡す・使い方を伝える |
| 2 | 読者の悩みを、読者が自分で言えなかった言葉で言い当てる |
| 3 | なぜ今のやり方ではうまくいかないのかを伝える |
| 4 | うまくいく方向と、それが本人にもできる理由（実例は本人の許可がある物だけ） |
| 5 | その方向に進む手段として、自分の商品を紹介する |
| 6 | よくある質問に答え、迷いを減らす |
| 7 | 最後の案内 |

| 基準 | 理由 |
|---|---|
| 1通に役割を1つ、押してほしいリンクを1つにする | 役割とリンクが多いと、何をすればいいのか分からず、どれも押されないため |
| 配信は興味を作るところまでにし、決めてもらうのは申し込みページでする。配信で全部を説明しない | 配信で説明し切ると、ページを開く理由が無くなるため |
| 毎日は送らない。1通は短めにする | 頻度が高すぎると、ブロックや通知を切る人が増えるため |
| 偽の締め切り・偽の残り枠・効果の約束を書かない（`references/quality/absolute-rules.md`） | 1度でも嘘が分かると、その後の配信すべてが信じられなくなるため |
| 共感から入るか、手に入る物から入るかは、その人がどこまで教育を受けたかで切り替える。登録したばかりの人には共感、配信を何通も読んだ人には手に入る物 | 同じ言葉でも、読者の準備によって届き方が変わるため |
| ステップ配信と、定期のセールス（月に1回の案内など）を組み合わせると、ローンチをしなくても売れる形に近づく（`sales-launch-evergreen.md` §4） | 新しく登録した人が、自分のタイミングで案内を受け取れるため |

## §5 申し込みと購入

| 基準 | 理由 |
|---|---|
| 申し込みの前に、案内→よくある質問→最後の案内の順で迷いを減らす。枠があるなら本当の枠数だけを書く | 迷っている理由に先に答えると、申し込みの手前で止まる人が減るため |
| 申し込みの手間を減らす。入力してもらう項目は、すぐ必要な物だけにする。詳しいことは申し込みの後で聞く | 入力が多いほど、途中でやめる人が増えるため |
| 感想や実例は、何を売っているかが伝わった後に見せる。入口の段で「受講生の声」ばかり見せない | 何の声なのかが分からないうちは、売り込みに見えて離れる人がいるため |
| 申し込みページの一番上の文や画像は、思い込みで決めず、2つを比べてから決める | 一番上で読むのをやめる人が多く、少しの違いで結果が変わるため |
| 買った人には、次の行き先を1つだけ案内する（次の note・次の鑑定・感想の送り先） | 買った直後は、一番関係が近い時だから（`sales-launch-evergreen.md` §4.5） |

## §6 届ける前の点検

配信文より先に「受け皿が本当に動くか」を確かめる。案内文だけが整っていて、申し込みボタンの行き先が空のまま・決済の商品が作られていないまま、ということが実際に起きるため。

1. 自分のスマホで、新しく登録するところから順に通す（友だち追加→1通目→キーワード→結果→案内→申し込み→決済）
2. 配信文のリンク・画像・ボタンを1つずつ押す
3. 配信ごとの「通知に出る1行目」を見る。初めから入っている文や空のままにしない。友だちからの連絡のように、読みたくなる1行にする
4. 深夜に届く設定になっていないかを見る

## §7 返信への対応

| 基準 | 理由 |
|---|---|
| 返信を見落とさない仕組みを作る（決まった時間に必ず見る・未読のまま残して「人が見る合図」にする） | 返信をくれた人は一番熱い人で、拾われないとそのまま離れるため |
| 返信はなるべく早く返す。熱いうちに次の段（鑑定・案内）へつなぐ | 時間がたつと、相談した時の気持ちが冷めるため |
| 返し方の順番: 送ってくれたことへのお礼 → 相手の言葉をそのまま受け取る → 不安に1つ答える → 次にやることを1つ | 不安に答えないまま案内すると、売り込みに聞こえるため |
| 自動で返す仕組みを使う時も、重い相談（体・お金・命に関わる内容）は人が読んでから返す。困っている人には公的な相談窓口を案内する（`references/quality/absolute-rules.md`） | 自動の文で重い相談に答えると、相手を傷つけるおそれがあるため |
| 同じ人に2回送っていないか、送る時間帯が深夜になっていないかを確かめる | 2回届く・深夜に届くと、ブロックにつながるため |

返信の下書きをグリモワールに頼む時は、相手の文を貼ってもらう。返信の文はあくまで下書きで、送るのは受講生本人が行う。

## §8 一斉配信と送り分け

| 基準 | 理由 |
|---|---|
| 全員に同じ物を送らず、状況で分ける（登録したばかり・配信を読んでいる・申し込んだ・買った・しばらく反応が無い）。ラベルは §3 の返事やリンクのクリックで付ける | 買った人に買う前の案内が届くと、「自分を見ていない」と感じさせるため |
| 一斉配信は、読者の暮らしに合うきっかけ（季節の行事・暦・新しい note を出した日）に合わせる | 送る理由がはっきりした配信は、開いてもらいやすいため。ただし、きっかけを口実にした偽の限定は作らない |
| 過去に反応が多かった曜日と時間帯に送る。反応の記録が溜まるまでは、時間を変えて試す | 読者が LINE を開く時間は、人によって違うため |
| 名前を入れて「あなたの分」と伝える配信は、本当に一人ずつ用意した時だけにする | 用意していない物を用意したと書くのは、偽の約束になるため |

## §9 数字の見方

| 見る物 | 分かること | 取り方 |
|---|---|---|
| 登録した人の数（週ごと） | 入口が働いているか | LINE の管理画面 |
| 1通目に反応した人の割合 | 入口の約束と1通目が合っているか | キーワードの数・リンクのクリック |
| 配信ごとのリンクの押された数 | どの配信で興味が切れるか | 配信ツールのクリックの数 |
| 登録から何日目に申し込みや購入が入っているか | ステップ配信の長さが合っているか。ある日より後に誰も申し込んでいないなら、そこで配信の中身を変える | 申し込みの日付と登録の日付を並べる |
| ブロックの数（配信ごと） | 頻度や中身が読者に合っているか | LINE の管理画面 |

- 数字は、人数が少ないうちは1人の動きで大きく揺れる。結論は人数がある程度溜まってから出し、それまでは「仮」と書く
- 見られる数字は、使っている配信ツールによって違う。見られない数字は推測で埋めない（`sales-launch-evergreen.md` §6.1）

## §10 やらないこと

- 偽の締め切り・偽の残り枠・「必ず〇〇になる」という約束を書く
- 不安をあおって申し込ませる（「今やらないと不幸になる」など）
- 買った人と買っていない人に、同じ売り込みを送り続ける
- 返信を自動で返したまま、重い相談に人が目を通さない
- 受け皿（申し込み・決済・特典の受け取り）を通しで試さずに配信を始める
